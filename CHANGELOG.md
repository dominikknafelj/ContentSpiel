# Changelog

## Unreleased

### Theme contract

- Added `theme.yml` at a theme folder's top, the one file beside its four folders: the lists `section_styles`, `page_templates` and `icons`, each entry a `name` (lowercase letters, digits and underscores, a letter first, at most 40) and a `label` (a text, or a mapping of language codes to texts), a page template also its `fields` (today only `hero`), an icon its `file` (an SVG under `assets/images`). A list the file does not declare is the default theme's; `page_templates: []` is refused. Any other list, any other key, and `settings` ("Appearance settings are not built yet.") stop the boot.
- Added page templates: `views/pages/templates/_<name>.html.erb`, one per entry of `page_templates`, rendered by `pages/show` with the locals `page`, `post` and `list_block` and nothing else. The default theme's are `standard` and `landing`, drawing what the page types drew. `theme:check` refuses `@page`, `@post` and `@post_list_block` in a page template.
- Added the helper `page_template`: the name of the template drawing the shown page (its stored one while the theme declares it, else the theme's first).
- The Section's template may call `style` and `anchor` (its line is now `block page columns layout background width style anchor`). The default template writes the class `content-section--style-<name>` for a style the theme declares, and the anchor as the section's `id`; a heading whose id would equal an anchor of the page gets a suffix.
- Added the Card block's component line: `block page title text link icon icon_name`. `link` is an `http`, `https` or `mailto` address, a site-relative one or a same-page anchor (`#team`).
- The Card's line is now `block page title text link icon icon_name image`. `image` is nil for a card with no image, and otherwise what `Media::PictureComponent` takes, a Hash of `asset`, `alt` and `sizes`: `<%= render Media::PictureComponent.new(**image, css_class: "…") if image %>`. A theme's Card template without it keeps working and draws no image. **A card with an image and no words is now drawn**: a template can now meet a card with no title or text and must guard them, and it draws its frame empty until it draws `image`. With no title and no text the default template puts the link on the image, whose alt then names it; a theme does the same, so a card stays one link.
- For a gem's block type: a type with `uses :image` and a `summary` of its own no longer gets the tile's missing-image mark, and an image leads the block's form only where the type has fields.
- The Card's `link` also answers for a card linked to a page or a post, as that target's current address in the visitor's language, or nil while a visitor can't reach it. It is still an address or nil, so a template needs no change. A template that reads the stored value through `block` instead will find `cs:page/12` where it may have found an address: use `link`.
- Added the Card's three tokens, `--th-card-ground`, `--th-card-line` and `--th-card-icon` (themed: a light and a dark value, re-valued in a strong band). The token names are the promise, not today's values.
- Added the default theme's icon names: `arrow_right`, `check`, `star`, `heart`, `mail`, `map_pin`, `calendar`, `user`, `shield`, `briefcase`, `clock`, `globe` (Lucide outlines; underscores where Lucide has a hyphen).
- An icon file is checked by a fence when the application starts: at most 32 KB, well-formed SVG, SVG's drawing elements only, no `script`, `foreignObject` or `style` element, no `style` or `on…` attribute, no address but `#…`, no `DOCTYPE` or entity, and no `id`.
- Added the attributes `img[data-image-preview]` and `img[data-image-empty]`, the two loading states of a library image's `<img>`, as names a theme's stylesheet may select.
- `theme:new` also writes a `theme.yml` of comments only and copies the two page templates.
- Added the Form block: `blocks/form_component` with thirteen names (`block page form_name fields action locale page_id drawn honeypot submit_label thank_you unavailable string`), and the five inputs it draws through the theme, each its own line with `field`, `value` and `error`: `blocks/form_fields/short_text_component`, `long_text_component`, `email_component`, `choice_component` and `checkbox_component`. `string` answers six keys (`required`, `choose`, `sending`, `sent`, `error_summary` with `count:`, `network`) and no other.
- Added six themed tokens: `--th-form-field-ground`, `--th-form-field-line`, `--th-form-field-focus`, `--th-form-error`, `--th-form-done-ground` and `--th-form-done-line` (a light and a dark value, re-valued in a strong band).
- Added the markup the `form-send` script reads, a promise to a theme's Form template: `data-controller="form-send"` and `data-action="form-send#send"` on the `<form>`, with `data-turbo="false"`; the hidden inputs `locale`, `page_id` and `drawn`; the targets `summary`, `body`, `button`, `status` (optional) and `done`; the values `sending`, `network` and `fields`; and, optional, `data-action="click->form-send#follow"` on the summary. A template without it still posts to the endpoint and lands on its plain page.
- A public page's ETag now also names whether the site has Active Record encryption keys, which decide whether its forms take answers.
- A link to an anchor of the same page (the same origin, path and query, with a fragment) is now the browser's on every public page, not a Turbo visit: the page is not drawn again, so what a theme's script wrote into it stays. Another page, or the same path with another query, is still a visit.
- The form-send pages (the plain pages a form's send answers without JavaScript: Check your answers, the thanks, 404, 429 and 503 pages) are CMS-drawn, not a theme's, and they change: their accent (the button, the focus ring, the checkbox, the back link) is ink instead of blue, in both schemes, and their grounds, lines and words take CS Studio's new token values. A theme has nothing to change; a theme's own pages look as before.

### Environment

- A form's submission mail is in no log at any level: at `RAILS_LOG_LEVEL=debug` Action Mailer's line for it is a placeholder, where every other mail is still logged whole.
- A new recurring task, `forms_resend_not_ready` (every 15 minutes, in `config/recurring.yml` for every environment): once mail is set up, by Settings or by `MAIL_*` variables, the form mails that failed because it was not are sent again, each recorded as System's "sent a submission again".
- The first numbered release. From it on, a release `X.Y.Z` is a git tag `vX.Y.Z`, a GitHub Release whose notes are its section of this file, and the image `ghcr.io/dominikknafelj/content_spiel:X.Y.Z` for `linux/amd64` and `linux/arm64`; `:stable` names the newest release. The commit tags stay, so a site that pins a commit still builds (`docs/reference/hosting.md`, "Releases").
- The image's `PATH` ends with `/rails/bin`, and `bin/docker-entrypoint` hands a `contentspiel …` command straight over, with no `db:prepare`.

### Migrations needing action

- Only the built-in Admin group is given the two forms permissions (`20261104090300`, below); any other group that should build forms or read submissions gets "Manage forms" and "View form submissions" by hand on the Groups screen.
- **A site without Active Record encryption keys takes no form answers**: every form says it can't take answers, a send is refused, and System status's Forms row says so. Set the three keys (`docs/reference/translations.md`, "Active Record encryption keys") before placing a form.
- A site behind a CDN adds the CDN's ranges to `config.action_dispatch.trusted_proxies`, or the forms' per-visitor rate limit counts every visitor as one (`docs/reference/hosting.md`, "Forms").

### Migrations

- `20261101090000_add_unique_section_anchor_to_content_blocks`: a unique index on a section's anchor (no anchor exists before it).
- `20261101100000_replace_page_type_with_page_settings`: moves every page's type into `pages.settings` and rewrites every page's published copies (current, pending and superseded) the same way; nothing is drawn differently and the content version does not move.
- `20261101110000_restate_state_check_constraints`: writes the check constraints on `note_threads.state` and `presence_marks.state` again in a form `db/schema.rb` dumps the same on every Postgres version; what they allow does not change.
- `20261104090000_create_forms`, `20261104090100_create_form_destinations`, `20261104100000_create_form_submissions` and `20261104100100_create_form_deliveries`: the forms' four tables.
- `20261104090200_add_form_keep_days_to_site_settings`: `site_settings.form_keep_days`, 90 by default.
- `20261104090300_grant_forms_permissions_to_admin_group`: gives the built-in Admin group "Manage forms" and "View form submissions".

### Changed

- CS Studio's dashboard is redrawn. Its panels are headed by their job: Waiting for you (open threads and unpublished changes in one list, a record with both in one row, filtered by Everything, Open threads or Unpublished changes, with "Review and publish…" for whoever may publish), Notes for you, Pick up where you left off (the viewer's drafts as tiles), and, in a rail beside them when the dashboard is 1200px wide, Publishing on its own, Languages behind … and What changed recently. "New page…" and "New post…" stand in the heading row. An editor's address with `?review=publish` opens Publish changes on load. Back to the dashboard shows it as it is now, never as it was left, and a filter pressed from the keyboard keeps the focus.
- Switching between light and dark cross-fades: in CS Studio over 250ms, ease-out; on the public site's footer toggle by the browser's default fade, which a theme may style with `::view-transition-old(root)` and `::view-transition-new(root)` in its own stylesheet. There is no fade under reduced motion, where the browser has no view transitions, or on first paint.
- Every module in CS Studio's sidebar stands on a chip of its own colour family (Dashboard, Pages and Mind graph structure, Posts and Tags lists, Media media, Forms form, Translations text, Users and Groups people, Trash and the system modules (Settings, AI assistant, System status, Audit log) code); the current module's chip keeps its colour on the accent-tint row.
- CS Studio's layers are one scale: the save bar takes the lowest page layer, the media library's drop overlay and the shell's scrim over an open menu, and the rich-text popover and the mind graph's search results at the menus' layer. A menu inside the editor's canvas scrolls under the editor's header and the top bar.
- The mind graph is drawn on CS Studio's new colours and in the sans: pages stay neutral, a tag is the structure hue, each kind of line has its own colour at a measured contrast, a draft's outline is the Draft chip's edge, and what a selection leaves out fades further. Its card and its list carry the shared chips (a list row shows a record's state as the posts list does and says it in its name), its buttons are the shared buttons, and the legend shows the five status looks as a third group, Status, beside Show and Key.
- A post type's dot is a little darker in light and a little lighter in dark on every screen, keeping its hue.
- On the posts list, the Type, Tag and Translation filters stand in a rail beside the list in a wide window and in a row above it otherwise, each under its own label.
- The New post dialog asks for a title and offers the types in a Type list. The posts list's New button names the type as "New post (Blog)", in the type's own case.
- The posts list's Tag filter offers only the tags on posts you can open that are not in the trash, and a Type the site no longer has shows as the chosen Type, so the filter can be seen and cleared.
- On Tags, each tag shows a bar for how many posts use it. Details opens the tag in a panel beside the list (above it in a narrow window) with its newest posts, Merge into… and Delete tag…. The row has no ⋯ menu.
- Added `GET <admin>/tags/:id`, the tag panel. It answers only the Tags screen's panel and otherwise sends back to the list.
- On a wide window CS Studio uses the room: the dashboard, the posts list, Tags and the page and post editors stand at the content's left edge and grow with the window up to 1680px, the rail staying 360px at their right. In the editors a field of running text keeps a readable width (about 72 characters, a Code field about 100), while images, tables, sections and a card's or form's rows take the whole column. The dashboard's Pick up where you left off shows four drafts a row where it has the room.

### Removed

- The mind graph's Status key dialog and its button: the five status looks stand on the legend's row.
- The dashboard's quick-create row: a draft is begun from "New post…" or "Start a draft", in the New post dialog.
- `POST <admin>/dashboard/draft`, which the quick-create row sent: it is a 404 now.
- `GET <admin>/notes/open_threads`, the Open threads panel's frame: it is a 404 now. Its list is part of Waiting for you, `GET <admin>/dashboard/waiting`.
- `Page#page_type` and `Page#landing?`, and the `page_type` column: a template writes `page_template == "landing"`. `theme:check` refuses a call of either with that sentence.
- The old password-reset link `GET <admin>/password/:token/edit`: it is a 404 now. The mailed link is `<admin>/password/edit#<token>`; ask for a new one. With it went telemetry's scrubbing of a token segment in `<admin>/password/…` paths: the reset token is in no path, and every query string is still cut from a span.
- `SITEMAP_HOST`, the old name of `PUBLIC_HOST`: set `PUBLIC_HOST`; `SITEMAP_HOST` is no longer read.
- The `after_id` parameter of the block create request (`POST …/blocks`): the block is appended; to place it, create it and move it.
- The comma-separated string for a post's `tag_names` in the post form's autosave (`post[tag_names]=a, b`): send an Array, `post[tag_names][]=a&post[tag_names][]=b`, as the chip input does. A string leaves the tags as they were.
- The ActionText import: the `rich_text:migrate_from_action_text` task, `RichText::ActionTextImport`, `RichText::HtmlImport` and `RichText::Document.from_html`. A site converts nothing; bodies are Tiptap documents from the start. The migration that drops the ActionText tables (`20260928040000_drop_action_text`) stays, for a database that still has them, and refuses while a body in them was never converted, since nothing converts it any more: `FORCE_DROP_ACTION_TEXT=1` drops the tables and discards such bodies.
- The posts list's `status` parameter and its `draft` spelling (`?status=draft`): an address that carries it lists every post, as with no filter. `scope` (`all`, `live`, `drafts`, `scheduled`) is the list's one name for it.

### For a gem or an outside caller

- SortableJS is no longer preloaded in CS Studio; a script that imports `sortablejs` fetches it on demand (the editor, the page tree, Settings' language rows and a groups field's rows do).
- For a gem's block type: `t.preview ->(block, locale:) { ContentModel::Preview.new(heading: …, text: …, mono: false) }` declares the heading and the few words CS Studio's tile shows of a closed block, as plain text (the text is cut at 240 characters, the heading at 80). It is optional: a type that declares none is drawn from its `summary`, and a callable that is not a callable taking the block and `locale:` is refused at registration. No public template or theme reads it.
- For a gem's block type: `t.icon "name", family: :text` (one of `text media code form lists structure`) names the hue of the chip CS Studio draws the icon on; a type that names none is drawn on the neutral chip, and any other value is refused at registration. The chip is CS Studio's only: no public page draws it.
- Added two hooks beside `ContentSpiel::Plugins.block_types`: `form_field_types` (a form field type's members, `owner/name`) and `form_destinations` (a destination's label, deliverer and settings block, `owner/name`), with the block types' owner rules and replayed after them (`docs/reference/content-blocks-and-types.md`, "Form field types and destinations from outside"). A destination's deliverer answers `deliver(delivery, final_attempt:)`.
- `StudioModules.register` requires `family:`, one of `text media code form lists structure people`: a CS Studio module's icon stands on that hue's chip in the sidebar. A module that names none raises Ruby's missing keyword at boot, and `:neutral`, `:accent` or any other value is refused at registration. The current module's chip keeps its family; only its row is the accent tint.
- Added the hook `ContentSpiel::Plugins.studio_modules { |modules| modules.register "owner/name", …; modules.badge("owner/name") { |viewer:| … } }`, for a gem's module in CS Studio's sidebar and ⌘K: its block is handed `register` and `badge` with `StudioModules`' own arguments, kept, and replayed after the built-in modules on every boot and development reload. A module a gem registered on `StudioModules` itself was emptied by the application's `reset!` at boot in every environment (from its own `to_prepare`) or at the first development reload (from `after_initialize`); the hook is the way to register one. Its name is `owner/name`, under the block types' owner rules (a bare name is refused), and is the key of its label, `admin.modules.<owner/name>`, which the gem's locale file gives; `badge` sets the count of a module the same hook call registered and refuses any other, a built-in's included; a hook that raises stops the boot naming its place, and on a development reload is logged and leaves the built-in modules registered.
- `AccessControl::Permissions.register` takes `grantable:` (default true); `Permissions.grantable` is what a group may hold. A caller that listed `Permissions.all` to offer or seed grants now reads `grantable`.
- `ContentModel::FieldTypes` has two more built-ins, `email` and `form`, and `text` takes `max:`.
- A form field type or destination that a gem no longer registers is dormant, not gone: a stored field of it is left out of a send and carried through a save, and a stored destination of it is carried through a save (its deliveries fail `unknown_destination`) and drawn in the builder with a box that removes it. Only one given anew under an unknown name is refused.
- `Posts::Save` and `Pages::Save` refuse a key under a language they would drop, by name, writing and auditing nothing, as `ContentBlocks::Save` does (#147). A caller outside this repository that sent such a key gets a failed result where it got ok.
- **A promise: the entrypoint.** Every installed wrapper relies on these and nothing else: every image holds an executable `contentspiel` on its `PATH` that takes the arguments exactly as typed; the wrapper runs it with the site's folder mounted at `/site` as the working folder; the subcommand `dev-files` writes `.contentspiel/compose.yml` into the site, which the wrapper's `dev` runs with `docker compose`; a release's image is tagged `X.Y.Z` and the newest is `stable`; and `upgrade` is the command the wrapper runs from `stable`, as it runs every command outside a site. A change to any of them is a breaking change (`docs/reference/hosting.md`, "The wrapper's one promise").
- **A promise: the pin.** A site names its CMS version in one file at its top, `.contentspiel-version`: one line, `X.Y.Z`. The `contentspiel` command run in the folder or under it uses that version, the site's `config/deploy.yml` reads it into the `Dockerfile`'s `CMS_VERSION`, and `contentspiel upgrade` is what moves it (`docs/reference/hosting.md`, "A site's version").
- Added the `contentspiel` command, for a machine with Docker and nothing else: `curl -fsSL https://github.com/dominikknafelj/ContentSpiel/releases/latest/download/install.sh | sh` installs it into `~/.local/bin`. `contentspiel new NAME` writes a site that builds on this release (theme, `Dockerfile`, Kamal's `config/deploy.yml` with three placeholders, the secrets' names, a README to follow); `generate section_style NAME "Label"` and `generate page_template NAME "Label"` add a theme choice; `check` is `theme:check` on the site's `theme/`; `dev` runs the site on the machine with its theme mounted and a database of its own; `upgrade` shows the notes since the pin, checks the theme against the newest release and only then moves the pin; `--version` and `help`. Inside a site every command runs the pinned image and pulls nothing by itself; outside one it pulls `stable` first, and runs the one on the machine, with a warning, when it can't.
- Added `ContentSpiel::VERSION` and `ContentSpiel::IMAGE` (`lib/content_spiel/version.rb`).
- For the CMS's own contributors: `bin/rails 'release:prepare[X.Y.Z]'` prepares a release's pull request, and a pull request that changes `test/support/contract_ledger.rb`, `lib/content_spiel/plugins.rb` or a file under `db/migrate/` fails CI until this file's "Unreleased" section changes too, and one that adds a migration until its version is named under "### Migrations" there (`bin/changelog-guard`).
