Save behaviour
AUTOSAVEContent: page and post editors, blocks, media title/alt/caption, tag rename, tree and block order. Saves 800ms after typing stops and on blur; indicator SAVING… → SAVED 10:42. On failure: NOT SAVED · Retry plus an error toast. Nothing to confirm on leave. EXPLICIT SAVEConfiguration: Settings (all sections, including Languages), Groups, Users, AI tokens, Change password. One sticky save bar per screen appears on the first change: “2 unsaved changes · Cancel · Save”. Leaving with changes opens the Leave dialog. Settings stops autosaving. INSTANTSingle actions with their own button (publish, trash, restore, revoke, turn a language off) run at once, after a confirm dialog where listed, and report with a toast.

09 · Rules
  1. Accent is for the one action per view and for focus. Everything else is ink on paper.
  2. Anything a machine produced or reads (slugs, dates, locales, tokens, counts) is set in mono.
  3. Divide with 1px rules. Shadows only on floating menus.
  4. Never hard-code a colour. Use a token so dark mode works everywhere.
  5. Never assume a fixed number of languages. Lists wrap. The public switcher becomes a dropdown above three languages; Studio language tabs show four, then “+N ▾”.
  6. A change made through an AI token is the token user’s change: “Mara König via claude-desktop” with an MCP chip. A token is never the actor.
  7. Red is only for destructive actions and failures. Missing translations and warnings use amber or neutral.
  8. Hide what’s normal: no badge for Live, no count when it’s zero.
  9. Content autosaves; configuration has one sticky save bar per screen (see Save behaviour).
  10. Never render any part of a secret (API key, token) after creation. Show “Key saved · added 2 Oct”.
  11. AI text is never saved until an editor presses Use.
  12. Copy describes what the app does today. If behaviour changes, change the copy with it.
