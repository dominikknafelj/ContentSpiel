# CS Studio's i18n key scheme

Every string a person reads in CS Studio comes from a locale file, never from
the source. This is the scheme, and the shared components and the admin layout are
converted to it (`test/lib/admin_i18n_test.rb` lists the files that are). The
German UI sub-project converts the other screens; new admin work uses keys from
the start.

## Files

```
config/locales/en.yml                  Rails' own (validation messages) and the named date/time formats
config/locales/admin/ui.en.yml         the shared components (`app/components/admin/ui/`)
config/locales/admin/<folder>.en.yml   a component folder's strings: one file per folder under
                                       `app/components/admin/`, holding exactly `admin.components.<folder>`
config/locales/admin/layout.en.yml     the admin layout (`admin.layout`)
config/locales/admin/<screen>.en.yml   a screen's own keys (`tags.en.yml`), all under the top-level key `admin`
```

Rails loads `config/locales/**/*.yml`, so a new file is picked up. A second
language is `ui.de.yml` beside `ui.en.yml`, with the same keys.

A value with a leading or trailing space, a `%{...}`, a `:` or a glyph that
could open a YAML token is double-quoted; check what loads with `I18n.t` in a
test rather than trusting the file (`"NOT SAVED · "` keeps its trailing space).

## The rules

**A view's keys mirror its path.** `t(".title")` in
`app/views/admin/tags/index.html.erb` reads `admin.tags.index.title` (Rails'
lazy lookup). The admin layout is the exception to this: lazy lookup in
`layouts/admin.html.erb` would read `layouts.admin.*`, outside the `admin` tree, so the
layout writes its keys in full under `admin.layout`:

```erb
<%= render Admin::Ui::DialogComponent.new(id: "leave-dialog", title: t("admin.layout.leave_dialog.title")) %>
```

**A component's keys live under `admin.components.<its scope>`.** The scope is the
class name without `Admin::` and `Component`, underscored, one segment per
namespace: `Admin::Ui::ConfirmDialogComponent` is `ui.confirm_dialog`,
`Admin::EditorScreen::HeaderComponent` is `editor_screen.header`. A component
writes `t(".cancel")` and `Admin::AdminComponent#translate` reads
`admin.components.ui.confirm_dialog.cancel`; any key that does not start with a dot
is passed on untouched (ViewComponent's own lookup would have read
`admin.confirm_dialog_component.cancel`). `_html` keys, `count` and
interpolation behave as in a view, and a missing key raises in the test
environment (`config.i18n.raise_on_missing_translations`).

```ruby
# app/components/admin/ui/confirm_dialog_component.rb
def cancel_label = @cancel_label || t(".cancel")   # admin.components.ui.confirm_dialog.cancel
```

A default argument cannot ask `t`: nothing is rendering when `initialize` runs
(`TranslateCalledBeforeRenderError`). Take `nil` and fall back in a method, as
above. A string the *caller* passes into a component (a button's label, an empty
state's title, a menu's label) belongs to the calling screen, never to the
component.

A relative key resolves in the INSTANCE's class: a `t(".x")` written in a base
class reads the subclass's scope, with no fallback to the ancestor's, so shared
base-class copy needs an absolute key. Only a String or Symbol starting with `.`
is rescoped (`t(:".x")` works); an Array of keys or any other key is passed on.
A component that is not under `Admin::AdminComponent` has no `t(".key")`; its base
class is changed when its screen is converted.

One file per component folder: the components in `app/components/admin/<folder>/`
keep their keys in `config/locales/admin/<folder>.en.yml`, which holds exactly
`admin.components.<folder>` (`Admin::TranslationScreen::MatrixComponent` reads
`admin.components.translation_screen.matrix.*` from `translation_screen.en.yml`).
The one exception is `notes.en.yml`: besides notes' own keys it holds notes'
wording on other screens (the block card's "Add note", the tree node's marker),
which Rails merges into those screens' scopes; they stay there so that no core
file names notes (`SourceLayoutTest` names the exception).

**A string a script shows comes from the server.** The element a controller lives
on (or `<body>`, for what every screen's scripts share) carries
`data-messages`, made by `messages_data(*keys)`; the script reads it through
`i18n/messages.js`. There is no English in a `.js` file.

**One key convention for server and script: every key is relative to `admin`.**
`components.ui.save_bar.changes` is `admin.components.ui.save_bar.changes`;
`tags.dialogs.delete_failed` is `admin.tags.dialogs.delete_failed`. `messages_data`
takes no scope argument for that reason, and `messages(element).t(key)` takes the
same key.

```erb
<%# app/components/admin/ui/chip_input_component.html.erb %>
data-messages="<%= messages %>"   <%# messages_data("components.ui.chip_input.remove", "components.ui.chip_input.results", ...) %>
```
```js
// app/javascript/controllers/admin/ui/chip_input_controller.js
this.announce(messages(this.element).t("components.ui.chip_input.added", { label: item.label }))
```

`messages(element)` WALKS UP: the element itself and each ancestor that carries
`data-messages` are asked in turn, nearest first, then `<body>`'s
(`Admin::MessagesHelper::SCRIPT_MESSAGES`: the autosave status line, the save
footer, the leave dialog, the toasts a failed drop raises); the first that has the
key answers, so a screen root with a few messages of its own never hides the ones
on `<body>`. Only when none has it does it throw. A missing key, a plural asked for
without a `count` and a placeholder without a value all throw; inside a Stimulus
action that is a `console.error`, which `JsErrorCollector` records, so a system
test fails (an error in `initialize`/`connect` likewise). Insert the result with
`textContent` or an attribute, never `innerHTML`. `messages_data` looks keys up with
`raise: true`, so a missing key fails at render -- in production too, where it is
a 500 for the screen, while a view's or component's own `t` raises only in the
test environment and renders a `translation_missing` span everywhere else -- and
`test/lib/script_messages_test.rb` checks that every key a script asks for is in
some `messages_data` list, so an untested path cannot ship a throw.

A sentence handed to a script that finds a name inside it by its quote characters
must keep those characters in every language: the Tags dialogs swap the live tag
name by looking for `“` and `”`; a language that quotes differently changes the
quotes in `tags.en.yml`-style files and the `QUOTES` pair in
`app/javascript/controllers/admin/tags/dialogs_controller.js` together.

**One key, server and script.** A text the server renders and a script also writes
is one key: the autosave status line is `admin.components.ui.save_status.*`, rendered
by `Admin::Ui::SaveStatusComponent` and written by `controllers/admin/saving/autosave_controller.js` from the
same keys.

**Counts use pluralisation, never a hand-built "1 post / 2 posts".**

```yaml
save_bar:
  changes:
    one: "%{count} unsaved change"
    other: "%{count} unsaved changes"
```
```ruby
t(".error", count: count)                                   # server
```
```js
messages(this.element).t("components.ui.save_bar.changes", { count })   // script
```

In the script the category is chosen by `Intl.PluralRules` for the `@locale` the
server sends in the payload (a `zero` form wins for 0, as in Rails; a locale tag
`Intl` rejects falls back to `other`). English is `one` for 1, `other` otherwise.

**Server-side pluralisation is Rails' own: `one` and `other` only.** There is no
`rails-i18n` gem and no `config.i18n.fallbacks`, so a language file with
`few`/`many` is not used by `t(..., count:)` on the server, and will disagree with
`Intl.PluralRules` in the browser for those counts until the server is given the
CLDR rules (the gem). A key missing from a non-English file raises in the test
environment and renders a `translation_missing` span in production, with no
fallback to English.

**A string with a name or number in it is one key with interpolation**, never a
sentence glued from parts, so a translator can reorder it:

```yaml
translation_chip:
  aria_label:
    missing: "%{language}: not translated"
```
```ruby
t(".aria_label.#{@state}", language: ::Locales.name(@locale, native: true))
```

**Flash and toast texts set in a controller use the same files**, under a key
named for what the screen says, with the absolute key (a controller has no view
path to resolve a dot from): `Admin::TagsController#merge` writes
`flash[:notice] = t("admin.tags.toasts.merged", source: source.name, into: into.name)`,
which reads `admin.tags.toasts.merged` in `config/locales/admin/tags.en.yml`, and
`toast_stream(t("admin.tags.toasts.deleted", name: tag.name))` answers a delete. A
service's own refusals are looked up the same way with `I18n.t` (a service may
call `I18n`, never a helper or component): `Tags::Merge`'s three messages are
`admin.tags.merge.*`, read through the class methods `Tags::Merge.gone`,
`.missing_tag` and `.same_tag`, which look the key up at each call so a later
locale switch applies, with `raise: true`: a missing key raises in every
environment rather than put a "translation missing" sentence into a toast.

A helper that chooses between whole sentences (`Admin::TagsHelper`) does the same
with absolute keys, one pluralised key per shape of the sentence.

**A date or a time goes through `I18n.l` with a named format**, defined in
`config/locales/en.yml` under `date.formats.admin` / `time.formats.admin` (`short`
`"%-d %b"`, `short_with_year`, `time` `"%H:%M"`, `datetime`, `short_datetime`):

```ruby
I18n.l(at, format: :"admin.datetime")   # "5 Sep 2026, 09:07" (Admin::Ui::StatusChipComponent#title)
```

Relative times ("just now", "5m ago") are keys with `count` and interpolation
(`admin.components.ui.time_ago.*`).

## The guard

`test/lib/admin_i18n_test.rb` holds `CONVERTED`, the files that must hold no English.
A listed file that does not exist fails. Its rules, the escape hatch (`i18n-ok:`
with a reason of ten characters or more) and its blind spots are written at the top
of the test and pinned against positive and negative samples; add a file to the
list as you convert it. It reads ERB text nodes and attributes (every attribute
that carries words, and any other value that reads as copy, `data-*` included),
Ruby string literals and calls that make English (`humanize`, `strftime`, ...), and
JavaScript sentences plus every literal written into the page on a sink line.

What it cannot see, after strengthening: a lower-case single word or phrase with no
stop word in Ruby ("yesterday"); copy built from several literals; English that
reaches the page through a variable or a helper that is not on its list; a
JavaScript sink split over several lines; markup built with `innerHTML`; a phrase
containing digits ("3 items"); English inside `${...}` of a template literal; a single
word in JavaScript that is not on a sink line (`const s = "Retry"`); a sentence that
holds an all-capitals SQL word ("Sorted ASC by name" reads as SQL); and any file not
in `CONVERTED`. An HTTP header name is exempt only as an `X-` name or one listed in
`STANDARD_HEADERS`, so a hyphenated label ("Read-Only", "Sign-In") counts as copy. An ERB `i18n-ok` marker excuses only the Ruby inside tags on its line,
never markup text. A class name is not exempt ("Posts", "Settings", "Media" are
namespaces and also labels): a line comparing one with a `*_type` column carries a
marker. A review stands behind it.

## Out of scope, named

- **Sentences built in Ruby.** `Audit::Sentence`, `Post.human_attribute_name` /
  `ContentBlock.human_attribute_name` (the typed-field names) and the denial message in
  `ApplicationService` stay English. When they are converted each becomes one key
  per whole sentence with interpolation; none is glued from parts.
- **How CS Studio chooses its own UI language.** Nothing sets `I18n.locale` for the admin
  today (only the public site does); it runs in the default `:en`. The editing
  language (`?locale=`, `admin_locale`) is the content's, not the interface's, and the
  layout's `<html lang>` carries it. The German UI sub-project decides how the
  interface language is picked; `messages_data` already sends `I18n.locale` as
  `@locale`, so the scripts follow whatever it decides.

## Left over from the shared-components conversion, on purpose

- English still in `app/javascript/search/suggestions.js` (`statusLabel`,
  `TEXTS.searchFailed`) and `app/javascript/rich_text/target_search.js` (`TEXTS`).
- The `data-message="Couldn’t save. Check your connection and try again."` literals
  of `Admin::EditorScreen::NewPageDialogComponent` and `NewPostDialogComponent`
  (curly apostrophe, unlike the toast's).
- `Admin::EditorScreen::RelatedPostsComponent` passes no `noun:`, so its chip input announces "No
  matching tags." and "Create tag ..." for posts: kept for byte-identical English;
  `noun: "post"` is the fix, and its sentences exist.
- `app/views/admin/shared/_stale_banner.html.erb` glues its sentence from literal
  parts ("...was changed" + "by <name>" / "in another tab or window" + the time +
  the advice). When the German UI converts the screens it becomes whole sentences
  with keys, one per variant.
- `Admin::Ui::ErrorSummaryComponent` still builds the English field name with
  `humanize` (marked `i18n-ok`), though the order of name and message is a key.
