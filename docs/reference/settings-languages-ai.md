# Settings, languages and the AI translation card

> Describes: `app/controllers/admin/settings_controller.rb`, `app/controllers/admin/languages_controller.rb`, `app/controllers/admin/ai_keys_controller.rb`, `app/controllers/admin/mail_logins_controller.rb`, `app/controllers/concerns/admin/carried_base.rb`, `app/controllers/concerns/admin/glance_rows.rb`, `app/values/settings_sections.rb`, `app/components/admin/settings_screen/`, `app/views/admin/settings/`, `config/locales/admin/settings.en.yml`, `config/locales/admin/settings_screen.en.yml`, `app/services/settings/`, `app/services/locales/`.

## Settings

**Settings** is one screen (`Admin::SettingsController`, `/<admin>/settings`): an in-page nav of anchors (`#site`, `#languages`, `#publishing`, `#forms`, `#ai`, `#mail`, `#sign_in` (an owner's alone), `#images`; `Admin::SettingsScreen::NavComponent`, each link the section's small chip, then its name), which marks the section in view (`admin--settings--nav`, `aria-current="true"`, drawn on the accent tint in ink at 600, with no bar and no shadow): the last heading whose top is above 40% of the window, the last section on a page scrolled to its end, the first on a page that does not scroll (window scroll and resize listeners, not an `IntersectionObserver`: a tall section never crosses a threshold at the 40% line), the "At a glance" rail (below), a card per section of `SettingsSections`, each drawn in the card frame (below) and in the form column (`--cs-form-max`, 760px at most; the API key input fills its row, and there is no logo "NONE" square) (`SiteCardComponent`, `LanguagesCardComponent`, `PublishingCardComponent`, `FormsCardComponent`, `AiCardComponent`, `MailCardComponent`, `SignInCardComponent`, `ImagesCardComponent`) (the Publishing card holds one field, "Keep trashed items for N days after an item is trashed", `site_setting[trash_retention_days]`, where 0 keeps trashed items until someone empties the trash) and ONE form, `#settings-form`, on ONE save bar (`Admin::Ui::SaveBarComponent`, floating at the column's foot, "Discard" and "Save changes", naming and marking what changed: `docs/reference/save-rule-and-write-queue.md`) — a plain `PATCH`, never a Turbo Stream: 303 with "Settings saved", the screen re-rendered at 422 with the error summary (`Admin::SettingsScreen::Values` puts the typed values back over the stored ones), or at 409 on a stale base; either re-render reads the stored row once more (`stored` in `show.html.erb`), so every word that says a state (the AI key's chip, the Mail state, the images' counts, the rail) says what is saved while the fields show what was typed, and the fields that differ carry the save bar's server mark (`Values#changed_fields`). The module opens for `settings.manage` **or** `languages.manage`; each card and its nav link render only for the right that owns them (Languages: `languages.manage`; Site, Publishing, AI translation, Mail, Images: `settings.manage`; Sign-in: `settings.manage` held by an owner, below), and the service enforces the same split: `Settings::Save(site, attributes:, translations:, languages:)` decides from what it is *passed* which rights it needs — a site part needs `settings.manage`, `languages:` needs `languages.manage`, a call with both needs both, checked before anything is assigned — so the controller passes exactly what was posted and a forged field outside the viewer's right is a 403 with one `access.denied`, never silently dropped. `languages:` is the complete ordered list of `{ "code", "fallbacks" }` entries (the form posts one `fallback` per row, and `SettingsController#language_arguments` turns it into the list: a row's stored fallbacks unchanged unless its select changed, a non-scalar value no choice at all), applied inside Save's own transaction through `Locales::Configure#apply` (which checks `languages.manage` itself and records `language.configured` only when something changed), so one Save is all-or-nothing. `Settings::Save` and `Locales::Enable`/`Disable`/`MakeDefault`/`Configure` take a row lock on the settings row first thing inside their transaction (`site.lock!`, which re-reads the row) and decide from the locked row, never from the copy loaded earlier in the request, so a language or settings change made meanwhile is not overwritten; a Save whose stored default makes it a default-language change re-checks `languages.manage` under that lock, and the lock is held until commit, including the synchronous `rebuild_all`. A languages-only call assigns and audits no site field, but the row is still saved — and so validated as a whole — by `Configure#apply`; and when the language part refuses after the site part was written, the rollback is followed by a reload of the site record, so no rolled-back value stays on `Current.site`. The Site card holds every enabled language's title and tagline at once (`site_setting[translations][<code>][title]`, ids `settings-<code>-title`); its language tabs are in-page buttons that only switch which pair is visible (`Admin::Ui::LanguageTabsComponent(mode: :buttons)`, `admin--settings--tabs`; `?locale=` picks the tab shown first, and a refusal on a translated field shows the default language's tab, where the required title lives), so switching never counts as a change or asks to leave. Social links are repeated rows (`admin--settings--repeat-rows`; the list starts as "+ Add link" with no row, and the fieldset posts `site_setting[social_links_present]=1`, so no rows with the marker clears the links, no marker leaves them, and `Values#social_rows` honours the marker so a save refused for another reason keeps an emptied list empty). The form never carries `default_locale`.

**The sections are one list.** `SettingsSections` (`app/values/settings_sections.rb`) holds the eight as `Section`s (`id`, `permission`, `family`, `icon`, `owner_only`), in the nav's order: Site (`structure`, `pages`), Languages (`text`, `translations`), Publishing (`lists`, `file_text`), Forms (`form`, `clipboard_list`), AI translation (`code`, `assistant`), Mail (`media`, `at_sign`), Sign-in (`neutral`, `fingerprint`, owner-only), Images (`media`, `image`). No section's family is accent, which marks the current module and what is addressed to you. `id` is the card heading's id and so every link's anchor; `permission` is the right that owns the card, so a viewer is never offered a section that answers 403; `SettingsSections.for(owner: AccessControl.owner?(actor)) { |permission| can?(permission) }` is the viewer's sections, handed to the nav and the rail (an `owner_only` section, Sign-in today, is left out for anyone who is not an owner, whatever rights they hold, so its nav link, its card and its ⌘K row are an owner's alone; `owner:` defaults to false, so a caller that forgets it offers the section to nobody), and `find(id)` raises on an id that names no section. It is a value with no words and names no component: a section's name is the key `admin.components.settings_screen.sections.<id>` (`CardComponent.word_key`, read by the card's heading and by the nav), and `Jump::Search` reads the list with its own English titles (`SETTINGS_TITLES`, "Settings › Mail"), so ⌘K offers every section the viewer holds, in the nav's order (`docs/reference/cs-studio-shell-and-dashboard.md`, "Jump to…"). `test/values/settings_sections_test.rb`; `test/integration/admin/settings_test.rb`: "every card is drawn by the card frame, in the nav's order, for the rights the viewer holds"; `test/queries/jump/search_test.rb`: "the Settings rows are SettingsSections', titled one each".

**The card frame.** `Admin::Ui::SettingsCardComponent.new(heading_id:, heading:, icon:, family:, intro: nil, **html)` draws every Settings card, and `Admin::SettingsScreen::SectionCard.options(section, view)` maps a section to its first four keywords (`word_key(section)` is the name's key): `section#settings-<id>-card` (`rounded-card bg-surface shadow-1`, no border), named by its `h2#<id>`, so the nav's, the rail's, ⌘K's and the error summary's links land on the heading rather than the middle of a tall card. Its head (`.admin-settings-card__head`) stands on `--cs-rail` with the section's 22px chip, the heading (`text-h2`, 600, ink) and the intro under it (`text-small`, dim); it is a grid, so the chip centres on the heading's line and the intro stands under the heading. Three slots: `head_end` at the end of the heading's row (the Site card's language tabs, the Mail card's state chip), `head_note` under the intro (the Languages card's drag help and pending-lock hint) and `heading_mark`, the heading's next sibling on its row (the Languages card's changed-order dot with its sr-only "Language order changed"), outside the `h2` so the section's accessible name stays its word. The frame knows no section: the name is the section's key read by `SectionCard`, the intro is the card's, handed in already read, and there are no `card.*` keys. The frame has no default `id` (each card hands its own `settings-<id>-card`), a `class` is appended and the rest (the cards' `data-controller`, actions and `data-messages`) goes on the section. `test/components/admin/ui/settings_card_component_test.rb`: "the card is a section named by its heading, whose id is the caller's", "the card has no border of its own and its head is the rail's ground". It is a shared component (`app/components/admin/ui/`) because a second screen draws it: the form builder's cards and a submission's Answers and Delivery take the same frame with the form chip (`docs/reference/forms.md`, "CS Studio"), handing their own heading and icon, since `SectionCard` is Settings' alone.

**The buttons.** The screen has one primary, the save bar's "Save changes" (`test/integration/admin/settings_test.rb`: "the Settings screen draws one primary button, the save bar's", whose matcher leaves dialogs out and is checked against a sample first); a dialog's confirm is that dialog's. Every instant action is secondary: Make default…, Add language, Replace, Add key, Save key, Save login, Test connection, Send test mail, Regenerate images…; Turn off… and Remove… are the danger text; the key's and the login's Cancel is tertiary, and so is the bar's Discard. "Default" on the default language's row is the neutral `Admin::Ui::BadgeComponent`.

**The layout.** `.admin-settings-layout` (`content-spiel.tailwind.css`) is the container (`container: admin-settings / inline-size`), so the rail docks by the room the Settings area has, never the window's, and `.admin-settings-layout__grid` inside it holds, in document order, the nav's wrapper (`__nav`: the `h1` and the nav), the rail, then the cards' column (`__cards`): the focus goes nav, rail, cards at every width, only the grid's areas place them, and nothing is moved by script. Below 1024px of the window it is one column, nav, rail, cards, the rail a compact card (`--cs-surface`, `--cs-shadow-1`, `--cs-radius-card`, as wide as the cards at most). From 1024px (the window rule, which names the grid alone) the nav is a 170px column at the left across both rows and sticky, and the rail is still the compact card, above the first card. Docked, in the one `@container admin-settings (min-width: 1200px)` block, the threshold the editors', the dashboard's and the lists' rails share, the three are columns: `170px minmax(0, var(--cs-form-max)) var(--cs-rail-width)`, `--cs-rail-gap` apart, so the cards' column narrows from 760px as the area does (to about 614px at 1200px; it is the full 760px from about 1346px), and the rail stands on `--cs-rail` with `--cs-shadow-2` and `--cs-radius-rail`, sticky at `calc(var(--admin-top-offset) + var(--cs-sp-4))`, scrolling inside itself when it is taller than the window. The docked grid stops at `--cs-content-max` and past it is centred in the content area. `test/lib/admin_design_rules_test.rb`: "Settings' rail is laid out by the Settings area's own container, from the rail's tokens", "the editors' rail, the dashboard's, the lists' and Settings' dock at one threshold", "Settings' docked grid centres past --cs-content-max"; `test/system/admin/settings_test.rb`: "at 1600px the rail stands right of the cards, on the rail's ground, and stays in view down the page", "at 1100px the rail is a card above the first card, beside the nav", "the rail follows the Settings area's own width: a 1279px window docks it, a 1280px one does not".

**At a glance.** `Admin::SettingsScreen::GlanceComponent.new(sections:, site_setting:, mail_settings:, images_progress:, locales:, default:, ai_result: nil)` is the rail: `aside[aria-labelledby]` with its heading "At a glance" (`text-label`, meta), one `GlanceRowComponent` for each handed section among languages, AI translation, mail and images, in the nav's order, then the hint "Settings save together, with the bar at the foot: they are configuration, not content." (`text-small`, meta); it is not drawn when no handed section has a row, and a viewer with `languages.manage` alone sees the languages row and nothing of mail, the key or the images. A row is one same-page link (`a#settings-glance-<id>`, `GlanceRowComponent.id_for`, to `#<id>`), a plain fragment link like the nav's, which the leave guard never asks about; its state chips take no focus, so the keyboard passes a row in one step. It carries no section chip (the nav beside it does), and its hover is the dashboard rail rows': the paper fill on the tile radius on the row's own padding (`-mx-2 px-2`), fading in 120ms on `--cs-ease`, at once under reduced motion, under `@media (hover: hover)` only. What each row says: Languages "3 languages" with "Deutsch is the default" under it (the default named in its own language), no chip, a count being no state; AI translation `AiState`'s word and tone; Mail `MailSettings#state` in `MailStateComponent::TONES` with the Mail card's words (Not set up, Saved, not tested, Working, Last send failed); Images "No images yet" (off) with no image, "N waiting" (warn: neither made with the saved settings nor failed) and "N failed" (danger), both when both, otherwise "Ready" (ok). A section with no row raises `ArgumentError`. The words are `admin.components.settings_screen.glance.*`, read by full key. **It is a component and runs no query**: the view hands it what it has already read (the stored row, its `MailSettings`, `Media::RenditionProgress`'s counts, the languages), so the rail costs no statement (`test/integration/admin/settings_test.rb`: "the rail costs no statement of its own", against the screen with no sections handed to it). Nothing of it is stored. **An answer that changes a state redraws its row in the same answer**: `Admin::GlanceRows#glance_row_stream(id, site:, ai_result:)` replaces the AI or the Mail row (the only two that change in place; the languages and the images change through the form's save, which draws the screen anew, and any other id raises), from Test connection (`ai_result: :connected` or `:failed`, said until the screen is drawn again), Send test mail, and a key or a login saved or removed (`Admin::CarriedBase#respond_with_streams(glance:)`, only when something was written). `test/components/admin/settings_screen/glance_row_component_test.rb`, `glance_component_test.rb`; `test/integration/admin/settings_mail_test.rb` and `ai_settings_test.rb`: "Test connection, Send test mail and a saved key update their rail row in the same answer", "a blank key's refusal leaves the rail's row alone", "a refused save after changing the mail server keeps the Mail row and the card chip on the stored state", "a refused save after choosing a provider keeps the key's chip and the rail's row on the stored state"; `test/system/admin/settings_test.rb`: "the rail's states are words a keyboard passes over: each row is one link, and no chip takes the focus", "a rail link with typed changes jumps to its card without asking".

**`AiState`** (`app/components/admin/settings_screen/ai_state.rb`) is the one place that names AI translation's state and maps a test's result to one, read by the key's chip, Test connection's result and the rail's row, so all three say the same word in the same tone: `off` without a provider, whatever key is stored ("Off"); `no_key` with a provider and no key ("No key", warn); `key_saved` ("Key saved", ok); and after a Test connection on this visit, `AiState.of_result(:connected | :failed)`, `connected` ("Connected", ok) or `not_connected` ("Not connected", danger). **A test's result counts only once both a provider and a key are saved**: Off and No key outrank it, so a result handed in with no provider still says Off and with no key still says No key. `AiState.of(site, result: nil)`, `tone(state)`, `word(state)` (`admin.components.settings_screen.ai_state.*`); an unknown result raises, in every state. Nothing of a test is stored. `test/components/admin/settings_screen/ai_state_test.rb`.

## The Sign-in card

**The Sign-in card** (`#sign_in`, after Mail, `Admin::SettingsScreen::SignInCardComponent`) is who must sign in with a passkey: `site_setting[passkey_policy]`, the shared segmented control's radios (`Admin::Ui::SegmentedComponent`, `mode: :radios`) with "Nobody", "Owners and admins" and "Everyone" (`SiteSetting::PASSKEY_POLICIES`; `sign_in_card.policies.<name>`), a field of the one Settings form on its save bar, and the line "Admins are people who may manage users, groups or API tokens." (`SignIn::Passkeys::Policy::ADMIN_PERMISSIONS`). Under it, for any saved policy but `nobody`, how many people the SAVED policy covers who hold no passkey (`SignIn::Passkeys::Policy#uncovered_count`: "3 people this covers have no passkey yet. Each is asked to add one at their next sign-in; until then, nothing changes for them.", or "Everyone this covers has a passkey."). There is no "At a glance" row: the rail draws none for it. What the policy does is `docs/reference/access-control-and-audit.md`, "Passkeys, recovery codes and the second step".

- **An owner's alone.** The section is `owner_only` (above), and `Settings::Save` refuses a call that carries `passkey_policy` (`Settings::Save::OWNER_ATTRIBUTES`) from anyone but an owner or the trusted nil actor (`Users::Manageability.actor_owner?`), whole, before anything is written, with one `access.denied` and the sentence "Only an owner can change who must sign in with a passkey." (`admin.settings.save.owner_only`), so a forged field from a `settings.manage` holder writes nothing else of the save either (`test/services/settings/save_test.rb`; `test/integration/admin/settings_test.rb`).
- **Unset stays unset.** A stored nil is the environment's default (`SiteSetting#effective_passkey_policy`: `owners_and_admins` in production, `nobody` in development and test), and the card shows it checked. A save that posts the value shown for a nil policy leaves the column nil, decided from the locked row, so a save of any other card never freezes the default into the row; only a choice the owner changed is written.
- **The toast.** A save whose one change is the policy (`SettingsController#policy_alone?`, against `Values#changed_fields`, with no logo chosen) says "Sign-in policy saved."; any other says "Settings saved".
- **At an IP address** (a `PUBLIC_HOST` that is an IP, or development reached at 127.0.0.1) there is no relying party (`SignIn::Passkeys::RelyingParty`), so no passkey can be made, the enrolment guard holds nobody, and the covered count's "Each is asked to add one at their next sign-in; until then, nothing changes for them." (`sign_in_card.uncovered`, "They're asked…" for one) does not happen there. **No guard and no word on the card says so**: the card draws the same at an IP address; the guide says it.

## Languages

**Languages** are the Languages card. A language is switched on from the built-in list, `SUPPORTED_LOCALES` in `config/supported_locales.rb` (38 languages; a new site starts with English alone, the `site_settings.locales` column's default, and the wizard's Languages step adds the others it is given; the development seed turns German and Spanish on, and the test fixtures' site has all three); only a language outside that list needs a code change. The card: rows with a drag handle (`admin--settings--sortable-rows`: the same SortableJS options and keyboard path as the block list, writing one tracked `site_setting[language_order]` field so a reorder is one change), the language's own name and path, a "Default" tag on the default language's row and a **Make default** button on every other, and a single "Falls back to" select — order and fallbacks wait for Save. A fallback select stores a one-element list or none; a language stored with several shows the first, and the others are dropped only when that row's fallback is changed and saved. What happens at once is `Admin::LanguagesController`, each a form of its own outside `#settings-form` (reached with `form=`), each a 303 back to `#languages` with a toast, each `languages.manage`: Add language (`Locales::Enable`), Turn off (`Locales::Disable`, behind a dialog; refused for the default) and Make default — `PATCH settings/languages/:id/default`, `Locales::MakeDefault`, event `language.default_changed`, behind "Make <Name> the default?", whose "(N items)" is `Translations::StateIndex.translated_record_count` (kept records holding at least one stored translation). `MakeDefault` assigns the code, clears the *new* default's own fallbacks (its select reads "None (default)" and is disabled, so no screen could clear them), lets the model carry the title and tagline over, and rebuilds the translation states. The default is chosen with buttons, never radios: a radio group changes on every arrow key, which opened a dialog per key press, while a button opens its dialog only when pressed. All three are `admin--saving--pending-lock` controls, and a request that changes nothing (Add for a language that is already on, Make default for the default) redirects without a toast. `GET settings/languages` is a 301 to `settings#languages`; there is no Languages screen.

## The AI translation card

**The AI translation card.** Provider and model are fields of the Settings form. The key is not — it is never rendered, so it can't be a pending change — and has its own controller: `Admin::AiKeysController`, `PATCH` / `DELETE /<admin>/settings/ai_key`, `settings.manage`, writing through `Settings::Save` and answering with Turbo Streams that replace only the key component (`AiKeyComponent`: `AiState`'s chip, `Admin::Ui::StateChipComponent`, "Key saved" followed by "· added 2 Oct" in small meta, the year added when it isn't this year, "Key saved" alone for a key older than the column, "No key" with a provider and no key, and "Off" with no provider, with no date even when a key is kept, since it would read as the day AI translation was turned off; Replace or Add key, Remove… behind a dialog; a blank key is a 422 with "Enter the API key first."), its forms, a toast, an empty test result and the rail's AI row. `site_settings.ai_api_key_saved_at` is set with the key and cleared with it (`SiteSetting#ai_api_key_saved_on` is the day in the site zone); it is bookkeeping, kept out of audit field changes. **The carried base:** a key write moves the settings row's `updated_at`, so the key forms carry the main form's base (`main_base_updated_at`) and the answer moves the main form's `base_updated_at` forward only when the request wrote something *and* the carried base was parseable and still current before the write; otherwise nothing moves and the forms come back carrying what they were given, so a key saved from a stale tab neither unlocks that tab's Save nor cancels its 409. **Test connection** (`SettingsController#test_ai_connection`) tests the *saved* provider, model and key and answers with the state chip, "Connected · 412 ms", or "Not connected" with the provider's message under it (`AiTestResultComponent`, its state from `AiState.of_result`), and redraws the rail's AI row in the same answer; `admin--settings--ai` disables it while provider or model differ from what is saved ("Save provider and model first. Tests the saved settings."), while anything else is pending, and while a test is running. The hint is per control: the test row and the key row may each show their own. A key typed into the open entry and not yet saved is nothing the main form would send, and the main Save's re-render would drop it without a word: while the entry holds text it carries `data-save-bar-holds`, and the footer's Save is disabled with "Save or cancel the API key first." The other way round the key is never locked out, even when the main form has unsaved changes, so the two can't lock each other: its input stays usable for as long as the entry is open (`data-pending-lock-exempt` — emptied to type another key it is not disabled under the caret), and Save key while the entry holds text; Remove key, Replace and Test connection stay under the pending lock.

**Without encryption keys** a save of the key (and of the mail login) does not raise: `Settings::Save` rescues `ActiveRecord::Encryption::Errors::Configuration`, rolls the whole call back, records nothing, reloads the site and answers "This site has no encryption keys, so a password can't be stored. See Hosting: encryption keys." (`Settings::Save.no_encryption_keys`), which `AiKeysController` shows in the key's slot with a 422, where "Enter the API key first." is shown; a denial is still the toast and a 403. The key's write, its carried base and the end of every answer are one concern, `Admin::CarriedBase`, shared with the mail login's controller (`test/integration/admin/settings_mail_test.rb`: "without encryption keys a save of the mail login and of the AI key answers the sentence and writes nothing").

## The Mail card

**The Mail card** (`#mail`, `settings.manage`) is described with the rest of outgoing mail in `docs/reference/mail.md` ("Settings → Mail"): five fields of the Settings form (server, port, security, sender name, sender address), the login's own instant forms on the AI key's pattern ("Set on 14 Oct 2026", Replace, Remove…), a field the host's environment sets drawn read-only as "Set by the host" (`Admin::Ui::MailHostValueComponent`), the fields in two groups, Server and Sender (`Admin::Ui::MailFieldsComponent`, the form the wizard's Mail step draws too), the state chip at the head's end, and "Send test mail" at the foot, under the pending lock like Test connection.


## The Forms card

**The Forms card** (`#forms`, after Publishing, `settings.manage`, `Admin::SettingsScreen::FormsCardComponent`) holds one field of the Settings form, `site_setting[form_keep_days]`: "Keep submissions for [90] days.", with the help line "Forms that keep submissions and don't set their own time keep them this long. A change applies to submissions already kept." It is saved by `Settings::Save` with the rest (which locks the row first and decides from it), validated by `SiteSetting` against `Forms::Form::KEEP_DAYS` (1 to 3,650, only when it changes; a refusal is the field's error, a 422) and recorded in `settings.updated` as the column's old and new value (`Audit::Snapshot.field_changes_for` takes any column that is not filtered, so nothing was added to a list). A form that keeps and sets no days of its own follows it at the next run of the clean-up, its existing submissions included (`docs/reference/forms.md`, "Keeping and the clean-up"; `test/integration/admin/settings_forms_test.rb`: "the Forms card saves the default keeping time, refuses 0 and 3,651, and needs settings.manage", "the save is recorded as settings.updated with the old and new days", "the clean-up reads the saved default for a form that sets no time of its own").

## The Images card

**The Images card** (`#images`, `settings.manage`, `Admin::SettingsScreen::ImagesCardComponent`) holds the five `image_*` columns as fields of the one Settings form: the format (WebP, or AVIF, which is opt-in: disabled with its reason where `ImageSettings.avif_available?` is false, and refused by `Settings::Save` too, with the line that browsers too old to show AVIF then show nothing), a quality for each format, the widths as ONE text of comma-separated numbers (`ImageSettings.parse_widths`: a token that is no whole number stays a string, so the model refuses the list with its one sentence; a width typed twice is refused, out of order is saved sorted) and the largest upload in MB (read by the next upload, `Media::Asset#image_type_and_size`). **Saving changes no image.** The card says "12 images were made with other settings" (singular "1 image was made ...", nothing when none; the count is `total - made` of `Media::RenditionProgress`, one statement over the kept images, for the SAVED settings; "There are no images yet." for an empty library) and "2 could not be made", which links to System status for a holder of `system_status.view` and is plain text for anyone else. There is no progress line for a run: nothing records one, and the card has no live refresh, so "12 images were made with other settings" (and the failed line) is all it says until the page is loaded again. The quality stays two fields, WebP (default 75) and AVIF (default 50): the same number is a different quality in each format. The AVIF note reads "Smaller files, slower to make; very old browsers show no image. Animated images are always made in WebP, at the WebP quality." The dialog asks "Remake 12 images? This runs in the background and can take a few minutes."; "Regenerate images…" is a button of its own, locked while the form has unsaved changes (`admin--saving--pending-lock`, since it makes images from the saved settings), that opens a dialog (`ImagesDialogComponent`, drawn after the form) saying how many images are not made with them. Its form posts `POST settings/regenerate_images` (`settings.manage`), `Media::Regenerate`: one plain `Media::RenditionJob` per kept image not made with the saved settings or missing its preview or size, `media.regenerated` on the site with the count ("regenerated N images"; silent for live editing), a 303 to `#images` and a toast naming the count. `bin/rails media:regenerate` runs the same service as System. The backfill's job (`Media::BackfillRenditionJob`) has a lower priority than the plain job, so an upload's widths never wait behind it. System status has a row "Images" beside "Image processing" (`Setup::SystemCheck#images`): "All images are ready." when every kept image is made with the saved settings, otherwise a warning with "8 images are still being made." (not made and not failed; "1 image is still being made.") and, when some failed, "2 images could not be made." (both sentences when both), linking to this card for a holder of `settings.manage` (the same counts, `Media::RenditionProgress`); "Image processing" says whether images CAN be made, the row whether they have been. The widths, the queue and what a page draws are in `docs/reference/media.md`.
