# CS Studio: shell, dashboard, audit log and small screens

> Describes: `app/controllers/admin/` (base, dashboard, audit events, system status, jump, mind graph), `app/components/admin/shell/`, `app/components/admin/dashboard_screen/`, `app/components/admin/audit_screen/`, `app/queries/dashboard/`, `app/queries/jump/`, `app/queries/post_graph.rb`, `app/models/audit/sentence.rb`, `app/components/public/preview_bar_component.rb`.

## Admin (CS Studio)

Our own admin, mounted at `ContentSpiel::ADMIN_PATH` (`config/initializers/admin_path.rb`, default `cs-studio`, configurable via `ADMIN_PATH`, one URL segment, can't be a reserved path), behind the same session-based auth as the rest of the app (no separate admin auth) plus the permission checks described in `docs/reference/access-control-and-audit.md`. Controllers live under `app/controllers/admin/` (`Admin::BaseController` and per-module controllers: `DashboardController`, `PagesController`, `PostsController`, `ContentBlocksController`, `TagsController`, `TagSuggestionsController`, `SettingsController`, `LanguagesController` (the Languages card's instant actions only; there is no Languages screen), `AiKeysController`, `UsersController`, `UserSuggestionsController`, `GroupsController`, `ApiTokensController`, `AuditEventsController`, `AccountsController`, `PasswordsController`, `SessionsController`, `SystemStatusController`, `TranslationsController`, `TranslationConfirmationsController`, `MindGraphController`, `LinkTargetsController`, `JumpController`, `MediaController`, `MediaAssetsController`, `StarterContentsController`, `TrashController`, `TreeController`). Every write goes through a service object (`app/services/`, e.g. `Pages::Save`, `ApiTokens::Issue`), never straight from a controller — see individual services' own comments for authorization and audit-event conventions. `Pages::Save` and `Posts::Save` take only the keys in their `ATTRIBUTES` lists in `attributes:`; any other (`parent_id`, `position`, the trash columns, a translated attribute) raises `ArgumentError`, because moving and trashing belong to `Pages::Move` and `Trash::Move`. `Admin::BaseController#require_permission(key)` gates whole admin areas (403 on refusal, rendered inside the CS Studio layout, never a bare error page); record-scoped controllers load through `AccessControl.scope` instead, so an out-of-scope id 404s; views use the `can?(key, record = nil)` helper (`app/helpers/access_control_helper.rb`) to hide buttons a signed-in user couldn't act on anyway. Content views use autosave (`admin--autosave` Stimulus controller, `Admin::AutosaveResponses#autosave_stream`) rather than a submit button, configuration screens an explicit Save; `docs/reference/save-rule-and-write-queue.md` says which is which and how a stale save is refused.

CS Studio's start page is the **dashboard** (`Admin::DashboardController#show`, dashboard spec `2026-09-30-dashboard-design.md`), not the pages list: `root to: "dashboard#show"` inside the admin scope, so `admin_root_path` means the dashboard. The Pages module is at `/<admin>/pages`, which is not a list but a redirect: `Admin::PagesController#index` sends a viewer who can open Home to Home's editor (303, the editing language kept, the flash kept) and otherwise shows the empty state "Choose a page from the tree" beside the tree; `Admin::BaseController#pages_landing_path` is the same decision for every redirect that used to mean "the pages list" (the trash's post-move redirect, starter content, a page's own delete). Sign-in and setup completion deliberately land on `admin_root_*`, the dashboard. It's open to every signed-in user (`BaseController::MODULES`'s `permission: nil` entry, listed first), including one whose groups hold no grants at all: every list it shows is already read-scoped through `AccessControl.scope`/`AccessControl.holds?` the way every other admin list is, so a user who can read nothing simply sees empty cards rather than a 403. The page is a quick-create row (`Admin::DashboardScreen::QuickCreateComponent`: a title, a type select and "Create draft" — a post draft through `Posts::Save`; choosing "Page" opens the New page dialog with the title carried over instead of creating anything), three cards in an auto-fit grid — "Your drafts" and "Going live next" from `Dashboard::Feed` (`app/queries/dashboard/feed.rb`, at most five rows each, "→" to the posts list filtered by `scope=drafts|scheduled`), and "Needs translation" from `Dashboard::TranslationNeeds` (per target language the viewer's readable pages, posts and — for a `media.upload` holder — images from `Translations::StateIndex.summary`, plus the most recently changed outdated item; hidden with one language) — and then **Recent activity** (`Dashboard::Activity`), with a link to the full audit log for `audit.view`. "Mine" in the drafts card means `author_id` for a post or, for any record including a page, that its *newest* audit event's user is me — "newest" ignoring `access.denied` (a refused attempt is no change, `Dashboard::Feed::NOT_A_CHANGE`) and, for a page or post, also counting events about any content block it currently owns, since editing a block is editing its owner. It is decided in SQL by one `LATERAL` join to each record's newest audit event rather than a Ruby-side filter-after-load, so each list stays one query per model whatever the data size.

**Recent activity** is the newest *content* audit events (pages, posts, blocks, library images; never `access.denied`, `session.*`, `user.*`, `group.*`, `token.*` or `settings.*`; the allow-list is `Dashboard::Activity::ACTIONS`), one sentence each — "<name> published “<title>”" with the title linking to the record's editor (`Admin::DashboardScreen::ActivityRowComponent`) — looking back `Dashboard::Activity::WINDOW` (90 days). The read scope is applied *in the event query itself* (`audit_events.subject_id IN (readable ids)` per subject type, a block event through its readable owner, images for a `media.upload` holder), never by over-fetching and filtering in Ruby, which under-filled the feed and leaked how much hidden activity there was; a record the viewer can't read, a trashed one or a deleted one leaves no row at all ("not found, not forbidden"), a trashed record's whole history disappearing with it until it is restored. `index_audit_events_on_recent` serves the `ORDER BY last_occurred_at DESC` scan. The query returns data only: a `Dashboard::Activity::Row` is `(event, record, sentence, at, span_end)`, the sentence an `Audit::Sentence` (see the audit log below) whose actor is facts, not a name — the viewer ("You"), a user, a `user_id` that names nobody any more, or nobody — and `ActivityRowComponent` hands it to `Admin::AuditScreen::SentenceComponent`, which is where a user is named, through `Admin::UserNameComponent` (the one place CS Studio names a user): the `display_name`, "a deleted user" when `user_id` names a user who no longer exists (`audit_events` has no FK on it; a token event whose user is gone reads the same), "System" only for an event with no user at all. A change made through an API token shows its *user* (round avatar) "via <token name>" beside an MCP chip (`Admin::ChannelChipComponent`, which draws an unknown channel as a plain chip and nothing for none), the name being the `audit_events.actor_label` written when the event was recorded (`Audit::Event#via_label`; it survives the token being deleted, and an event recorded before tokens had names reads "via an API token"), the token itself never loaded. A coalesced burst shows the time it last extended, the whole span as its tooltip.

**The audit log** (`Admin::AuditEventsController`, `audit.view`, never content-scoped) tells every event as one sentence through `Audit::Sentence` (`app/models/audit/sentence.rb`: plain data -- actor facts, parts, a route name + params for the subject, a `security` flag -- never markup or a component; `Admin::AuditScreen::SentenceComponent` draws it), the dashboard's feed words its rows through the same class so the two can't differ. A sentence for an action outside `Audit::Sentence::ACTIONS` (a plugin's) is the generic "<actor> did <action> on <subject>"; the actions in `Audit::Sentence::SECURITY_ACTIONS` (a failed sign-in, a refusal, an owner change, a token issued or revoked, a user or group deleted) carry the `security` flag, and the row draws their key in warn ink. `test/models/audit/sentence_test.rb` greps `app/` for every recorded action name and fails for one without a sentence (interpolated and variable call sites are listed explicitly there). A subject links only when the viewer may open it, decided for the whole page of events in a bounded number of queries (`Audit::Sentence::Targets`); an unreadable, trashed or deleted one is the label the event stored, as plain text, and a failed sign-in never echoes the attempted address. A refusal says what it was refused on when the event names a subject ("was refused permission to edit posts on" and the subject), and a schedule taken off a page or post reads "removed the schedule from". The list is `last_occurred_at DESC, id DESC` under day headers in the site time zone (`Admin::AuditScreen::DayListComponent`), filtered by `Audit::Filter` (user, action, type, channel, a `range` preset or custom `from`/`to`, a `subject_type`+`subject_id` chip; junk is "all"), "Load older" over `offset` (it replaces the page; "Newer" goes back). A coalesced row shows its span ("16:05–16:31", `Admin::AuditScreen::TimeSpan`), and `audit_events.occurrences` (1, incremented by `Audit::Coalescer` each time an event merges into the row) is the "N saves" on the event page ("N times" for anything but a `*.updated` event: twelve refusals are not twelve saves). The event page (`EventHeaderComponent`, `ChangesComponent`) shows field changes as word diffs per language (`Translations::SourceDiff` drawn by `Admin::WordDiffComponent`, shared with the translation reference card), "Changed" for a body, and Older/Newer through the same filtered order, every link on the page keeping the filters. The event is found by id whatever the filter says: one that exists but lies outside the active filter (a link carrying `range=today`, opened the next day) is answered 303 to its own filter-free address, the language kept, where Older and Newer walk the whole log; only an id that names nothing is a 404. Components live under `Admin::AuditScreen::`, never `Admin::Audit` (see "Key Conventions").

Every CS Studio and MCP request also runs inside the **site time zone** (`site_settings.time_zone`, default `"UTC"`, stored as a Rails zone name — an IANA identifier like `"Europe/Berlin"` is normalised to its Rails name on save, because the Settings select's option values are Rails names and every Save resends the whole form; the select also always lists the stored value, so a value written around the model is resent unchanged rather than replaced by the first option): `SiteSetting#effective_time_zone` resolves the stored name to an `ActiveSupport::TimeZone`, falling back to UTC for a value that doesn't resolve (a blank or no-longer-valid stored zone) rather than letting `Time.use_zone` raise and 500 every request; `Admin::BaseController` and `McpController` each wrap their actions in `around_action :use_site_time_zone { Time.use_zone(Current.site.effective_time_zone) { ... } }`. That's what lets the existing `Time.zone.parse`/`strftime` call sites (schedule inputs, "Saved HH:MM", the dashboard, the trash and audit screens) show and parse local time without change — storage stays UTC throughout, and MCP's own dates are still emitted as ISO-8601, now with the site's offset rather than always `Z`. The public site (and `/preview`) still renders dates in UTC — tracked in the roadmap, since it needs the render cache to vary on the zone.

## Shell

**Shell.** `Admin::BaseController::MODULES` entries carry `group:` (`:content`, `:people`, `:system`), which `Admin::Shell::SidebarComponent` renders as the sidebar sections (Dashboard stays first); the sidebar also holds the ⌘K field, the account block and the theme switch. The account block is `Admin::Shell::AccountIdentityComponent` (`#account-identity`: `display_name`, then "email · role" on one line, the role being "Owner", up to two group names then "+N", or "No groups" — its own component because the account screen's Save name replaces just it by stream), then Change password and Sign out. Sign out is a plain form with `data-turbo="false"`: a full document load, so nothing a tab's scripts hold for one user (the media upload queue's tiles) survives into the next sign-in, and with unsaved changes it is the browser's own prompt that asks. `Admin::Shell::TopBarComponent` appears below 1280px, where the sidebar becomes a drawer (the page-tree column becomes one below 1024px); the bar is 3rem tall, so everything sticky inside the content area (the editor header, Settings' nav, the Media panel) sits at `--admin-top-offset`, which is 0 and 3rem below 1280px; `admin--drawer` owns open state, scrim and Escape, and the CSS keys on `data-open` (`.admin-shell` in `content-spiel.tailwind.css`). In the page tree, a context-only row (an ancestor shown only as the path to a readable page) is greyed text with no actions, a row has a hover "+" only where `pages.create` holds under it and a drag handle only where `pages.move` does, the homepage has no handle, and a row shows "↻N" (outdated) and "○N" (missing) summed over the target languages, hidden at zero, from `Translations::StateIndex.counts_for` read once by `Admin::TreeComponent` (never red; the tooltip names the languages). The Trash entry carries `trash_badge_count` (`Admin::TrashController.visible/roots/counts/badge_count`: the page branch roots, posts and images the viewer may act on, the sum of the Trash screen's own tab counts). A 403 and a 404 render inside the layout (`admin/errors/forbidden`, `admin/errors/not_found`; `rescue_from ActiveRecord::RecordNotFound`); the 404's link is "Back to the dashboard" unless the screen names a nearer way on (`@not_found_back`: Media's "Back to Media", the search and segment kept); a non-HTML request (a Turbo Stream, a `fetch`) gets a bare `text/plain` 404 so the caller doesn't mistake it for a stream.

## Jump to…

**⌘K "Jump to…".** `Admin::JumpController` answers `GET /<admin>/jump?q=` with `Jump::Search` (`app/queries/jump/search.rb`): pages, posts and library images (read-scoped through `AccessControl.scope`, trash hidden), then CS Studio's modules as **Sections**, destinations inside the Settings screen as their own **Settings** group ("Settings › Site", "Publishing", "Languages", "AI translation", each behind the right that owns its card: `languages.manage` for Languages, `settings.manage` for the others), and **Actions** (New page and New post open their dialogs; the rest are links); five rows per group. Pages and posts match **titles only** — in every language, via `jsonb_each_text` on the translated jsonb columns (`TitleSearch`, `SqlNodes.any_json_value`) — never bodies (full-text search is a separate roadmap row); images go through `Media::Search` like the library does. A page or post row shows a non-Live status chip at its right end (`Admin::StatusChipComponent`, Live draws none). `Admin::Shell::CommandPaletteComponent` is the dialog (an ESC chip beside the field and a hint row, "↑↓ MOVE · ↵ OPEN · ⌘↵ NEW TAB"), `admin--command-palette` the controller (⌘K / Ctrl+K, arrows, Enter; ⌘/Ctrl+Enter opens the row in a new tab). An Enter pressed while the results for the typed text are still on their way, or before any row is selected, is remembered and opens the first row when they arrive (⌘/Ctrl+Enter the same, in a new tab); the arrows do nothing meanwhile. A row that leads to a section of the screen already showing ("Settings › AI translation" used on Settings) is a same-page fragment link: it jumps there without a visit, so an unsaved form is not asked about leaving. The shortcut does nothing while another modal dialog is open: the editor closes what is open first.

## System status

**System status** (`Admin::SystemStatusController`, `system_status.view`): "N of M checks passed · last run HH:MM", warnings first, each check an `Admin::SystemCheckRowComponent` (the setup wizard draws the same rows with `copyable: false`). A check may carry a console `command`, shown in a code box with Copy (`admin--clipboard`). The outgoing-mail warning's command resets a password through `Users::UpdatePassword` — never `update!` on the model — so it is audited and ends that user's sessions (`Setup::SystemCheck::MAIL_FALLBACK_COMMAND`, a static string). "Run checks again" is a GET with prefetch off, because the storage check writes and deletes a probe.

## The preview bar

**The preview bar** (`Public::PreviewBarComponent`, rendered first in the public layout on `/preview…` only): a fixed 36px bar, "PREVIEW · <title> · <Draft | Scheduled | Live> · <language>", Edit and Exit preview. It is the public site's chrome: the public stylesheet only, no admin JavaScript, and its colours are the theme tokens `--th-preview-bg` / `--th-preview-ink`, which do not switch with light and dark. Edit opens the record's editor in the previewed language. Exit preview goes to the record's public URL in that language when it is live, and otherwise to CS Studio's list (the pages landing for a page, the posts list for a post) — there is no public page to leave for.

## Mind graph

**Mind graph** (`Admin::MindGraphController`, `PostGraph` in `app/queries/post_graph.rb`, `admin--mind-graph` on d3-force). The data is `{ nodes: [{ id, title, type, colour_index, status, url }], tags: [{ id: "tag-<id>", name, count }], edges: [{ source, target, kind: "related" | "tag" }] }`: every post the actor may read, one tag node for each tag on at least two *readable* posts (derived only from those posts, its count the readable number, so nothing about unreadable posts shows), an edge per `PostRelation` and one from each tag to each of its posts; four queries whatever the size, no cap on posts. It carries no colour: the page draws a node from its `colour_index` and `status` through the `--cs-cat-N` tokens (`.mg-*` classes), with two cues that never share a shape. Status is the outline: a live post's is solid, a draft's or scheduled post's a dashed ring. The index is the fill, as `Admin::ContentTypeDotComponent` draws it: 1–6 filled with the hue, 7–12 a ring of the same six hues. So a live post is a filled dot (1–6) or a solid ring (7–12), and a draft a dashed ring with a small filled core (1–6) or an empty dashed ring (7–12). A post whose type is no longer registered has no index and is a ring in the `meta` grey: the same shape as a 7–12 ring, told apart by colour alone. A tag's label carries its count ("name (N)"), and a focused node gets a ring of its own outside the dot. `Admin::MindGraphLegendComponent` names the types present, Tag, "Draft or scheduled" (a dashed ring) and the two edge kinds (related solid, shared tag dashed), and a client-side filter (All / Related / Tags) hands the simulation only what is visible. Post nodes are links (Enter and Space open the editor); tag nodes are not focusable.
