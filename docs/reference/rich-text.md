# Rich text

> Describes: `app/models/rich_text/`, `app/values/table_body.rb`, `app/javascript/rich_text/table.js`, `app/models/concerns/has_rich_text_body.rb`, `app/javascript/rich_text/`, `vendor/javascript/`, `config/importmap.rb`, `lib/tasks/rich_text.rake`, `app/mcp/`.

## The document and its cache

`Post#body`/`ContentBlock#body` (via `HasRichTextBody`, `app/models/concerns/has_rich_text_body.rb`) store a Tiptap/ProseMirror JSON document per locale, read back as a `RichText::Document` value object (`app/models/rich_text/document.rb`) and written through `#assign_body` rather than the raw Mobility accessor. Node/mark types (built-ins: `doc paragraph heading bulletList orderedList listItem blockquote codeBlock horizontalRule hardBreak text youtube image` / `bold italic strike code link internalLink`) are declared in the `RichText::Schema` registry (`app/models/rich_text/schema.rb`, `built_ins.rb`) — the plugin seam: plugins register prefixed `owner/name` types, duplicates raise. `Document#validate` checks types/attributes are registered and allowed, enforces the editor's own content model (each node's `content` expression and mark `excludes`, mirrored from the vendored Tiptap extensions — `code` can't combine with another mark, no empty text nodes, a `listItem` starts with a paragraph, no empty quotes/lists; the one deliberate difference is that `doc` may be empty), so nothing the server accepts opens read-only in the editor, and that referenced records (internal links, image `Media::Asset`s -- see `docs/reference/media.md`) exist; existence checks only block references that are new relative to the locale's *stored* document, so a pre-existing dead reference never blocks an unrelated edit, and validation only re-runs on the locales that actually changed in a given save. `#to_html`/`#to_markdown`/`.from_markdown` convert to/from rendered HTML (via `RichText::HtmlRenderer`, always scrubbed by `RichTextScrubber`, whose list is Rails' safe list plus `figure`, `figcaption`, `iframe` and `s` (and, on an `img` only, `style`, `data-image-preview` and `data-image-empty`: an `img` keeps a `src` that is a `data:` URL only as exactly the WebP preview and a `style` only as exactly the preview background, each judged as a browser reads the value, because those are the two shapes `Media::PictureComponent` writes and a rich-text image is that component's tag, `test/sanitizers/rich_text_scrubber_test.rb`; `docs/reference/media.md`, "What a page draws"): struck text, the `strike` mark's `<s>`, reaches the public page since `s` was added, where it used to be shown struck in the editor and arrive plain on the site, because Rails' list has `del` and no `s`; `test/sanitizers/rich_text_scrubber_test.rb`, and `test/values/theme/contract_test.rb`: "a rendered text is the elements the contract lists, under no class of its own", which found it) and CommonMark (via `RichText::Markdown`, backed by `commonmarker`); the render cache key (`Rails.cache.fetch`) is `["rich_text", digest, RichText::Schema.version, locale, PublicSite.current_content_version, RichText.code_revision]` — `PublicSite.content_version` (`app/models/public_site.rb`) is memoised per request on `Current` and is there because a document's own digest only covers the document, not the world its links and images resolve against. It is four queries: a stored counter (`PublicSite::Version`, the one row of `public_site_versions`), the newest `published_at` that has already passed, of kept pages and of kept posts (a scheduled record going live writes no row), and the newest `live_at` among the published copies in force (`Publishing::Version.in_force`, `index_published_versions_on_live_at`): a change scheduled for later bumps nothing when it is taken and comes into force when its time passes with no write and no job, and a request a second past that time already reads a different version (a job's settle marker is not consulted). A record that has a published copy shows the copy, so an edit of its rows (a title, a block, a tag) does NOT move the counter; taking the next copy does, and what stays immediate (the slug, the tree, `published_at`, the trash, a post's type, a destroy) moves it as before; a live record with no copy moves it on every write. The counter moves only when published output can have changed — `PublicSite.bump_version!`, deferred to the commit, called from the models' `after_commit` (a page or post live before or after the change, a block of a live page that has no copy in force, a library image only when a live page can show it (`Media::Usage.shown_publicly`) and once per generation from `Media::RenditionJob`, a site logo's variant record, a settings commit, a tag renamed or deleted, a live post's tag with no copy in force) and explicitly beside every write that goes around the callbacks (`test/lib/version_bump_test.rb` fails on an `update_all`, `update_columns`, `touch_all`, `insert_all` or `delete_all` in a file that neither bumps nor says `# version: none (reason)` on the line); a draft's autosave moves nothing. `test/models/public_site/version_test.rb` lists every write path with whether it moves the counter, and `bin/rails public_site:bump_version` moves it by hand after a console change or raw SQL. A restored backup rewinds the counter to values already used, so it needs `Rails.cache.clear` as well, and an ETag a browser or CDN stored can still match until the counter has passed its old value (a roadmap row). A preview render is never cached, since the version doesn't cover drafts; `RichText.code_revision` (`KAMAL_VERSION`, else a `REVISION` file, else a value chosen at boot) covers the code, so a renderer or component markup change reaches pages after a deploy instead of Solid Cache serving the old HTML. The public ETag (`PagesController#show`, which reads the content version first) is built from the resolved record, `PublicSite.current_content_version`, `Current.site` (the settings row, which every page prints), `RichText.code_revision` (the version moves only with published content, so a deploy that changed a component or the layout would otherwise keep being answered 304), the theme's fingerprint (`Theme.current.fingerprint`: a site's image rebuilt on the same CMS image with a changed theme moves none of the revision's three sources, and a template the theme replaced is as much what the response is built from as one of the CMS's; `docs/reference/theming.md`, "The render cache and the ETag"), the current year (the footer prints it) and, only while no site address is configured, the request's origin (`PublicController#origin_etag_key`: the head's `og:url`, canonical link and hreflang then follow the host the request named, so an ETag given under one host must not confirm a body under another; a configured site's ETags do not hold it), so a conditional GET that still matches costs the resolver lookup, the version, the settings row and, for a page, one light read of its current copy's id (the copy and its blocks are read and rebuilt only for a response that is rendered; a post's is rebuilt first, since whether it has a page to appear on depends on that page's blocks).

## MCP and Markdown

MCP (`create_post`/`update_post`/`get_post`) exchanges `body` as Markdown: standard nodes are CommonMark, custom nodes are directives (`::youtube{id="…"}`, `::image{asset="42" alt="…" caption="…"}`) on their own line, and internal links are `[text](cs:page/42)` / `[text](cs:post/7)`. Directives are recognised inside list items and quotes too (`- ::youtube{…}`). Unknown directives are kept as text and reported as warnings, never a hard failure; whatever the Markdown can express but the editor's content model can't (a bold code span, an empty quote) is repaired by `RichText::ContentRepair`, also with a warning. Markdown can't spell an empty paragraph or a trailing hard break, so those two don't survive a round trip; otherwise editor-shaped documents round-trip exactly over `Document#normalized` (which also moves whitespace at the edges of bold/italic/strike runs outside the mark).

## Tables

Four built-in node types, `table`, `tableRow`, `tableHeader` and `tableCell` (`RichText::BuiltIns`), carry a table; the Table block's body is the only body that may hold one (`docs/reference/content-blocks-and-types.md`, "The Table block"; the design is `docs/superpowers/specs/2026-10-27-table-block-design.md`, whose "As built" says where the build left it). A row's content is `cell+` (the group both cell types are in, because `ContentExpression` has no alternation); a cell holds one paragraph, and the HTML renderer draws it without the `<p>` (`RichText::HtmlRenderer#render_fragment` for one cell's inline content; the Table component asks `RichText::Document#table_cells_html`, which draws every cell of the table in one pass with one sanitizer parse, `render_fragments`, and keeps the list in the render cache under the body render's key with its own first word, so a public view of a large table is one cached read, as a prose body's is; a preview draws it every time). A header cell is `th scope="col"` (the node cannot know its column, so a header column's `scope="row"` is the component's), and the scrubber lets `table tbody tr th td` and `scope` through, and `class` on a `th`/`td` only when it is `align-left`, `align-center` or `align-right`.

**What an `internalLink` draws** is `PublicSite::Urls#drawn_target_path` (`RichText::BuiltIns.render_internal_link` asks it), the one rule a Card's reference follows too (`docs/reference/theme-choices.md`): change it there and both move. A public render asks `target_path`, the visibility gate, and nobody's rights. In a preview (`/preview` and CS Studio's reference renders, which `Urls.new(preview: true)` draws) the gate is off and `LinkTargets.readable` stands in for it: a draft outside the reader's scope is the link's words alone, no address (#152). That answer depends on the actor and the render cache's key holds none, which is safe only because a preview is never cached: a cache in front of one must carry the actor in its key first (`test/integration/preview_internal_link_test.rb`: "the same body previewed by each viewer gets each their own answer, whoever was first, and the cache holds neither", "the public render and its cache are the same for every actor, in statements too").

**The body-content rule: a table is allowed in a body that says so and in no other.** `HasRichTextBody#body_content_kind` is `:rich` for every body but a block type's that declares `t.body_content :table` (`BlockTypeDefinition#body_content`, `ContentBlock#body_content_kind`; an outside type may not declare it, refused at registration as `read_only_actions` is). A `:rich` body refuses a table node anywhere ("a table is allowed only in a Table block", with the language prefix: an MCP or API writer's mistake, not an editor's). A `:table` body is blank or exactly one table: nothing beside it, rows of the same number of cells (the node schema cannot count, `TableBody#ragged?` does), and in a cell only the marks bold, italic, code, link and internalLink (`TABLE_CELL_MARKS`: the schema admits every registered mark, so strike is refused here) and hard breaks. Over the hard limits, 30 columns, 500 rows, 2,000 characters in a cell (`TableBody::MAX_COLUMNS`, `MAX_ROWS`, `MAX_CELL`), the save is refused with a sentence for an editor, "A table can have at most 30 columns and 500 rows." or "A cell can have at most 2,000 characters." (`errors.messages.table_too_large`, `table_cell_too_long`), added once and with no language prefix. The warning thresholds (6 columns, 40 rows) are advice and refuse nothing. `TableBody` (`app/values/table_body.rb`) is how everything else reads a table (rows, `Cell` values, the header kinds, `shape`, `warnings`, `limit_errors`); it is total over a document that never passed validation, so a stored body cannot make a public page a 500 (`test/models/content_block_table_body_test.rb`: "a table body holding exactly one table is valid; a table followed by a paragraph is refused; a paragraph alone is refused", "a cell holding a struck text is refused, and bold, italic, code and links are fine", "a text block's, a note's and a post's body with a table in it is refused", "over the hard limit the save is refused with the table's sentence and no language prefix"; `test/models/rich_text/table_nodes_test.rb`: "a cell holding a list, an image or two paragraphs is refused", "a class that is not a cell's alignment does not survive the scrubber"; `test/values/table_body_test.rb`: "limit errors: 31 columns or 501 rows is :size, a 2,001-character cell is :cell, exactly the limits are fine"; `test/models/content_model/block_type_definition_test.rb`: "body_content is :rich unless declared, takes :table, refuses anything else; an outside type may not declare :table").

**Markdown.** `RichText::Markdown` reads and writes a GFM table only when it is asked to (`tables: true`): the first row is the header, a column's alignment is the delimiter line's (`:---`, `:---:`, `---:`) and is put on every cell of the column, a pipe, a backslash and a line break in a cell are escaped and come back unchanged, `<br>` in a cell is a hard break and nowhere else, a short row is padded to the header's width, and strikethrough in a cell is dropped with a warning. A table with no header row is written with its first row as the header, so it reads back with one. Only the AI translation of a table body passes `tables: true` (`AI::Translate`); every other caller (MCP's `create_post`/`update_post`, the guide's loader, any post) keeps degrading a table to one paragraph per row with the warning, as before, so a table never reaches a body that refuses one (`test/models/rich_text/markdown_table_test.rb`: "a table with a header row, alignment, bold and a link dumps to GFM and loads back to the same document with tables: true", "cell text with a pipe, a backslash and a line break comes back unchanged", "a hand-written <br>, <br/> and <br /> in a cell are hard breaks, and nowhere else", "a GFM table with a short row loads padded to the header's width", "without tables: true a GFM table still degrades to one paragraph per row, with the warning", "a table without a header row is written with its first row as the header", "strikethrough in a cell is dropped with a warning"). The alignments come from the delimiter line of `table.to_commonmark` because Commonmarker exposes neither alignments nor the header; a comment in `markdown.rb` says the parse assumes that output is never wrapped.

**Plain text.** `RichText::Document#plain_paragraphs` reads a table one entry per cell, row by row, empty cells dropped, so the translation diff and every `plain_paragraphs.first` (the tile, a note's heading, the changes overview) see a table's cells and not one run of words; the digest is unchanged (`test/models/rich_text/document_test.rb`: "a table's plain paragraphs are its cells' texts, row by row"; `test/queries/notes/heading_test.rb`: "a note on a Table block is headed by its first cell's text").

## The vendored editor

The Tiptap editor is vendored under `vendor/javascript` via import maps (`config/importmap.rb`) — no npm, no CDN at runtime. There are three entry points: setup and sign-in import `application` (Turbo plus the site's own controllers); CS Studio's layout imports `admin` (`app/javascript/admin.js`: `application` plus `controllers/admin/*`); the public layout, and it alone, imports `site` (`app/javascript/site.js`: `application` plus a theme's `controllers/theme/*`, which are `preload: "site"`). CS Studio's controllers, `rich_text/*` and Tiptap/ProseMirror are all `preload: "admin"`, so they're modulepreloaded in CS Studio and never on a public page. SortableJS, the mind graph's modules and d3-force are `preload: false`: SortableJS is imported by the four controllers that drag (the blocks list, the groups field, the page tree, Settings' language rows) when they connect, each marking its element `data-sortable="pending"` until its Sortables exist, which `await_sortables` waits on; only the Mind graph screen fetches its modules, d3-force from inside its layout worker (`docs/reference/cs-studio-shell-and-dashboard.md`).

**The table pins.** The grid of a Table block is Tiptap's table extension, pinned as `@tiptap/extension-table` with `@tiptap/pm/tables` and `prosemirror-tables` (the three files `bin/importmap pin @tiptap/extension-table` writes), each `preload: "admin"` like every other editor pin (`test/integration/public_javascript_test.rb`: the CS Studio preload test expects `rich_text/table`, `@tiptap--extension-table`, `@tiptap--pm--tables` and `prosemirror-tables`, and the public-page test keeps every `@tiptap` and `prosemirror` fragment off a public page). **That pin raised two packages already there by a patch release for the whole editor**, `prosemirror-view` 1.42.5 to 1.42.8 and `prosemirror-transform` 1.12.1 to 1.12.4, because the table extension requires them; the editor's system tests pass on them, and the pull request names them. Like every re-pin it strips `preload: "admin"` from the existing Tiptap lines (twenty of them), which were re-added by hand. `app/javascript/rich_text/schema.js` builds the editor's extensions for a content kind (`extensions({ content: "rich" | "table" })`): table mode is the document, paragraph, text, hard break, bold, italic, code, links and the table nodes (`app/javascript/rich_text/table.js`: the four schema nodes with `align` as an `align-*` class, `TableKeys` (with the `is-current-cell` decoration on the cell the caret is in, which the card outlines while the grid has the focus), `storedDocument`, the grid helpers and `TableColumnAlignment`), with no StarterKit, so nothing a cell may not hold can be typed; `storedDocument` drops the editor-only `colspan`, `rowspan` and `colwidth`, and a grid emptied of every row is stored as `{ "type": "doc", "content": [] }`. A paste into a cell is flattened to inline content joined by hard breaks, a pasted table included. A post's editor is unchanged: it has no table node, so a pasted HTML table keeps its words and loses its structure there.

## ActionText

There is no ActionText import: a body is a Tiptap/ProseMirror document from the start. The ActionText tables are dropped by a guarded migration (`db/migrate/20260928040000_drop_action_text.rb`), which stays so that a database that still has them migrates. It refuses while a body in them was never converted, and says that nothing converts one any more; `FORCE_DROP_ACTION_TEXT=1` drops the tables and discards such bodies (`test/migrations/drop_action_text_test.rb`).

## Rules a change can break silently

Moved word for word from `CLAUDE.md`, where "above" and "below" meant the list these rules stood in: a rule named that way may now be in another reference file. Each names the test that guards it; a rule or a part of one with no guard is also said in `CLAUDE.md`.

- The public content version moves only through `PublicSite.bump_version!`; a write that goes around the callbacks (`update_all`, `update_columns`, `touch_all`, `insert_all`, `delete_all`) bumps it or says `# version: none (reason)` on the line (`test/lib/version_bump_test.rb`). For a record with a published copy a content write moves it not at all and taking a copy (or a scheduled change coming into force, a read-time part with no write and no job) moves it; for a record with no copy every write moves it (`test/models/public_site/version_test.rb`: "creating a live page moves; editing it stays, and publishing the changes moves", "a scheduled change coming into force by the clock changes the version with no write").
