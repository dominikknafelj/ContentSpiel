# Rich text

> Describes: `app/models/rich_text/`, `app/models/concerns/has_rich_text_body.rb`, `app/javascript/rich_text/`, `vendor/javascript/`, `config/importmap.rb`, `lib/tasks/rich_text.rake`, `app/mcp/`.

## The document and its cache

`Post#body`/`ContentBlock#body` (via `HasRichTextBody`, `app/models/concerns/has_rich_text_body.rb`) store a Tiptap/ProseMirror JSON document per locale, read back as a `RichText::Document` value object (`app/models/rich_text/document.rb`) and written through `#assign_body` rather than the raw Mobility accessor. Node/mark types (built-ins: `doc paragraph heading bulletList orderedList listItem blockquote codeBlock horizontalRule hardBreak text youtube image` / `bold italic strike code link internalLink`) are declared in the `RichText::Schema` registry (`app/models/rich_text/schema.rb`, `built_ins.rb`) — the plugin seam: plugins register prefixed `owner/name` types, duplicates raise. `Document#validate` checks types/attributes are registered and allowed, enforces the editor's own content model (each node's `content` expression and mark `excludes`, mirrored from the vendored Tiptap extensions — `code` can't combine with another mark, no empty text nodes, a `listItem` starts with a paragraph, no empty quotes/lists; the one deliberate difference is that `doc` may be empty), so nothing the server accepts opens read-only in the editor, and that referenced records (internal links, image `Media::Asset`s -- see `docs/reference/media.md`) exist; existence checks only block references that are new relative to the locale's *stored* document, so a pre-existing dead reference never blocks an unrelated edit, and validation only re-runs on the locales that actually changed in a given save. `#to_html`/`#to_markdown`/`.from_markdown` convert to/from rendered HTML (via `RichText::HtmlRenderer`, always scrubbed by `RichTextScrubber`) and CommonMark (via `RichText::Markdown`, backed by `commonmarker`); the render cache key (`Rails.cache.fetch`) is `["rich_text", digest, RichText::Schema.version, locale, preview, PublicSite.current_content_version, RichText.code_revision]` — `PublicSite.content_version` (`app/models/public_site.rb`) is memoised per request on `Current` and is there because a document's own digest only covers the document, not the world its links and images resolve against. It is four queries: a stored counter (`PublicSite::Version`, the one row of `public_site_versions`), the newest `published_at` that has already passed, of kept pages and of kept posts (a scheduled record going live writes no row), and the newest `live_at` among the published copies in force (`Publishing::Version.in_force`, `index_published_versions_on_live_at`): a change scheduled for later bumps nothing when it is taken and comes into force when its time passes with no write and no job, and a request a second past that time already reads a different version (a job's settle marker is not consulted). A record that has a published copy shows the copy, so an edit of its rows (a title, a block, a tag) does NOT move the counter; taking the next copy does, and what stays immediate (the slug, the tree, `published_at`, the trash, a post's type, a destroy) moves it as before; a live record with no copy moves it on every write. The counter moves only when published output can have changed — `PublicSite.bump_version!`, deferred to the commit, called from the models' `after_commit` (a page or post live before or after the change, a block of a live page that has no copy in force, every library image, variant record and settings commit, a tag renamed or deleted, a live post's tag with no copy in force) and explicitly beside every write that goes around the callbacks (`test/lib/version_bump_test.rb` fails on an `update_all`, `update_columns`, `touch_all`, `insert_all` or `delete_all` in a file that neither bumps nor says `# version: none (reason)` on the line); a draft's autosave moves nothing. `test/models/public_site/version_test.rb` lists every write path with whether it moves the counter, and `bin/rails public_site:bump_version` moves it by hand after a console change or raw SQL. A restored backup rewinds the counter to values already used, so it needs `Rails.cache.clear` as well, and an ETag a browser or CDN stored can still match until the counter has passed its old value (a roadmap row). A preview render is never cached, since the version doesn't cover drafts; `RichText.code_revision` (`KAMAL_VERSION`, else a `REVISION` file, else a value chosen at boot) covers the code, so a renderer or component markup change reaches pages after a deploy instead of Solid Cache serving the old HTML. The public ETag (`PagesController#show`, which reads the content version first) is built from the resolved record, `PublicSite.current_content_version`, `Current.site` (the settings row, which every page prints), `RichText.code_revision` (the version moves only with published content, so a deploy that changed a component or the layout would otherwise keep being answered 304) the current year (the footer prints it) and, only while no site address is configured, the request's origin (`PublicController#origin_etag_key`: the head's `og:url`, canonical link and hreflang then follow the host the request named, so an ETag given under one host must not confirm a body under another; a configured site's ETags do not hold it), so a conditional GET that still matches costs the resolver lookup, the version, the settings row and, for a page, one light read of its current copy's id (the copy and its blocks are read and rebuilt only for a response that is rendered; a post's is rebuilt first, since whether it has a page to appear on depends on that page's blocks).

## MCP and Markdown

MCP (`create_post`/`update_post`/`get_post`) exchanges `body` as Markdown: standard nodes are CommonMark, custom nodes are directives (`::youtube{id="…"}`, `::image{asset="42" alt="…" caption="…"}`) on their own line, and internal links are `[text](cs:page/42)` / `[text](cs:post/7)`. Directives are recognised inside list items and quotes too (`- ::youtube{…}`). Unknown directives are kept as text and reported as warnings, never a hard failure; whatever the Markdown can express but the editor's content model can't (a bold code span, an empty quote) is repaired by `RichText::ContentRepair`, also with a warning. Markdown can't spell an empty paragraph or a trailing hard break, so those two don't survive a round trip; otherwise editor-shaped documents round-trip exactly over `Document#normalized` (which also moves whitespace at the edges of bold/italic/strike runs outside the mark).

## The vendored editor

The Tiptap editor is vendored under `vendor/javascript` via import maps (`config/importmap.rb`) — no npm, no CDN at runtime. There are two entry points: the public site (and setup/sign-in) imports `application` (Turbo plus the site's own controllers); CS Studio's layout imports `admin` (`app/javascript/admin.js`: `application` plus `controllers/admin/*`). CS Studio's controllers, `rich_text/*`, Tiptap/ProseMirror and SortableJS are all `preload: "admin"`, so they're modulepreloaded in CS Studio and never on a public page. The mind graph's modules and d3-force are `preload: false`: only the Mind graph screen fetches them, d3-force from inside its layout worker (`docs/reference/cs-studio-shell-and-dashboard.md`).

## Importing ActionText

`bin/rails rich_text:migrate_from_action_text` (`lib/tasks/rich_text.rake`) runs `RichText::ActionTextImport`, which orchestrates the conversion of every stored ActionText/Trix body — it never aborts partway and reports counts plus every unmapped fragment — handing each HTML fragment to `RichText::HtmlImport`, the per-fragment HTML → `RichText::Document` converter. The ActionText tables are dropped by a later, guarded migration (`db/migrate/20260928040000_drop_action_text.rb`) that refuses to run while unimported rows remain, unless `FORCE_DROP_ACTION_TEXT=1` overrides the guard.
