# Page tree and public routing

> Describes: `app/models/page.rb`, `app/models/page/`, `app/models/public_site/`, `app/models/public_path.rb`, `app/models/concerns/has_public_paths.rb`, `app/controllers/pages_controller.rb`, `config/routes.rb`, `config/sitemap.rb`, `app/jobs/public_site/`.

## The page tree

`Page` (`app/models/page.rb`) is a `closure_tree` (gem `closure_tree`), backed by a `page_hierarchies` closure table, with exactly one root (the homepage, enforced by `only_one_root_page` and, as a database backstop, the partial unique index `index_pages_on_single_root`). `page_type` is an enum with `validate: true`, so a forged value is an ordinary validation failure on the field, not an `ArgumentError`. Sibling order is the `position` column; closure_tree renumbers it, but reordering to a given rank is implemented on top of that in `remember_requested_position`/`place_among_siblings` because closure_tree's own renumbering doesn't do what a literal "move to rank N" needs. In CS Studio a page is moved in the page tree: by dragging the handle of its row (`Admin::PagesScreen::TreeNodeComponent`, SortableJS in `admin--pages--tree`) or, with the focus on that handle, by the keyboard (Space picks the row up and drops it, the up and down arrows step it among its siblings, the right arrow nests it, the left arrow moves it out, Escape cancels), both sent as `Pages::Move.call(page, parent:, position:)` by `Admin::TreeController` (`test/system/admin/tree_test.rb`: "dragging a page onto another node reparents it and persists"). A move is a write of the moved page (its `updated_at` moves, its URLs are resynced, its new siblings are renumbered with `update_columns`), sent through the write queue like every other write of the screen, but it is **not a change of the page's settings**: `parent_id` and `position` are in `Page::SETTINGS_BASE_IGNORES`, so the page settings form's base (`settings_changed_at`) stays where it was and someone typing in that form, in the mover's tab or a colleague's, goes on saving (`docs/reference/live-editing.md`, "The page settings form's own base"; `test/models/page_test.rb`: "a move in the tree leaves the settings base of the moved page and of its new siblings where it was"; `test/integration/admin/tree_test.rb`: "a settings form held while a colleague moves that page in the tree saves afterwards"). The homepage has no handle, and neither has a page the viewer may not move.

**The page type and the public menu.** `page_type` is `standard` or `landing`. A landing page differs in one place, the public page's header (`app/views/pages/show.html.erb`): it shows the page's subtitle under the title and its hero image; a standard page shows neither. In the page settings form the hero image and its alt text are offered only for a landing page, while the subtitle field is there for every page although only a landing page renders it. The public site's menu is not configured anywhere: it is the homepage's children that are published and not in the trash, in their sibling order (`ThemeHelper#navigation_pages`, drawn by `layouts/public/_header.html.erb`), so every live child of the homepage is in it and no other page can be.

Every public URL is precomputed and stored: the `public_paths` table (`PublicPath`, one row per record per locale, `current: true` for the live URL and `current: false` for the redirects an old URL leaves behind) is derived by `PublicSite::Paths` from model callbacks (`HasPublicPaths`), never written by hand -- a page save that changes one of its URL inputs (`url_inputs_are`: slug, parent, position, publication, trash state; any other save, and a bare `touch`, syncs nothing) resyncs its whole subtree (`sync_subtree`), since a slug change on an ancestor shifts every descendant's URL, plus every post its listing blocks give a URL to. A post's sync is conditional the same way (its slug, content type, publication or trash state, or its tags; a tag change through an association is noted by the association's callbacks, and `Tags::Rename`/`Merge`/`Destroy` sync what they touch themselves), and the writer is set-based (`PublicSite::Paths.write_all`, a fixed number of statements however large the subtree). A post whose listing page goes live by the clock writes no row, so `PublicSite::Paths.sync_went_live(since:)` runs from `PublicSite::SyncWentLiveJob` every five minutes over a 24-hour window (`config/recurring.yml`, which, like the trash job, runs only where Solid Queue is the adapter). `test/models/public_site/paths_test.rb` has the parity test: after every write path that feeds a URL the live rows must equal what `PublicSite::Paths.rebuild!` would write (a partial oracle: it asks no condition, but works from the same records). Interim, tracked in the roadmap: a record that had to yield its address to another is not healed by an unrelated save (`bin/rails public_paths:rebuild` does it), and the descendants of a yielding page get no address. The public router (`PagesController#show`) asks `PublicSite::Resolver` for a URL, which is a single indexed lookup in that table plus the visibility rule (`:published`, or `:preview` for signed-in editors) rather than a walk of the tree per request; `PublicSite::Urls` builds links the other way round. Sibling ranking lives in `Page::TreeRanking` (`app/models/page/tree_ranking.rb`).

## Addresses follow the published copies

A post's address is not made of its slug and the tree alone: it runs through the page whose list block lists it, and which block lists which post is content, held in the published copies (`docs/superpowers/specs/2026-10-11-drafts-of-live-content-design.md`, §5). So `PublicSite::Paths.canonical_pages` reads both sides as published. The candidates are `Publishing::Listing.blocks`: of a kept page that is published or scheduled and has a copy in force, the list blocks of its current copy; of every other kept page (a draft, whatever copies it kept, and a page written around the services), the blocks of its rows; of a trashed page, none. Each post is judged by the tags of its current copy when it is published or scheduled and has one, by its rows' tags otherwise, and a filter's tag is matched by id (`Publishing::Listing.filter_tags`: the id the page's copy recorded, or, when it recorded none, the tag of that name as it is now). That is the rule the public list itself is drawn by (`Publishing::Listing.posts`), which is the point: an address exists for exactly the posts a public list shows, under the page whose published list shows them. A list block changed, added or deleted in the rows of a live page, and a tag changed in the rows of a live post, therefore move no address until that record's changes are published (`test/models/public_site/paths_test.rb`: "changing a live page's list block to another type moves no address until the page is published", "a tag changed in a live post's rows moves it to another listing only when the post is published"; `test/integration/public_drafts_test.rb`: "a post whose tag was taken off in the rows keeps its address and the list's link to it until the post is published").

**What stays on the rows, and immediate:** a slug, the place in the tree, publication and scheduling, the trash, a post's content type. The owner of every candidate block is the page's row, and the ranking (live chain, specificity, tree order) reads rows only. The block's own sync (`ContentBlock#sync_listed_post_paths`) and the join row's (`PostTag`) still run; for a record with a copy they find nothing to move.

**Who moves the addresses then.** `Publishing::Version.take!` announces a copy that is in force at once, inside its transaction: `PublicSite::Paths.published(record, version, previous)` re-derives a post's own address, and for a page the posts of every content type its list blocks name in the new copy and in the one before. A save that changes a page's state (publish, unpublish, trash, restore, a move) switches the page between its copy and its rows, so `sync_posts_listed_under` takes the types of both. A copy taken with a time ("Publish changes" at a time) comes into force with no write: the five-minute sweep covers it (`sync_went_live` calls `sync_copies_went_live`, which takes the copies whose `live_at` is later than their `created_at` and lies in the window, and compares each with the copy before it). A late or missing sweep costs more here than for a page going live: the public list is drawn from the new copy at once, so until the sweep a post a new list block lists has no address. Where nothing sweeps, `bin/rails public_paths:rebuild` catches up.

**A clash is refused, not yielded.** Publishing never leaves a live record without an address. `Publishing::PublishChanges` on a post asks first whether the address the post would have with its rows' tags published is another record's (`HasPublicPaths#address_free_as_typed?`, which is `PublicSite::Paths.compute(post, rows: true)` against the current rows) and answers the validation's own error ("gives the address /topic/hello, which is already taken in EN") with nothing written: no copy, no address, no event, no version bump. `Posts::Save` asks the same once the tags are written, where the validation could not see: a tag the save itself created had no id yet, and a post published again after an unpublish was validated by its older copy's tags. The one case that cannot refuse is the sweep bringing a scheduled post copy into force onto an address taken since it was scheduled: it yields and logs, as any sync triggered by another record's write does (`test/integration/public_drafts_test.rb`: "publishing a post's tags that would put it on an address another record holds is refused, and nothing is written", "a new live post whose brand-new tag would put it on a taken address is refused as before, and so is a draft").

**Tags.** A rename and a delete change nothing public while both copies hold the tag's id; they show when the page or the post is published again. `Tags::Listings#affected_content_types` reads the current copies' list blocks beside the rows', because a copy that recorded no id finds its tag by name. A **merge is immediate everywhere**, as a slug is: `Tags::Merge` calls `Publishing::Version.repoint_tag!(from:, to:)`, the one write to a copy after it is taken, which replaces the merged tag's id in every copy's `tag_ids` and in the id a copy's list block recorded (and gives a block that named the merged tag by name, with no id, the kept tag's). A tag's id in a copy is a reference, not content, and the id is about to stop existing; the names a visitor reads in a copy are not touched and change when the record is published. After a merge the lists and addresses that held the merged tag's posts are what they were, and the merged tag's carriers are carriers of the kept tag at once (`test/lib/publishing_guards_test.rb`: "inside Publishing::Version only take! and repoint_tag! write a row, and only Tags::Merge repoints"; `test/integration/public_drafts_test.rb`: "merging a tag changes no public list and no address, with no publish, and publishing the page and the posts afterwards changes nothing either", "a merge reaches a pending copy too: a scheduled change keeps its posts when its time comes").

**The preview** shows the rows, so a post in a list block that is only in a live page's rows has no address there. Its link is that page's preview address plus the post's slug (`PublicSite::Urls#path_for(post, locale, listed_on: page)`, preview only), which the preview's resolver answers with the post drawn on that page (`Resolver#listing_fallback`, `Result#listing_page`); a visitor gets a 404 at the same path.

## Public routing

Routes: `config/routes.rb`. Two catch-all routes, declared last (named routes like `/cs-studio`, `/mcp`, `/up` must win first; the unprefixed catch-all also skips `/rails/active_storage/...`, whose routes Rails draws after this file): `get ":locale(/*path)"` for an explicit locale prefix (`/de/about`), and `root`/`get "*path"` for no prefix at all (served in `SiteSetting#default_locale`, editable in CS Studio's Settings module, checked per request — not a code-level default). `PagesController#redirect_default_locale_prefix` 302s an explicit prefix that happens to name the *current* default locale to the unprefixed URL, so each page has exactly one canonical address even though the default can change at runtime. `PagesController#show` resolves the path through `PublicSite::Resolver` against `public_paths`, where pages and posts both have rows: a post's URL is its canonical listing page's path plus its own slug (`PublicSite::Paths.canonical_page`) — posts have no page-tree node of their own. An old URL answers a 301 to the current one; a miss, a draft (outside preview) or a trashed record is a 404. `PagesHelper#page_url_path`/`#post_url_path` and `config/sitemap.rb` both mirror the same default-locale-omits-prefix rule when building links — grep for `default_locale` if changing how locales map to URLs.

## SEO / sitemap

`config/sitemap.rb` (gem `sitemap_generator`) walks the published page tree across all locales; built via `rake sitemap:create`, output to `public/sitemap.xml`.
