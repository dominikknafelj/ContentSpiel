# The media library

> Describes: `app/models/media/`, `app/services/media/`, `app/controllers/admin/media_controller.rb`, `app/controllers/admin/media_assets_controller.rb`, `app/components/admin/media_library/`, `app/components/media/`, `app/jobs/media/`, `app/values/media/`, `app/queries/media/`, `app/controllers/admin/media_originals_controller.rb`, `app/controllers/concerns/active_storage_*.rb`, `config/initializers/active_storage_access.rb`, `app/mcp/mcp/tools/`, `lib/tasks/media.rake`, `app/channels/media/`, `app/controllers/admin/media_folders_controller.rb`, `app/controllers/admin/media_moves_controller.rb`, `app/controllers/concerns/admin/media_places.rb`, `app/controllers/admin/answers/` (the folder and move answers), `app/javascript/controllers/admin/media/`.

## The asset

`Media::Asset` (`app/models/media/asset.rb`, table `media_assets` -- Zeitwerk would otherwise demodulize `Media::Asset` down to `assets`, so `self.table_name` is explicit, same as `Media::Usage`/`media_usages` below) is the one place any image enters the app: a `title`, translated `alt`/`caption` (Mobility jsonb, same backend and fallback chain as every other translated attribute), and a `has_one_attached :file` that is never served to the public: the public gets only the re-encoded widths this app makes from it ("Widths and the generation" and "Delivery", below). `Media::Decoding` (`app/values/media/decoding.rb`) reads the file once, at validation, and everything the row knows about the pixels comes from that one decode: `width` and `height` as shown (after the camera's rotation; an animated image's first frame), a ~24px WebP `preview` made from the oriented pixels with all metadata stripped, and `has_alpha`. A file is refused, with a message of its own (`activerecord.errors.models.media/asset.attributes.file.*` in `config/locales/en.yml`, because `Media::Asset` is below CS Studio and MCP and the import read the same messages), when it is over the largest upload (`:too_large`), when libvips cannot read it or reads it as another format than its sniffed type (`:unreadable`), or when it describes more than `Decoding::MAX_PIXELS` (100 megapixels, `:too_many_pixels`, judged from the header before a pixel is decoded: a few kilobytes of one-colour PNG can describe a canvas of gigabytes), or when an animation's frame times its frames is more than `Decoding::MAX_ANIMATION_PIXELS` (500 megapixels, `:too_many_frames`, from the header too: every width decodes and encodes every frame on the one images thread, and a long screen recording is under the byte limit). The upload waits for that decode and nothing else: the widths are made afterwards (`test/models/media/asset_test.rb`, `test/values/media/decoding_test.rb`). `#alt_text(override:, locale:)`/`#caption_text(override:, locale:)` are the one place the resolution order lives: a rich-text node's single-valued override (a String) wins outright, then this asset's own translation along the fallback chain; a *translated* override (a block's `alt`/`caption`, a page's `hero_alt`) is passed whole as its `{locale => value}` jsonb (`read_attribute`, not `translated(...)`) and interleaved per locale -- the override in a locale, then the asset in that locale, then the next locale -- so an override written in another language never beats the asset's default in this one. A page hero, an image block and a rich-text `image` node all call through these rather than reading `alt`/`caption` directly, and `Media::PictureComponent` (`app/components/media/`) is the one place every image render builds its `<img>` from (lazy by default; the page hero passes `loading: "eager", fetchpriority: "high"`); what the tag carries is in "What a page draws" below. Allowed types are png/jpeg/gif/webp, byte-sniffed against the actual bytes (never a client's Content-Type header or filename), largest upload from Settings → Images (default 10 MB, 1 to 50) -- SVG stays refused everywhere, and the site logo stays its own separate `SiteSetting` attachment outside the library (moving it in, with the SVG sanitising that would need, is tracked in the roadmap, not built).

## Widths and the generation

The widths of an image are made by `Media::RenditionJob` (`app/jobs/media/rendition_job.rb`), once per image, on the queue `images`. The settings (`ImageSettings`, the five `image_*` columns of `site_settings`: format `webp` by default or opt-in `avif`, a quality per format at libvips' own defaults of 75 and 50, 1 to 6 distinct widths of 160 to 4,000 pixels, default 480, 960, 1600 and 2400, and the largest upload) are read when the job RUNS, never taken from its arguments, so a format saved between the enqueue and the run, or a Regenerate that queued an image twice, makes the image once with the newest settings; an image already made with them is left alone. The widths of an image are every configured width below its own width plus one at the smaller of its own width and the largest configured (`Media::Renditions.widths_for`): an image narrower than the smallest width gets one WebP of its own, and the widest candidate is a re-encoded file, never the original. An animated GIF or WebP is loaded with all its frames and becomes an animated WebP at each width, whatever the format setting, at the WebP quality (`Media::Renditions.format_for`): libvips writes an animation's AVIF as a still image collection, which a browser shows as its first frame, so under AVIF the job reads the header of a GIF or WebP for its frame count, a still one is made in AVIF, and the fingerprint holds the WebP quality too (`test/jobs/media/rendition_job_test.rb`). Its preview is its first frame. Each width is Active Storage's own `variant(...).processed` (a variant record and one download of the original per width, which on the Disk service is a local copy), with `strip: true`, so the public files carry no camera data, GPS included.

What was made is recorded on the row, not found by asking Active Storage: `media_assets.renditions` holds `{ "current", "previous" }`, each a generation `{ "fingerprint", "files": [{ "width", "key", "digest" }] }` (`Media::Generation`, the one reader). The key is the signed variation key an address is built from and the digest is what the 404 concern and the cleanup compare; `renditions_fingerprint` repeats the current fingerprint as a column of its own, so the progress counts, Regenerate and the backfill select with hash conditions. The fingerprint is a SHA-256 of the format, quality and widths. The generation is written in ONE statement after the last width, so a page never lists a width before every width exists, and a job that dies half way leaves the image as it was: the next run finds the variants already made. The generation before the current one is kept as `previous`, so a page cached under it still finds its files, and the one before that is deleted; a change of format never sends a page back to the preview while the remake runs, because the page switches only when the next generation is complete. A failure is retried twice and then recorded as `renditions_failed_at` and the error's class (never its message, which can quote a path); a file libvips cannot read is recorded at once; the image keeps its preview either way, and System status counts it. A vanished image's job is discarded, not retried.

**Queues.** `config/queue.yml` has two workers: `default` (three threads, `JOB_CONCURRENCY` processes) and `images` (ONE thread, one process, polling every 2 seconds), so a batch of uploads takes one core of a small host and mail is never behind an image. `Media::RenditionJob`, `Media::BackfillJob`, Active Storage's analysis and transform jobs are on `images` (`config/application.rb`); purge and mirror and every other job stay on `default` (`test/lib/job_queues_test.rb`). A library upload queues no analysis at all: its blob is marked analyzed with the decode's size when the asset is saved (`Media::Asset#mark_blob_analyzed`), because the analysis would read the whole file again and then touch the asset, moving the media panel's autosave base under an editor typing the alt text (`test/models/media/asset_test.rb`). The plain job has priority 0; `Media::BackfillRenditionJob` has priority 10 and is limited to one per image at a time, so an upload's widths and a Regenerate's never wait behind a backfill.

**Existing images.** `20261031120000_adopt_existing_image_variants.rb` records the variants the old preprocessing made as each image's first generation, under the fingerprint `"adopted"` (`Media::Generation::ADOPTED`). Those were made without `strip` and carry a JPEG's camera data, and the public gets only widths without it, so an adopted generation is served only until the image is made again: it is never kept as `previous`, it is deleted when the new generation is recorded (its addresses then answer 404, and a page cached before the remake shows a broken image until it is reloaded), and a remake that fails withdraws it (the page shows the preview or the box). `Media::BackfillJob` (every ten minutes, `config/recurring.yml`) queues at most 300 images per run, the oldest first, and selects an adopted image explicitly; on a site with nothing due it is one `exists?` answered by a partial index. A purged image's widths stop being served at once (the allow-list below); a TRASHED image's made widths stay public until it is purged, because the trash is restorable and its screen shows them; they carry no camera data.

**Telemetry.** The job's span is a consumer root and is kept (`Telemetry::WorkSampler`); it carries `image.queue_latency_ms`, `image.width.<w>.ms`, `image.bytes_in` and `image.bytes_out`, and no file name or path.

## What a page draws

`Media::PictureComponent` draws one `<img>` and never a wrapper, a `<picture>` or a script (`test/components/media/picture_component_test.rb`; the rich-text scrubber keeps only the preview style on an `img`, `test/sanitizers/rich_text_scrubber_test.rb`). It has three states, always with `width` and `height`, and never the original:

- **Widths made:** `src` is the middle width, `srcset` lists exactly the widths of the current generation, and the preview is the image's own `style` background (`background:url("data:image/webp;base64,...") center/cover no-repeat`), so the browser paints the sharp image over it as it arrives. There is no fade and no attribute for one. An image with an alpha channel gets no background, or the preview would show through its transparent parts for ever.
- **No width yet** (just uploaded, a failed generation, an image waiting for the backfill): `src` is the preview itself and `data-image-preview` lets the stylesheet blur it to its box (`app/assets/tailwind/themes/default/images.css`).
- **Neither:** no `src`, a box of the image's size with its alt, `data-image-empty`, on `--th-sunken`. The box carries the Design System's image mark, 28px at its centre, as a centred non-repeating CSS background of the same `<img>` (`images.css`), so the component keeps no wrapper and no script. A data-URI SVG cannot read a token, so the mark's stroke is `--th-meta` written out once per scheme (`#6c6d72` light, `#8e8f95` dark, under `[data-theme="dark"]`), and `test/integration/design_tokens_test.rb` ("the empty image's mark ...") reads `--th-meta` from `tokens.css` and holds both to it. **A theme that overrides `--th-meta` is not followed**: the mark keeps the default theme's colour until the theme restyles `img[data-image-empty]` itself; **no guard** for that.

The public content security policy sets no `img-src` or `style-src`, which is what lets a `data:` URL stand as a `src` and a background. The scrubber keeps an `img`'s `src` only as exactly the WebP preview data URL, and its `style` only as exactly the preview background, each judged as a browser reads it; `data-image-preview` and `data-image-empty` are the only other attributes it adds. CS Studio draws the same rule through `Admin::Ui::LibraryImageComponent` and `Media::Asset#display_url`: the smallest width that covers the tile, else the preview, else the box.

## Delivery

Every attachment is addressed through Active Storage's PROXY routes (`config.active_storage.resolve_model_to_route = :rails_storage_proxy`, `config/application.rb`): one request, no redirect, answered `Cache-Control: max-age=3155695200, public, immutable` (Rails' own `http_cache_forever`). The address names its bytes for ever, since a signed id carries no expiry and a variation key is a digest of the transformation, so an image is fetched once per browser and once per cache in front of the site, and the headers are what a CDN or a proxy caches by (`docs/reference/hosting.md`, "What a host sets", the paragraph "Images and the proxies in front of the site"). Nothing is configured for a CDN.

What the public routes refuse is an allow-list that fails closed (`ActiveStoragePublicFiles`, applied by `config/initializers/active_storage_access.rb`), shown by `test/integration/image_delivery_test.rb`:

- **No library original, to anyone.** The blob routes (redirect, proxy and the disk route) serve an original only of the site logo. A blob attached to nothing, which is what a purged image's is until `purge_later` has run while its signed id is in every srcset ever published, is refused like the rest; a refusal decided by the attachment row would have served it for a hundred years.
- **No request makes a width.** The representation routes serve a width only when the asset's recorded generation (current or previous) lists its digest and its variant record exists. Rails' own `set_representation` processes the variant inline, and the variation keys of the configured widths are predictable, so a request for a width not made would run a 2,400px transform on a Puma thread; the concern overrides the callback instead of following it (`ActiveStorageMadeVariantsOnly`). Only the logo's variants are made on request, as Rails makes them.
- A refusal is a bare 404 before `http_cache_forever` runs, so it carries no `Cache-Control: public`.
- A note's file stays refused by `ActiveStorageNoteFilesRefusal`; no MCP answer, public route or srcset carries a library original.

**Download original.** Signed-in editors download the original from the media panel through `Admin::MediaOriginalsController` (`GET media/:id/original`, `media.upload`, a kept image; a 403 before anything is looked up). It is not the blob proxy because Active Storage's proxy controllers take no session and cannot tell an editor from a visitor. It streams the original's bytes as an attachment, `private, no-store` (`test/controllers/admin/media_originals_controller_test.rb`). The panel's link is a plain text link with one small line under it, "Only editors can download the original." (`admin.components.media_library.panel.download_hint`).

## The content version

A rendered page bakes in an image's address, alt, caption and dimensions, so a change to an image moves the public content version, but only when a live page can show it (`test/models/media/asset_version_test.rb`). `Media::Asset`'s own commit bumps only when `Media::Usage.shown_publicly` holds for it: a usage row whose owner (through its block, for a block's row) is kept and published or scheduled, or a row of role `published`; a question that fails answers yes, because a needless bump costs a cache and a missed one a stale page. `Media::RenditionJob` bumps ONCE per image, when it records the generation (and when it fails after writing the size and preview, since a cached page holds neither), and the variant records it makes do not bump, so an upload no longer empties the site's caches four times. The logo's variants still bump. Every `update_columns` on `media_assets` says `# version: none (reason)` or bumps (`test/lib/version_bump_test.rb`). Left alone, and not images': re-keying the rich-text render cache on what it reads.

## In tests

`make_renditions!(asset)` (`test/support/media_renditions.rb`) gives an asset a generation: with no arguments the real job runs inline and the files are made; with `widths:` or `fingerprint:` a generation is written without making any file, its keys and digests the real variation ones, so the addresses have the real shape and the public routes answer them 404 (nothing was made). The test environment's queue adapter is `:test`, so a job is enqueued and not run unless the test performs it. A test that wants the public routes to serve a width makes it with the job.

## Measured

The figures that matter are the documentation site's, and its server is behind Cloudflare Access and was not reachable from the session that built this: **the site's figures are the owner's to take and write here.** The procedure, for before (the revision before this work) and after on the same page:

1. A page with a hero image, in Chrome with the network throttled to a mid-tier phone profile (Slow 4G, 4x CPU slowdown) and the cache disabled; record the transfer size of the page and its images, which file the hero is, and the time of the Largest Contentful Paint.
2. Upload a 10 MB photo: time from the request to the answer (the decode and the preview are inside it) and the time until the widths are recorded (`image.queue_latency_ms` and the job's duration in telemetry, or `renditions_fingerprint` appearing on the row).
3. One generation per image for a still WebP and an animated GIF, from the job's span.

Local figures, from libvips on a development laptop (Apple silicon), the pipeline the job runs (`resize_to_limit`, WebP quality 75, `strip`), on synthetic images. They are an order of magnitude, not a promise: noise compresses unlike a photograph.

| What | Figure |
|---|---|
| Decode and preview of a 4000x3000 JPEG of 5.9 MB (`Media::Decoding.read`), the work the upload waits for | about 40 ms |
| The preview of a 2880x1800 PNG | 62 bytes (83 as base64 in the page) |
| Widths of a 4000x3000 JPEG: 480, 960, 1600, 2400 and its own 4000 | 81, 85, 176, 353 and 929 ms, about 1.6 s in all |
| Widths of a 2880x1800 PNG (1.99 MB original) | 21, 35, 67, 126 and 166 ms, about 0.4 s in all; the 480 width is 508 bytes and the widest 15.8 KB |
| An animated GIF of 800x600 and 20 frames (11.9 MB): the 480 and 800 widths | 256 and 647 ms, 206 KB and 1.78 MB as animated WebP |

Add the downloads (a local copy on the Disk service) and the database writes; the job is one thread, so a burst of N images takes N times the per-image figure, which is why the queue exists. The backfill's bound of 300 images per run is about what that queue makes in ten minutes.

## References and usages

Three places reference a library asset -- `pages.hero_media_asset_id`, `content_blocks.media_asset_id` (both plain FKs to `media_assets` -- default NO ACTION, not `on_delete: :restrict`: Postgres 18 reports a RESTRICT violation as SQLSTATE 23001, which Rails doesn't map to `ActiveRecord::InvalidForeignKey`, so every `rescue` of it would miss; `MediaForeignKeysNoAction`) and a rich-text `image` node's `asset_id` (`RichText::BuiltIns`) -- and `Media::Choosing` (shared by `Pages::Save`/`ContentBlocks::Save`) is what lets *choosing* one need `media.upload` and an existing asset id while *clearing* it needs only the ordinary edit right already being checked, refusing a forged or nonexistent id as a validation failure on the field the editor sees rather than letting it reach Postgres as an FK-violation 500 (an asset deleted between that check and the write still hits the FK; `Pages::Save`/`ContentBlocks::Save`/`Posts::Save` rescue `ActiveRecord::InvalidForeignKey` into the same "doesn't exist" failure, `Media::Choosing#vanished_media_failure`). Embedding an image that's already in the library in *rich text* needs no `media.upload` -- it's content editing, covered by the right to edit the post or block, and only the asset's existence is validated (`RichText::BuiltIns`' `image` node); uploading a new image, and browsing the library in the picker, do need `media.upload`. Where an asset is actually used is entirely derived, never hand-maintained: `Media::Usage`/`Media::UsageIndex` (`app/models/media/`, table `media_usages`, unique on `(media_asset_id, owner_type, owner_id, role, locale)` with `nulls_not_distinct: true` so two rows that both have a nil `locale` still collide as "the same usage" instead of silently duplicating) rebuilds one owner's (`Page`, `ContentBlock` or `Post`) *entire* set of rows at once -- delete-then-reinsert, never an incremental diff -- from inside the same save/destroy service transaction that changed it; The images a record's published copies show (its current copy and the one waiting for its time) are rows of role `published` on the page or post (`Media::UsageIndex.refresh_published`, in the transaction that takes a copy; `refresh` leaves them alone unless the owner is destroyed), so an image dropped from the rows but still on the site stays "used" until the changes are published; those rows exist only while the record is live or scheduled (an unpublish releases them in the same transaction, publishing again writes them from the copy then taken); a trashed record keeps them, since restoring it makes the same copy public again; "Used on" and MCP's `usage_count` count a page or post once (`Media::Asset#usages_summary`, `.usage_places_for`), and show `published` alone only when nothing in the rows shows the image any more; the copy a pending one replaces by the clock keeps its rows until the next copy is taken (more protection than needed, never less). `bin/rails media:reindex` (`Media::UsageIndex.rebuild_all`) recomputes the whole table any time it's suspected stale (a bug, a direct SQL edit, a restored backup). `Media::Asset#used?`/`#usages_summary` read this table to back the library's "Unused" filter and a detail panel's "Used on" list, and it's the database's own FK -- not this table -- that's the actual guarantee behind "can't delete an asset that's in use" (`Trash::Purge`, which turns the violation into an ordinary failure). Editing or deleting needs `media.manage` (seeded onto Admin and Editor) or, via `Media::Ownership`, being the asset's own uploader with `media.upload` alone -- see `docs/reference/access-control-and-audit.md` for the full permission story, including how a token is judged.

## CS Studio's Media module

CS Studio's own Media module (`Admin::MediaController`, `Admin::MediaLibrary::ToolbarComponent`/`GridComponent`/`TileComponent`/`PanelComponent`) is the grid/search/multi-file-upload home with one image's autosaving panel in a rail beside the grid (`/media?selected=ID`, keeping `q`, `filter`, `page`, `folder`, `locale`; `GET /media/:id` is a 303 to it, and a trashed or missing id is a 404 either way). Every action sits behind a gate that runs before any image is looked up: `index`, `show` and `create` need `media.upload`, `update` and `destroy` need `media.upload` or `media.manage` (the controller's 403, with no `access.denied`, like every module gate — so to someone with no media right an id that names nothing and one that exists answer alike); which image a holder may then edit or delete is still the services' decision. The segments All / Unused / Missing alt (default-language alt blank or only whitespace) / Untranslated (`missing` in any target language; hidden with one language) / Mine come with counts from one grouped query (`Media::Search#counts`: respects the search, not the segment, kept images only), and an autosave in the panel streams the tile, the counts and the panel's title back rather than reloading. A tile is a link into `#content` that advances the URL, and `admin--media--panel` moves focus into the panel after a tile was chosen and back to that tile when Close closes the rail (a plain load moves no focus). A tile is `.admin-tile` (`Admin::MediaLibrary::TileComponent::CARD`): elevation 1 at rest, 2 under the pointer, the accent outline 2px out while it is chosen (`aria-current`, the picker's `aria-pressed`), and while its made width loads the image's blurred preview under the thumbnail (`docs/reference/design-system.md`, "E4: the content-side screens"). The screen carries `turbo-cache-control: no-cache` and `turbo-prefetch: false` in its head, like the editors, so Back never restores a panel with a stale base or stale chips. A missing, trashed or malformed `?selected=` is the 404, never a grid without a panel; its link is "Back to Media" with the search and segment kept. **The rail** (`#media-rail`, `docs/reference/design-system.md`, "E4: the content-side screens", which has the measures) is laid out by the library's own width (`#media-library`, the `admin-media` container), never the window's: below 760px of the library it is a card under the grid with every panel shown; from 760px the same card 340px beside the grid, sticky and scrolling inside itself; from 1200px it docks on the rail's ground, and its tabs, Image and then whatever is registered at the panel slot `media.rail.tabs` (`docs/reference/slots.md`, "A panel slot"), choose the one panel shown, under a tablist named "Image details". The view draws `Admin::Ui::RailSlotComponent.new(slot: "media.rail.tabs", …)` and never names a feature (`test/lib/notes_boundary_test.rb`'s `SLOT_HOSTS`). Close is the rail's last child, a link to the grid with its `q`, `filter` and `page`, over the rail's top-right corner; Escape inside the rail presses it unless a field, the notes, an open dialog or a menu takes the key first (`admin--media--panel#escape`). Choosing another tile keeps the tab that was current (Notes stays Notes while the address advances), but the address does not carry it: a reload shows Image. Every other opening is unchanged. Beside its grid stand the library's places (`Admin::MediaLibrary::FolderTreeComponent`, `mode: :picker`, drawn in the frame by `admin/media/picker`): a 200px list of read-only rows (no "+", no handle, no drag) whose links load the frame with `picker=1` and no history entry, folded but for the path to the place and keeping no folds (no `data-tree-open-cookie`, so nothing reaches `cs_media_open`), and below 640px the same places as a select, "Folder", above the toolbar. The frame opens at the place it showed last in this browser (`localStorage["cs.media.picker.place"]`, `all`, `none` or an id, every read and write inside `try`/`catch`; refused storage is All media), read after each load from `#media-picker-place` inside the frame: a folder gone meanwhile answers All media with `data-media-place-gone`, and the script forgets it. "Uploads go into Client A" (or "into no folder") stands before Upload and describes it, and an upload goes into the place shown. New page and New post hang from the same fixed top edge (`Admin::Ui::DialogComponent`'s `hang:`). MCP exposes the library read-only as `list_media_tool`/`get_media_tool`/`list_media_folders_tool` (`app/mcp/mcp/tools/`); `list_media_tool` pages 50 per call through a `page:` argument and takes `folder` (a folder's id, or `none`; an unknown one is the error "No such folder"), each entry of it and `get_media_tool` names its `folder` as `{id, name, path}` or null, and `list_media_folders_tool` lists the tree in order with `parent_id`, `path` and the kept `image_count`, all three behind `media.upload`. It is the only MCP list tool that pages: `list_posts_tool` returns every readable post in one answer (without bodies), which is a roadmap row. `db/migrate/20260929050000_move_images_into_media_library.rb` moved every legacy `Page#hero_image`/`ContentBlock#image` Active Storage attachment into this one storage path -- deduping identical files by blob checksum, recording which assets it created in a ledger table (`media_library_migrated_assets`, so its own `down` can roll back cleanly without touching a pre-existing or later-uploaded asset), leaving in place (and reporting, never silently dropping) any attachment whose blob type the library refuses, and adding the `rich_text` usage rows for bodies that already embedded a library image (rich-text uploads predate the index; without those rows such an image reads as "Unused" and can be deleted -- a rich-text reference has no FK). `20260929070000_backfill_rich_text_media_usages.rb` runs that same additive, idempotent SQL for databases that ran the move before it did. `bin/rails media:orphans` lists (and, with `CONFIRM=1`, purges) blobs with no attachment at all -- duplicates that migration deliberately never deleted, plus ActionText leftovers; never a blob of the notes' storage service, which the notes services remove themselves -- and `bin/rails media:regenerate` queues `Media::RenditionJob` for every kept image not made with the current image settings (`Media::Asset.not_made_with`), idempotent since it only ever looks at what is recorded as made, never at what is queued. An existing site's images keep their widths through the deploy and get their previews from the backfill ("Widths and the generation", above).

## Folders

A folder is a place an editor keeps images in. It is never drawn on the site: no page, address, width, usage row or content version names one, and rich text names images by id, so moving an image changes no body. Spec: `docs/superpowers/specs/2026-11-16-media-folders-design.md`.

**The table and the tree.** `Media::Folder` (`app/models/media/folder.rb`, table `media_folders`, `self.table_name` explicit as the asset's is) holds a `name`, a `parent_id` (nil: at the top, a foreign key with NO ACTION) and `created_by_id`. `media_assets.folder_id` is nullable, so an image is in at most one folder, with a foreign key `on_delete: :nullify`, which is the floor under a console delete and never the way a folder's images are handled (the keys *to* library images stay NO ACTION, "Rules a change can break silently"). A unique index on `(parent_id, lower(name))` with `nulls_not_distinct` makes two siblings of one name in any case, and two at the top, collide. A name is stripped, 1 to 80 characters (`NAME_LENGTH`), with no control character. Folders nest at most four levels (`MAX_DEPTH`, a folder at the top is level 1) and a site holds at most 1,000 (`MAX_FOLDERS`); the model holds only what one row says of itself, and the depth, the count and the name's uniqueness are the services', judged under the tree's lock. Names are not translated and have no order of their own: `Media::FolderTree` (`app/values/media/folder_tree.rb`) is built from one query (`Media::Folder.pluck(:id, :parent_id, :name)`), sorts each level case-insensitively with a run of digits read as a number ("Event 2" before "Event 10"), and answers `roots`, `children`, `path`, `depth`, `height`, `descendant_ids`, `inside?` and `find` from memory; the column, the picker, the Move to… list, the services' checks and MCP all read it, and nothing walks the table recursively in SQL. Images in a place keep the library's order, newest first.

**Places.** `Media::Place` (`app/values/media/place.rb`) is the one value of where a listing looks: `ALL`, `NONE` or a folder. The parameter is `folder`: absent, blank or `all` is All media (every kept image, wherever it is), `none` is Not in a folder, digits are a folder's id and show that folder's own images, never its subfolders'. `Place.parse(raw, tree:)` is nil for an id the tree does not hold and for anything that is not a String (`?folder[]=5`): on the Media screen that is the 404 with "Back to Media", in the picker All media. The search and the segment narrow the place (`Media::Search.new(place:)`, and the segment counts are the place's), so a search typed in a folder looks in that folder, and the screen offers the same search in All media. **Every link of the Media screen keeps `folder` beside `q`, `filter` and `page`** (`Admin::MediaController#list_query`); a link to another place keeps `q` and `filter` and drops `page`, `selected` and `select`, and `Admin::MediaPlaces#place_query` is the one builder of it. `?selected=ID` with no `folder` is All media, as before. `Media::FolderCounts` (`app/queries/media/folder_counts.rb`) answers `{ all:, none:, folders: { id => count } }` from one grouped query over kept images, a folder's count being its direct images; a trashed image is in no count and no listing. `Place#digest(tree)` is an MD5 over the place's kept image ids and the names of the folders on its path, which a tab compares to learn whether what it shows changed ("Other tabs", below).

**The services.** Three, each an `ApplicationService`, none ever draws or fetches for the site.
- `Media::SaveFolder.call(folder_or_nil, attributes: { name:, parent_id: })` creates, renames or moves a folder; `Media::DeleteFolder.call(folder)` deletes one. Both need `media.manage`: shaping the library is managing it, and a person with `media.upload` alone uploads into folders and moves their own images but does not reshape the tree. Every tree write takes `Media::Folder.lock_tree!` first (`LOCK TABLE media_folders IN SHARE ROW EXCLUSIVE MODE`, the one SQL string, marked `# sql:`) and then reads the whole tree, so two moves that would make a cycle together, or two creates of one name, are decided one after the other against the tree as it then is. The refusals are the services' sentences, put on the record's `name` or `parent_id` ("Give the folder a name.", "Use at most 80 characters.", "A folder named “X” is already here.", "A folder can't go inside itself.", "That would nest folders more than 4 levels deep.", "That folder is gone.", "A site holds at most 1,000 folders."); the unique index's `RecordNotUnique` is rescued into the same name failure. A rename and a move are `media_folder.renamed` and `media_folder.moved`, each its own event and never coalesced.
- `Media::DeleteFolder` moves a folder's images and its subfolders one level up, into its parent (or out of every folder at the top), and then deletes the row; it is never refused for what the folder holds. Its order is the tree's lock, then the folder's own row `FOR UPDATE`, then the images (every image with the folder's id, kept or trashed, locked by id) and the subfolders, then the row. A subfolder whose name the parent holds takes the first free " 2", " 3", … and is recorded as `media_folder.renamed`; `DeleteFolder.preview` says before the press what will move and be renamed, which the confirm dialog quotes. One `media_folder.deleted` is recorded on the folder before the row goes, its metadata the parent, `moved_image_count`, `moved_folder_ids` and, for `IDS_KEPT` (200) images or fewer, `moved_image_ids`; there is no `media.moved` per image. There is no Undo: the event names what moved.
- `Media::MoveImages.call(asset_ids:, folder:)` (`folder` nil: out of every folder) is the one writer of `media_assets.folder_id` after an upload. Each image needs its own edit right as `Media::Save` judges it (`Media::Ownership`: `media.manage`, or its uploader holding `media.upload`), **all or nothing**: one image the actor may not move refuses the whole move, said by how many ("2 of these images are not yours to move. Nothing was moved."), with one denial recorded. At most `MAX` (200) ids, refused before anything is read; a trashed or missing id refuses the move. The target is read `FOR KEY SHARE` and the images `FOR UPDATE` by id, the order `DeleteFolder` shares (folder rows first, then image rows by id); `FOR KEY SHARE` and never `FOR SHARE`, which would deadlock with a delete of the target's parent re-parenting the target while a move holds that parent's images. So whichever of a move and a delete commits first wins whole: a move into a folder deleted first says "That folder is gone." and moves nothing, and one that commits first has its images moved up with the rest. The write is one `update_all(folder_id:)` that touches no `updated_at`: the panel's autosave base is the image's `updated_at`, and a move that moved it would refuse, with a 409, the alt text someone is typing in another tab (the blob-analysis incident). It carries `# version: none (a folder is never drawn on the site)`, as does every write on `media_assets` around the callbacks in these services. An image already in the target is left out and recorded nowhere; each image that moved gets its own `media.moved`, never coalesced.
- An upload takes the place's folder (`Media::Upload.call(file:, folder: nil)`, and `folder` on `POST /media` and `POST /media_assets`): it needs `media.upload` alone, reads the folder through the tree and locks it `FOR KEY SHARE` like a move's target, and a folder deleted meanwhile refuses the file ("That folder is gone.") and stores nothing. `media.uploaded` records `folder_id`, and the answer carries `folder_counts` beside `counts` (`Admin::MediaUploadResponses`).

**The Media screen's column.** The Folders column is the shell's tree column, the subject `media` (`docs/reference/cs-studio-shell-and-dashboard.md`, "The column hosts three screens"), drawn through the view's `content_for :tree` for a full answer only, outside `#content` (`Admin::MediaLibrary::FolderTreeComponent`, `#media-folder-tree-part`). Its rows are the shared tree row (`Admin::Ui::TreeItemComponent`): All media and Not in a folder with their counts, a rule, then the folders with their direct counts (nothing at 0), each folder above level 4 with a "+" ("New folder in %{name}") for `media.manage`; "+ New folder" in the head is for the same right. Rows link to `?folder=`. Which branches are open is the cookie `cs_media_open` (`TreeOpenSet::MEDIA_COOKIE`), read against the folders' ids, with no root and the path to the place shown always open; the picker's places keep no folds. `admin--media--folders` marks the row of the place `#content` names (`[data-media-place]`) after each frame navigation, opens the path to it, rewrites the rows' links with the search the content shows, and follows `data-media-go`, which a write's answer carries because a stream cannot navigate. The place heading (`PlaceHeadingComponent`) is the breadcrumb, the `h1` the place's name, the count, the "Folder actions" menu ("New folder inside…", "Rename…", "Move to…", "Delete folder…", `media.manage`), Select and Upload images. Subfolders are not drawn in the grid.

**Writes from the browser.** The folder dialogs (`FolderDialogComponent`, one dialog set up as each trigger opens it by `admin--media--folder-dialog`; `DeleteFolderDialogComponent`, the destructive confirm) and the Move to… dialog (`MoveDialogComponent` with `MoveChoicesComponent`, `admin--media--move`, its list fetched as it opens from `GET /media/move/new`) post through the write queue (`saving/queue.js`): `Admin::MediaFoldersController` (`create`, `update` for a rename or a move, `destroy`; every action gated by `media.manage` before any folder is looked up, so an id that names nothing and one that exists answer alike) and `Admin::MediaMovesController` (`POST /media/move`, gated by `media.upload` or `media.manage` and then the service's all-or-nothing). Their answers are Turbo Streams, one responder per outcome (`Admin::Answers::FolderSaved`, `FolderRefused`, `FolderDeleted`, `ImagesMoved`, `MoveRefused`, `FolderTreePart`): the column's part with its counts, the moved tiles taken out of a folder's grid, the segment counts, each moved image's Folder fact, and a toast. A refusal of a create or a rename stands under the field; a refusal of a move sent from the dialog is drawn in the dialog's list, a danger notice that takes the focus; any other refusal is an error toast. A folder or an image gone by the time a write arrives is "That folder is gone." and no 404 page. `GET /media/folders` is the column's part as it stands, with the screen's gate (`media.upload`).

**Selecting and dragging.** `select=1` is selection mode (`admin--media--selection`, on `#media-library`): the tiles are `aria-pressed` buttons, Shift+click ticks a range, "Select all" ticks what the page draws, and Move to… (the bar's) opens the dialog on exactly what is ticked. What is ticked lives in the page alone and is taken back before Turbo caches it. A drag (`admin--media--drag`) is made only under `(pointer: fine)` and goes through `loadSortable()` (`editor/drag.js`, `sort: false`, pointer-driven): a tile, or the ticked tiles from a ticked tile, onto a folder row or Not in a folder; a folder, by its row's gutter handle, onto a folder row or All media, with no search typed. The row that takes the drag carries `TreeItemComponent::CLASSES[:drop_into]` (`admin-tree-row--drop-into`); a row that cannot take a folder shows no target and says why ("this folder", "too deep", "name taken", judged from the rows' `data-media-folder-*`), and the server judges again. A folded folder opens after 600ms of hover. Escape ends the drop for the rest of that drag and is taken. The drop is sent through the write queue.

**Other tabs.** `Media::LibrarySignals.changed(reason:)` (`app/models/media/library_signals.rb`) says through `Live::Signals.later` on the one stream `media:library` that the folders changed (`folders`: any tree write, a delete included) or images moved (`moved`), after the outermost commit, never which: the payload names no folder, image or word. Its `origin` is `Current.editing_tab`, the acting tab (the header `X-Notes-Tab`, read for every CS Studio request), so that tab does not fetch what its own answer drew. An upload sends nothing. `Media::LibraryChannel` streams it to whoever holds the `media` record kind's read right (`media.upload`) as of the subscribe, and rejects everyone else alike; folders are not a record kind, and no note or presence attaches to one. `admin--media--live` (the screen's `#media-library`, and the picker's `<dialog>` while it is open) fetches the column's part again, at most once per two seconds, and replaces it silently, keeping the folds and the focus. **The grid is never replaced under the person:** when the fetched part's place digest differs from the one the grid was drawn with (or the folder shown is gone), one notice stands above the grid, "Images here changed since you opened this view.", with "Show changes", which reloads the place's frame; it is taken back before Turbo caches the page, and never stands twice. No Turbo page refresh or morph is used.

**The picker** browses the same places: `GET /media?picker=1` takes `folder`, `Admin::MediaLibrary::FolderTreeComponent` with `mode: :picker` draws the read-only list (a select below 640px), and the place it showed last is `localStorage["cs.media.picker.place"]`, per browser and not per person, every read and write in `try`/`catch` (the module paragraph above has the rest).

**MCP.** `list_media_tool` takes `folder` (an id, or `none`), each image names its `folder` as `{id, name, path}` or null, and `list_media_folders_tool` lists the tree in order; MCP writes nothing to folders. A folder's id that names nothing is the error "No such folder", never an empty list.

**Permissions.** Nothing is access-controlled by folder: whoever opens the library (`media.upload`) sees every folder and image. The seam for later is named, not built: a grant scope key `media_folder_ids` (as `page_ids` is for pages), matched against a folder and the folders under it, which would make the `media` record kind scoped (`RecordKinds.register "media", scoped: true`), so that the library's lists, the picker, ⌘K, MCP and the library stream narrow through `AccessControl.scope` and Not in a folder becomes a place a scope grants or not. Every list of images already goes through `Media::Search` or a named scope and the place is one value (`Media::Place`) a scope can narrow.

**Audit.** `media_folder.created`, `.renamed`, `.moved` and `.deleted` are on the folder (labelled by its name; its link is the Media screen at that folder, none once it is deleted; the log's Type filter lists "Media folder"), and `media.moved` is on the image and counted (the dashboard reads "moved 12 images to “Client A”", runs joining only when they went to one place); all five are in `Editing::Signals::SILENT` (`docs/reference/access-control-and-audit.md`).

## Notes on an image

A library image takes notes like a page or a post (`docs/reference/notes.md`). There is no drawer on the Media screen: the image's notes are the rail's **Notes** tab (`#media-notes`; `Admin::NotesScreen::MediaSectionComponent`, registered at the rail's panel slot `media.rail.tabs`, which the Media view draws without naming it), one element at every width: where the rail docks it is the Notes tab's panel, its own heading hidden since the tab names it, and the tab's count is the open threads as the tab's bubble, reading "N new" on the accent while something is unread for the viewer; below that the rail draws no tabs and it is the section after the Image panel, under its heading "NOTES · N OPEN". `?selected=ID&notes=open` or a `thread` makes it the current tab as the page is drawn (`tab_current?`). It embeds the same `turbo-frame#notes` as the editors' Notes tab with `view=media`, outside the panel's autosave form: a note is no field of the image, and inside an `admin--saving--autosave` form a note's field would be saved as one. A thread opens in place in the panel. With no thread the list says "No notes on this image yet." (`admin.components.notes_screen.rail_panel.empty_image`), standing as the label over the composer for a viewer who may start one. Anyone who may open the panel may read and write notes there (`media.upload`), whether or not the image is theirs to edit; deleting someone else's note and pinning need `media.manage` or being the image's uploader. A tile with open threads shows a count chip on the image, top right, on the surface background so that it stays readable over a photo, accent while something on that image is unread for the viewer (`Admin::NoteCountsHelper#media_note_marks`: one grouped query for the page of the grid and one beside it, only for a `media.upload` holder); the picker's tiles show none, since choosing an image is not reading about it. `?selected=ID&thread=N` opens the panel at a thread, which is where an inbox row for an image leads. **A note's files are not library images**: they are attachments of the message on a storage service of their own (`notes` in `config/storage.yml`), with no `Media::Asset`, no usage row and no variant, read only through `Admin::NoteFilesController` and refused by Active Storage's public read routes. A purged image takes its notes with it (`Trash::Purge` calls `Notes::Remove`); a trashed one keeps them, hidden.

## Who else has an image open

The Image panel's title row also draws the slot `media.panel.header`, after the title: presence's people (`Admin::PresenceScreen::PeopleComponent`, `size: :panel`), 22px circles standing 2px apart with no ring, two and then "+N" at every width. The title is `flex-1 min-w-0` and is cut with an ellipsis on one line (the full name stays in the fields below), and the row keeps clear of the rail's Close (`pr-10`); the people never give way, since a group that vanished on long names would be unreliable. It is a part of the Image panel, so closing the rail ends its subscription; it stays in the document while the Notes tab is current, as a hidden panel. Who is shown is decided in `docs/reference/presence.md`; an image is a record kind with no per-image read right (`RecordKinds`, `scoped: false`), so a user without `media.upload` gets the 403 of the media screen, and the grid's tiles show no presence (not built).

## Rules a change can break silently

Moved word for word from `CLAUDE.md`, where "above" and "below" meant the list these rules stood in: a rule named that way may now be in another reference file. Each names the test that guards it; a rule or a part of one with no guard is also said in `CLAUDE.md`.

- An image a current or pending copy shows is in use (role `published`, released on unpublish) (`test/models/media/usage_index_test.rb`: "an image only the published copy shows cannot be moved to the trash or deleted, and can once the changes are published").
- No public route, page, `srcset`, rich-text image or MCP answer gives a library image's original, and no request makes a width: Active Storage's public routes serve an allow-list (the logo, and the widths the asset's recorded generation lists whose variant record exists), a purged image's blob included in the refusal, and Rails' `set_representation` is overridden, not followed, because it transforms inline; editors download the original through `Admin::MediaOriginalsController` (`test/integration/image_delivery_test.rb`).
- An image moves the public content version only when `Media::Usage.shown_publicly` holds for it, and the library's widths once per generation from `Media::RenditionJob`, never one bump per variant record; a write around the callbacks on `media_assets` says `# version:` (`test/models/media/asset_version_test.rb`).
- An asset's `width`, `height`, `has_alpha` and preview come from `Media::Decoding` at validation, on every path that makes an asset (`Media::Upload`, the import, a test's `create!`), and nothing reads the file again to learn them (`test/models/media/asset_test.rb`).
- Image jobs (`Media::RenditionJob`, `Media::BackfillRenditionJob`, `Media::BackfillJob`, Active Storage's analysis and transform) are on the `images` queue, served by one thread, and every other job stays on `default`: a new job names its queue (`test/lib/job_queues_test.rb`).
- `Media::PictureComponent` stays one `<img>` with no wrapper and no script, and `RichTextScrubber` keeps on an `img` only the exact preview `src` and `style` and the two `data-image-*` attributes (`test/components/media/picture_component_test.rb`, `test/sanitizers/rich_text_scrubber_test.rb`).
- A folder never reaches the site, and `media_assets.folder_id` has few writers: `Media::MoveImages`, `Media::DeleteFolder`'s move up and `Media::Upload`, each taking the folder's row in the order above, recording what it moved and marking its write `# version: none (a folder is never drawn on the site)` (`test/lib/media_folder_writers_test.rb` reads `app/` and `lib/` for any other assignment, bulk write or new image with a folder; `test/lib/version_bump_test.rb` holds the mark; `test/services/media/move_images_test.rb`: "a move touches neither updated_at nor the content version"; `test/integration/public_blocks_test.rb`: "an image's folder changes nothing a visitor is served", a page's body, ETag and the content version equal before and after a move). **No guard** for a write that computes the column's name, raw SQL, a migration, or a script, none that a new image-writing path (an MCP upload) sets the folder through `Media::Upload`, and none that a public template or component added later reads an image's folder.
- Every list, count or tool over a place hides the trash itself, and a trashed image keeps its folder (`test/integration/trash_visibility_test.rb`: "a trashed image is in no folder's listing or count, and comes back to its folder", "list_media_folders counts no trashed image").
- A new link of the Media screen that opens a list of images keeps `folder` beside `q`, `filter` and `page` (`Admin::MediaPlaces#place_query` builds it). **No guard**: a link that drops `folder` sends a person back to All media.
- A new write path that changes the folder tree takes `Media::Folder.lock_tree!` first and says `Media::LibrarySignals.changed`. **No guard** for one that skips either.
