# Forms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Editors build forms in CS Studio, place them on pages with a Form block, and receive each visitor's submission by mail and, where the form keeps them, encrypted in CS Studio, with a seam for a gem to add field types and destinations.

**Architecture:** A `Forms::Form` is its own trashable record (no drafts), written by `ApplicationService`s; its fields are a jsonb list whose values are typed by `ContentModel::FieldTypes` and whose public side is a thin form registry, `Forms::FieldTypes`. A visitor posts to its own cookieless endpoint (`FormSendsController`, not a `PublicController`), where the spam measures run and `Forms::Submit`, acting as the one new actor `AccessControl::VISITOR`, writes an encrypted `Forms::Submission` and one `Forms::Delivery` per destination; each delivery is a job (`Forms::DeliveryJob`) that asks its `Forms::DestinationTypes` entry to deliver. Public pages stay as they are: the Form block draws a form whose only per-render value is a signed draw time, and the content version moves when a form changes.

**Tech Stack:** Rails 8.1, Active Record encryption, Action Mailer through `ApplicationMailer`/`MailSettings`, Solid Queue (recurring jobs), ViewComponent, Stimulus (import maps), Tailwind, Minitest, Capybara on Cuprite.

**Spec:** `docs/superpowers/specs/2026-11-03-forms-design.md` (decisions 1–10; read it whole). Recipes this plan follows: `docs/reference/content-blocks-and-types.md` ("Adding a block type", steps 0–11; "Field types"; "Block types from outside"), `docs/reference/mail.md`, `docs/reference/access-control-and-audit.md`, `docs/reference/theming.md` (the public wall, the contract, the ledger), `docs/reference/trash.md`.

## Decisions the spec left to the builder

Each goes into the spec's "As built" in Task 9, with its reason.

1. **Tables and columns.** `forms` (`name` string not null; `fields` jsonb list, default `[]`; `submit_label`, `thank_you` jsonb, Mobility's backend; `keep_submissions` boolean not null default false; `keep_days` integer null, nil meaning the site's default; `trashed_at`, `trashed_by_id` as `posts`; timestamps). `form_destinations` (`form_id` FK cascade, `kind` string, `position` integer, `settings` jsonb, `secrets` text encrypted, `secrets_saved_at`). `form_submissions` (`form_id` FK cascade, `page_id` FK nullify, `locale` string, `answers` text encrypted, `created_at`; index `[form_id, created_at]`). `form_deliveries` (`submission_id` FK cascade, `destination_id` FK nullify, `kind` string, `state` string `waiting|sent|failed`, `attempts` integer, `failure` jsonb `{key, line}`, `sent_at`, `failed_at`; index `[state]`). `site_settings.form_keep_days` integer not null default 90. Why: a field list saved whole by one explicit Save needs no row per field; a destination has its own secrets and a delivery its own state, so they are rows.
2. **Field types reuse `ContentModel::FieldTypes` for what a value is, and add a thin form registry for what a visitor's form needs.** A form type names its `value_type` (`short_text` → `:string` with `max: 500`, `long_text` → `:text` with `max: 5_000`, `email` → `:email` (a new ContentModel type), `choice` → `:select`, `checkbox` → `:boolean`), whose `cast` and `validate` it calls with a `ContentModel::Definition::Field` built from the stored field. `Forms::FieldTypes` holds only the form's half: the builder's options, the public input component, the summary flag and how a value reads in a submission. Why: #114's admin-defined fields need exactly the value half and the existing `Admin::Fields` inputs, which is why that half stays the content model's and assumes no form; a public input, choices typed by an editor and a submission's display are a visitor form's own. Cost if wrong: the form registry folds into `ContentModel::FieldType` later, one member each.
3. **Forms are trashable, with no drafts.** Trashed like pages and posts (`Trash::Move`/`Restore`/`Purge`, a "Forms" tab in the Trash); a purge deletes the submissions. A form's change is live at its Save (an explicit Save, not autosave, so a half-typed field is never live). A trashed form draws nothing and its endpoint answers "no longer available". Why: the spec's suggestion; explicit Save gives what drafts would have given a form.
4. **Keeping-time default lives on `site_settings.form_keep_days` (90), in a "Forms" card of Settings**, saved by `Settings::Save` (`settings.manage`). A form's `keep_days` nil follows it at every run of the clean-up, so changing the default changes those forms' existing submissions too.
5. **Spam numbers.** Minimum send time 3 seconds (`Forms::Drawn::MIN_SECONDS`). Rate limits: 5 sends per visitor per 10 minutes across all forms, 30 per form per 10 minutes (`Forms::SendLimit`). The visitor is counted by an HMAC of the address (`Forms::SendLimit.visitor_key`), so the cache holds no IP. Why: a person sends a contact form once or twice; a small site's form gets a few a day, and 30 in ten minutes is a flood. Cost of the per-form limit, named: during a flood a real send is answered as a success and kept nowhere, as the spec says for every trip.
6. **Failure handling with keeping off.** With encryption keys every submission is a row, encrypted, whatever the form keeps; with keeping off it is deleted once every delivery has been sent (`Forms::DeleteSubmissions`, reason `delivered`), and a submission with a failed delivery stays, listed under the form as not delivered with Send again, for at most 30 days (`Forms::UNDELIVERED_DAYS`). A mail while mail is not ready fails at once with the key `not_ready` (no retry) and so is kept the same way. Without encryption keys there is no row: the mail job carries the answers sealed (`Forms::Transit`, `ActiveSupport::MessageEncryptor` keyed from `secret_key_base`), a mail that fails after its retries is lost and logged by form id, and the form's screen says so beforehand; with no keys AND mail not ready a send is refused to the visitor ("This form can't take answers at the moment."), never lost silently.
7. **The list's summary is computed, never stored:** the list decrypts the 50 rows of the page it shows and `Forms::Summary.of` takes the first two answers of types whose `summary` is true (`short_text`, `email`), joined with " · ", cut at 80 characters. A row that cannot be decrypted (keys changed) reads "Can't be read" and can still be deleted.
8. **A visitor's write is a service that authorizes, with one new actor: the bent rule.** `AccessControl::VISITOR` (a value, `AccessControl::Visitor`) is allowed exactly `forms.submit` and only on `:public`; `forms.submit` is registered with `grantable: false`, so no group, token, matrix or seed holds it. What bends: "a nil or unknown actor on `:public` is denied everything" becomes "everything but `forms.submit` for the visitor". Guards: `test/models/access_control/visitor_test.rb` (every registered key × every channel) and `test/lib/visitor_actor_test.rb` (only `FormSendsController` sets it). The visitor's audit event has no actor row, `actor_label` "visitor", channel `public`, no IP.
9. **Content version.** `Forms::Save` and the three trash services on a form call `PublicSite.bump_version!` in their transaction: a form has no published copy, so every write that changes what a placed form draws moves it ("for a record with no copy every write moves it"). Submissions and deliveries never move it. The Form block's own settings are the page's and follow publishing as every block does.
10. **The signed draw time, without a session:** `Forms::Drawn.token(form, at:)` is `Rails.application.message_verifier("content_spiel forms drawn")` over `{ "f" => form.id, "t" => at.to_i }`, with no expiry (a cached page keeps an old token, which only makes it older than the minimum). The no-JavaScript error page carries the token the visitor first sent, never a fresh one, so a quick correction is never dropped as too fast.
11. **The mail destination delivers inside `Forms::DeliveryJob`, through `ApplicationMailer.deliver_in_job`,** not `ApplicationMailer.queue`: the delivery row must learn its result, and one job per delivery is the seam a gem's destination uses too. `deliver_in_job` keeps mail's rules (the site's state recorded, a connection failure recorded once after the last attempt, the line scrubbed).
12. **The endpoint answers JSON to its script and a plain page otherwise.** `form-send` (a public controller like `code-copy`) posts with `Accept: application/json` and writes the thank-you and errors as text; without it the answer is `form_sends/*.html.erb` in the `product` layout. `PublicController`'s cookie wall moves into a concern, `Cookieless`, which both include.
13. **The model is `Forms::Form`, not `Form`** (table `forms`), as the library image is `Media::Asset`: a top-level `Form` would make the block type `form` a name the generator refuses (`BlockTypes::Form` would shadow it), and the block's name is what themes and the contract read.

## Review Focus

1. **A visitor without JavaScript fixes an error and resends at once.** The redrawn page must not reset the draw time, or a correction under 3 seconds is answered as a success and dropped. → Task 6, test "the error page carries the first token: a correction sent a second later is kept".
2. **Encryption keys changed or lost after submissions were kept.** The list, a submission and System status must not raise. → Task 5, test "a submission that can't be decrypted is listed as Can't be read, opens with that sentence, and can be deleted".
3. **A field removed, renamed or a choice reworded after submissions exist.** An old submission still reads as it was sent. → Task 3, test "a submission keeps the labels and choice words it was sent with after the form changes".
4. **One form placed twice on one page** (or on a page and in a section). Ids, labels and error links must not collide. → Task 7, test "two Form blocks of one form on one page have distinct field ids and error links".
5. **A form trashed while a visitor has the page open.** The send answers "This form is no longer available." with a link back, never a 500 and never a stored row. → Task 6, test "a send to a trashed or missing form is a 404 page with a link back, and writes nothing".
