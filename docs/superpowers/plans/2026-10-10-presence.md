# Presence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show who else has a page, a post or a library image open (in the editors' headers and the media panel) and where someone is working (in the page tree and the posts list), on three seams that notes and presence share.

**Architecture:** First the live notes script is split so its connection becomes a shared module. Then three seams are extracted and notes is moved onto each: a registry of record kinds, a live core on the server (one sender of signals, one base channel), and screen slots with a registry. Presence is then built as the second user of all three: a throwaway table, a roster query, a channel, a sweep job, one script and two components.

**Tech Stack:** Rails 8.1, Postgres, Action Cable (Solid Cable in production, the `test` adapter in tests), Stimulus through importmap-rails, ViewComponent, Tailwind v4, Minitest, Capybara on Cuprite.

**Spec:** `docs/superpowers/specs/2026-10-10-presence-design.md`. The look: `docs/superpowers/specs/2026-10-10-presence-handoff.md` (binding for every size, token, place and wording; where it and the spec differ on look, it wins).

## Global Constraints

- Every test command is prefixed `PGGSSENCMODE=disable`. System tests need `bin/rails tailwindcss:build` first, run with `PARALLEL_WORKERS=6`, and a named set of system files is run with `bin/rails test <files>`. Never two test runners at once. Output of a long run is redirected to a file, never piped through `grep`.
- Tasks 1–8 change no behaviour a person can see: the existing notes tests pass with no assertion edited (a name that follows a moved file is the only allowed edit).
- The layout rules of `CLAUDE.md` hold (`test/lib/source_layout_test.rb`): a controller is in `app/javascript/controllers/admin/<topic>/`, a topic's plain modules in `app/javascript/<topic>/`, a component in its screen's folder or `Admin::Ui`, a component folder's strings in `config/locales/admin/<folder>.en.yml`. A Stimulus identifier follows its file's path; when a controller file is added, moved or split, every attribute, event name and selector follows, and tests that assert a controller's ABSENCE by a fragment of its name are searched by hand.
- New admin strings are locale keys. No colour literals. No inline event handlers. No fixed sleeps in system tests (`assert_eventually`, `await_js`, `await_notes_live`, `backdate`).
- A signal carries a kind, ids, a reason and an origin, never text or a name, and every part it refreshes is fetched through the read scope. A record outside the viewer's scope is not found (404, or a rejected subscription), never forbidden.
- Nothing replaces a note's composer or an open edit form. Turbo's morphing refresh stays off.
- `Admin::Presence` is never defined (it would shadow `Presence::`): components are `Admin::PresenceScreen::…`, the controller is `Admin::PresenceController`, a class.
- `presence_marks` is an ordinary table (Rails' schema dumper does not record `UNLOGGED`, so the spec's D5 falls to its stated alternative).
- Presence's numbers: away after 5 minutes without input; keep-alive every 30 seconds; a row is stale after 60 seconds; the sweep deletes rows older than 5 minutes; a list re-fetches at most once every 5 seconds.
- A design question the handoff does not answer is not decided by the implementer: finish the rest and report it under "Design questions".
- Commits are conventional and end with:

  Claude-Session: https://claude.ai/code/session_01B1T44ndwnt9ofQCkDEUcKT

- Push nothing. Delete nothing outside the worktree. Dispatch no subagents.

## Review Focus

1. **Someone sees who is on a record they may not read.** The roster for a record, the list markers and a subscription must each go through the read scope; a trashed record has no presence. Tests in Task 9 (controller and channel) and Task 11 (`trash_visibility_test.rb`).
2. **A person who left still shows as here.** A crashed tab or a dropped network sends no "leave": a row not refreshed for 60 seconds must be ignored by every read, whatever the sweep has done. Test in Task 9 (roster), with `backdate`.
3. **You see yourself, or one person twice.** Two tabs, two browsers, a reload that briefly overlaps the old subscription. Test in Task 9 (roster) and Task 10 (two sessions of the same user).
4. **The split of the live script loses typed text.** Every path that redraws a thread must still go through the one merge. The notes system tests are the net; Task 3 adds the merge's own tests so a path cannot bypass it unnoticed.
5. **A list redraws constantly, or costs a query per row.** Markers are loaded in one query for any number of rows (statement count pinned, Task 8 and 11) and a list re-fetches at most once every 5 seconds (Task 11).
