# Search 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The public site search finds close matches for a typo, offers one verified "Did you mean …?", finds Japanese, Chinese, Thai and Korean pages by the text they contain, suggests live titles and tags while a visitor types, shows a post's tags on its result, and refuses to run on a database without `pg_trgm` and a UTF-8 character type.

**Architecture:** The data and contract tasks come first (1–8): documents, the migration and its requirement checks, the vocabulary, the backend contract's additive members, the built-in's close and contains passes, `Result#tags`, the optional `suggest` and the `POST /search/suggestions` endpoint. None of them changes a template. Tasks 9–10 then draw what the Design System cards SiteSearchMatches and SiteSearchSuggest decided: the results' new lines, the token `--th-search-active` and the `search-suggest` combobox. Task 11 finishes the release notes and runs CI. It is one pull request, and no placeholder look ships (spec §12.x).

**Tech Stack:** Rails 8.1, Postgres 17 (`pg_trgm`, `tsvector`), Minitest with fixtures, Stimulus via import maps, Tailwind (`tailwindcss-rails`), Cuprite browser tests.

**Spec:** `docs/superpowers/specs/2026-11-15-search-2-design.md` (binding). Design: the Design System artifact `https://claude.ai/artifact/Pg9o6tAeyWk98YFsrMmXxT`, version `1794766530-8135`, cards SiteSearchSuggest, SiteSearchMatches and EditorSearchBlock.

## Global Constraints

- Postgres 15 or later; `plpgsql`; `pg_trgm`; encoding `UTF8` with a UTF-8 character type (not `C` or `POSIX`). These are checked at the migration, at a schema load and at a serving production boot, all with one message: "ContentSpiel requires the Postgres extension pg_trgm (docs/reference/hosting.md, "Database requirements"; the guide's "What ContentSpiel asks of its host")." preceded by what is missing and its cause in one line.
- The probe is `SELECT show_trgm('éé') <> '{}'`.
- `CLOSE_BELOW = 1`; similarity threshold 0.3 (`SET LOCAL pg_trgm.similarity_threshold = 0.3`); 3 candidates per word, up to 6 words, query words of 4 or more characters; `CLOSE_SHARE = 1` second.
- Vocabulary words: `/[\p{L}\p{M}\p{N}]+/` with an inner apostrophe, Ruby `downcase`, 4–32 characters, not digits alone, never from `code`, never a stopword of the language (`to_tsvector(config, word)` empty). The four `LIMITED` languages (`ja ko th zh`) get no vocabulary.
- Weights: `title` A, `tags` A (was B), `summary` B (a page's subtitle, meta title, meta description and slug; a post's excerpt and slug), `body` C, `code` D. `Documents::REVISION = 2`; `Postgres::REVISION = 1`, part of the built-in's fingerprint.
- Suggestions: `POST /search/suggestions`, JSON body `{"suggest", "language"}`, body capped at 1,024 bytes (413), no CSRF token, refused with 403 by `Sec-Fetch-Site` (present and not `same-origin`), then `Origin` (present and not `request.base_url`), then a `Content-Type` that is not `application/json`. Behind `Cookieless`, included first. `Cache-Control: private, no-store`, no ETag, `X-Robots-Tag: noindex`. Limits are 120 a minute per visitor and 3,000 across the site (`suggest_visitor`, `suggest_site`, scope `site_search_suggest`). `SUGGEST_TIMEOUT = 0.3` s in all, of which the backend gets 0.2 s. Prefixes under 2 or over 100 characters ask nothing. Up to 8 suggestions: 5 titles, then 3 tags, each kind filling the other's gap.
- `filter_parameters` gains `/\Asuggest\z/` by its whole name. No prefix reaches a log line, span, audit event, table, cache entry or error report.
- No new top-level name: everything new lives under `SiteSearch::` or `ContentSpiel::`. No Breaking change for gems: `suggest` is optional (`OPTIONAL_METHODS = %i[suggest]`), and `Hit#close`, `Results#correction` and `Query#close_matches` all have defaults.
- Words go under `public.blocks.search`: `close_matches`, `did_you_mean`, `tagged`, `matched_tag`, `suggestions` (plural), `no_suggestions`, `suggestions_limited`, `suggestions_unavailable`, `suggestions_loading`, `suggestions_label`, `kind_page`, `kind_post`, `kind_tag`. The exact English is in Task 9 and Task 10.
- Every test command is prefixed with `PGGSSENCMODE=disable`. Browser tests run one file at a time, after `bin/rails tailwindcss:build`, never while a build runs.
- Queries go Active Record first, then Arel through `SqlNodes`, then SQL with `# sql: <reason>`. Every write to `search_entries` or `search_words` carries `# version: none (…)`. A visitor's text, a candidate and a pattern are always binds (`SqlNodes.bound`).
- Comments state invariants, hazards and reasons, never plan steps or history. No compatibility code.

## Review Focus

1. **A malformed or oversized JSON body logged by Rails before the controller runs.** `ActionController::Instrumentation#process_action` reads `request.filtered_parameters` before any callback runs, and that parses the JSON body. A `JSON::ParserError` message quotes the body, so the prefix would reach the log. Expected: the 413 and the 400 are decided before Rails parses anything, and no log line holds the body. Task 8 owns this with the gate `ContentSpiel::SuggestGate` and the test "a malformed body is a 400 and its text is in no log line".
2. **A typed `%`, `_` or `\` in the contains pass or in `Tag.name_starting`.** Expected: each is a literal character. Tasks 5 and 7 test "a typed % finds a percent sign, not everything" and "a tag prefix of % or _ suggests no tag that lacks it".
3. **A query of only stopwords or digits with `close_matches` on.** Expected: no candidate, no correction, no error, and the span shows `search.close = "none"`. Task 5 tests "a query of stopwords and digits runs no candidate lookup and offers no correction".
4. **Back after choosing a suggestion.** Expected: Turbo's snapshot holds a closed, empty list and a plain field. Task 10 tests "Back after choosing a suggestion shows the field closed, with no list".
5. **The live region repeating itself.** Typing quickly must not queue several announcements. Expected: the region says only the latest answer's sentence, and says nothing while loading. Task 10 tests "the live region says only the answer that is drawn".

## Where the plan departs from the spec, and why

- **The suggestion's message row and an error state (card over spec §4.5).** The spec says the list stays closed when suggestions are unavailable. The SiteSearchSuggest card draws one quiet row in the list's frame for no suggestions, unavailable and limited. The look is the design agent's (spec §10), so the row is drawn. It stands outside `role="listbox"` (targets `popup` and `message`), and `aria-expanded` stays `"false"` while the list holds no option, so the ARIA pattern holds.
- **A post's date as a suggestion's `where` (card over spec §4.1).** The spec's `where` is a page's place. The card gives a post's row its date. `where` is plain text either way.
- **`suggestions_loading` and the `loading` target (card).** These are one key and one target beyond spec §8.2. The script holds no words of its own, so the template writes the word. For the same reason it also writes `data-search-suggest-unavailable-value`, the sentence for a network failure, when no answer arrives to carry one.
- **The tags line stands under the date, not the title (card).**
- **The live region (the card's words).** The card's prose says the region says "No suggestions", while its wording key is "No suggestions. Press Enter to search.". The plan reads the key: the region says the server's `status`, which is that key.
- **The tags preload (spec §12.x against the code).** `Publishing::Snapshot.rebuild` already sets a post view's `tags` from its copy with no statement. The plan therefore pins the count with the extended statement-count test, and adds the one preload only if that test shows a statement per post.
- **`ContentSpiel::SuggestGate` (a gap in spec §4.1).** Rails parses a JSON body for the instrumentation's "Parameters:" line before any callback runs, and a `JSON::ParserError` message quotes the body. So the 413 and the malformed-body decision are made in a Rack middleware before Rails parses anything. It is under `ContentSpiel::`, which adds no top-level name.
- **The backend's suggest limit.** The spec's comment gives `SuggestQuery`'s limit as 5. ContentSpiel asks for 8, because "when one kind has fewer, the other fills up to 8" (§4.3) needs up to 8 titles when there are no tags.
- **The routing test file.** The spec names `test/integration/public_routing_test.rb`, which does not exist. The page tree's routing tests are in `test/integration/pages_routing_test.rb`.
