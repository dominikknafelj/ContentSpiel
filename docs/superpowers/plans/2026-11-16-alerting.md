# Alerting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Errors and chosen security events reach the site's owners (a digest mail, System status, a log line, a span event); CS Studio's throttle trips are audited; `/ready` checks the databases.

**Architecture:** An `alerts` table written only by jobs. `Rails.error` reports reach `Alerts::ErrorSubscriber`, which logs, adds a span event and queues `Alerts::RecordErrorJob`. A recurring `Alerts::CheckJob` (every minute) scans chosen columns of `audit_events` into security alerts, mails due alerts to owners as one digest, and prunes. Rails' `rate_limit.action_controller` notification is audited as `request.limited` for non-public doors. `GET /ready` answers 200/503 from a primary and queue database probe.

**Tech Stack:** Rails 8.1, Postgres, Solid Queue, Solid Cache, Minitest + fixtures, ViewComponent, Action Mailer.

**Spec:** `docs/superpowers/specs/2026-11-16-alerting-design.md` (binding; read it whole before any task). Its section 9 fixes the names: `Alerts::Alert`, `Alerts::DigestMailer`, `Audit::RequestLimits`, `ReadinessController`.

## Review Focus

1. The database is down: the error subscriber, `RecordErrorJob` and `CheckJob` must not chain reports or raise from the subscriber; `/ready` answers 503, never 500. (Task 2, Task 6 tests.)
2. An exception whose message holds a secret-looking string (`"password=hunter2"`) must not appear in the log line, the row, the mail or the page. (Task 2, Task 5, Task 7 tests.)
3. Mail not set up, or no site address for the link: alerts stay unmailed and are not marked; nothing raises; System status says so. (Task 5, Task 7.)
4. A scan run twice in one minute, or late: no duplicate per-event alert, no second digest within ten minutes. (Task 4, Task 5.)
5. A limit on a public door (search, forms, suggestions) records nothing in the audit log. (Task 3.)
