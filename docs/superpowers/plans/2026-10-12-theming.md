# Theming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A site keeps a theme folder in its own repository, sets `THEME_PATH`, and is drawn by it (templates, head, stylesheet, images, fonts, scripts), with the default theme behind everything the folder does not hold and a written contract of the names a theme may rely on.

**Architecture:** `ThemeFolder` (`lib/`, plain Ruby) reads `THEME_PATH`, checks the folder's shape and fingerprints it; `Theme` (`app/values/theme.rb`) is the runtime side, built in `to_prepare` and swapped in a test with `Theme.with`. Four seams, each one place: page templates through the view path of the two public controllers; block and post templates through `Theme#component_for`, which answers a generated subclass that carries the theme's template; one stylesheet built from an entry file that imports the default theme and then the theme; scripts pinned under `controllers/theme/` and loaded by a `site` entry point the public layout alone uses. `Theme::Contract` is the one list of tokens, templates, components and helpers that the boot check, `theme:check`, `theme:new`, the tests and the reference file all read.

**Tech Stack:** Rails 8.1, ViewComponent 4.15.0, Propshaft, importmap-rails, tailwindcss-rails 4 (`Tailwindcss::Ruby.executable`), Nokogiri (HTML5), closure_tree, Minitest + fixtures, Capybara/Cuprite.

**Spec:** `docs/superpowers/specs/2026-10-12-theming-design.md` (decisions 1 to 18; read all of it before Task 1).

## Review Focus

Seven conditions the spec implies and a person will meet. Each names the test that pins it; the test's code is in the task named.

1. **A stray file in the folder.** `.DS_Store` anywhere and a `README.md` at the top are ignored; an editor's backup (`show.html.erb~`) or a misspelt template (`pages/shwo.html.erb`) stops the boot and the message names the file (Task 3: `"dot files anywhere and a README at the top are not the theme's files"`; Task 4: `"a file the contract does not name is refused by name: a misspelt template, a backup file, a layout"`).
2. **`THEME_PATH` typed loosely.** A relative path, a trailing slash, a path to a file, a path that does not exist, and a value of spaces only (Task 3: `"a relative path and a trailing slash name the same folder"`, `"a path that is a file or does not exist is refused, and the message names the variable and the path"`, `"blank is the default theme"`).
3. **A theme's template that raises.** It is an error whose message names the theme's file, never the default template drawn in its place (Task 2: `"a theme's page template that raises is an error that names the theme's file, not a fallback"`; Task 1: `"a theme's block template that raises names the theme's file"`).
4. **An empty or half theme.** A folder with no file at all, and one with a stylesheet and no template, draw the site exactly as the default theme does (Task 3: `"an empty folder is a theme with no templates"`; Task 4: `"an empty theme draws the homepage as the default theme does"`).
5. **Headings a slug cannot be made from.** Two headings with the same words, an empty heading, a heading in a script `parameterize` empties, and a heading with markup in it each get a unique, non-empty id (Task 6: `"two headings alike, an empty one, one in another script and one with markup each get an id of their own"`).
6. **A title pattern that prints more than a line.** A `_title` partial with line breaks or indentation yields one line of text in `<title>`, and a site title with an apostrophe is escaped once (Task 2: `"the title is the theme's pattern on one line, escaped once"`).
7. **A page with no address in the language shown.** It is left out of the tree with everything under it, and previous/next walk past it (Task 6: `"a page with no address in this language is left out with its branch"`).

### Task 1: The proof — a block's template replaced through `Theme#component_for`

This is the risk the spec names (§3, "Risks"): ViewComponent finds a template beside its class and never asks the view path. The task proves, against ViewComponent 4.15.0 as locked in `Gemfile.lock`, that a generated subclass can carry a theme's template while the CMS's class keeps its own, in one process.

**What the gem does, read from its source** (`bundle info view_component --path`, then `lib/view_component/base.rb:588` `sidecar_files`, `:643` `inherited`; `lib/view_component/compiler.rb:170` `gather_templates`; `lib/view_component/template.rb` `safe_method_name`):

- `Compiler#gather_templates` asks the component class `sidecar_files(extensions)` for its template files. A class that answers the theme's file is compiled from it, into methods defined on that class.
- `Template#safe_method_name` calls `@component.name.underscore`: an anonymous class (`Class.new(component)`) has no name, so the subclass must answer its parent's.
- `inherited` sets `child.virtual_path = child.name&.underscore`, nil for an anonymous class, so the subclass takes its parent's.
- A subclass also gets an `InlineCall` template for the parent's compiled `call`; with the theme's file compiled first into the subclass's own `call`, both resolve to the theme's method.

**What "it does not work" looks like**, any one of: `NoMethodError: undefined method 'underscore' for nil` at the first render; `ViewComponent::TemplateError` ("More than one HTML template found", "Template file and inline render method found"); the default template's markup under the theme (the parent's `call` won); or the theme's markup under the default theme after the subclass was rendered (the template leaked into the CMS's class). The test below fails for each.

**The fallback**, if Step 4 cannot be made to pass in an hour's reading of the gem: the spike's override, kept behind the same two methods so no later task changes. `Theme#component_for` answers the definition's own class; `ApplicationComponent` gains `def self.sidecar_files(extensions) = (template = Theme.current.template_for(self)) && extensions.map(&:to_s).include?("erb") ? [ template.to_s ] : super`; and `Theme.with` makes the swap real for the tests by dropping the compiled templates of every component the entering and the leaving theme replace (`ViewComponent::CompileCache.invalidate_class!(component)` and `component.instance_variable_set(:@__vc_compiler, nil)` for each, on the way in and on the way out). The price is the one the spec names in decision 9: the theme's template is compiled into the CMS's class, so a process serves one theme, and the test's last assertion ("the component's own class keeps its own template") is rewritten to say so. Record which way was taken in the task's report; Task 8 writes it into "As built".

```ruby
require "tmpdir"
require "fileutils"

# The second theme (`test/fixtures/themes/plain`) for the length of a block.
# The test environment ignores THEME_PATH, so this is the one way a test is
# drawn by a theme: `Theme.current` is swapped in this process and put back,
# also when the block raises. A system test's server runs in this process
# too, so the swap reaches it.
module ThemeTestHelper
  PLAIN = Rails.root.join("test/fixtures/themes/plain")

  def plain_theme = Theme.new(path: PLAIN)

  def with_plain_theme(&block) = Theme.with(plain_theme, &block)

  # A copy of the second theme in a directory of its own, for a test that
  # adds, changes or removes a file. Yields the directory as a Pathname.
  def with_theme_copy
    Dir.mktmpdir("theme") do |dir|
      FileUtils.cp_r("#{PLAIN}/.", dir)
      yield Pathname(dir)
    end
  end
end
```

Replace `app/values/theme.rb` with:

```ruby
# The theme that draws the public site (theming spec §1 and §3). `Theme.current`
# is built from the folder `THEME_PATH` names when the application is prepared
# (`config/initializers/theme.rb`), as every registry is, and a test swaps it
# for the length of a block (`Theme.with`, `test/support/theme_test_helper.rb`).
# Without a folder it is the default theme: every question below is answered
# with the CMS's own.
#
# THE ONE PLACE THAT KNOWS HOW A COMPONENT'S TEMPLATE IS REPLACED.
# ViewComponent finds a template beside its class file and never asks the
# view path, so a theme's `components/blocks/image_component.html.erb` is not
# found by putting the folder on a path. `component_for` is already where the
# public site gets a block's, a post list's and a post's component from
# (`ThemeHelper#render_block`, `Blocks::PostListComponent#list_component`).
# For a component whose template the folder holds it answers a subclass
# generated here, once per theme: `Class.new(component)` whose
# `sidecar_files` answers the theme's file. The template is therefore
# compiled into a class of the theme's own and calls everything the default
# template calls (the private readers included, as any subclass may), and
# the CMS's class keeps its own template, so one process can hold two themes
# and a test can draw both.
#
# Three things the subclass has to say because it is anonymous, each read
# from view_component 4.15.0:
# - `name`: `ViewComponent::Template#safe_method_name` calls
#   `@component.name.underscore`, and an anonymous class has no name;
# - `virtual_path`: `ViewComponent::Base.inherited` derives it from the name
#   at a moment the class has none yet;
# - `identifier`: `inherited` takes it from the call stack, which is this
#   file; with the component's own, every question but the template's
#   (`sidecar_files` for a translation file) is answered as the component's.
#
# The rejected way is the spike's: an override of
# `ApplicationComponent.sidecar_files`, which compiles the theme's template
# into the CMS's own class, so a process holds one theme and no test draws
# two. `test/values/theme_test.rb` is the proof that this way works, and it
# fails on the day an upgrade of the gem changes `sidecar_files`.
#
# The subclasses live as long as their Theme does. A code reload in
# development builds a new Theme (`to_prepare`), and with it new subclasses
# of the freshly loaded components.
class Theme
  DEFAULT_FINGERPRINT = "default".freeze

  class << self
    attr_writer :current

    def current = @current ||= new

    # `theme` for the length of the block, and the theme that was current
    # before afterwards, also when the block raises.
    def with(theme)
      before = @current
      @current = theme
      yield
    ensure
      @current = before
    end
  end

  attr_reader :path, :fingerprint

  def initialize(path: nil, fingerprint: DEFAULT_FINGERPRINT)
    @path = path && Pathname(path)
    @fingerprint = fingerprint
    @components = Concurrent::Map.new
  end

  def configured? = !path.nil?

  # The folder's base name, for a log line and System status.
  def name = path ? path.basename.to_s : "default"

  # Where the theme's page and layout templates are, looked up before
  # app/views by the two public controllers (`PublicPageRendering`).
  def views_path = path&.join("views")

  # The component that draws `definition` in `role` (`:component` for a
  # block, `:list_component` and `:detail_component` for a content type):
  # the theme's class when the folder holds that component's template, the
  # definition's own otherwise.
  def component_for(definition, role = :component)
    component = definition.public_send(role)
    return component if component.nil?

    @components.compute_if_absent(component) do
      template = template_for(component)
      template ? subclass_with(component, template) : component
    end
  end

  # The theme's own template for a component class, by the component's path:
  # `Blocks::ImageComponent` is `components/blocks/image_component.html.erb`.
  # nil when the folder holds none, and without a folder.
  def template_for(component)
    return nil unless path && component.name

    file = path.join("components", "#{component.name.underscore}.html.erb")
    file.file? ? file : nil
  end

  private

  def subclass_with(component, template)
    Class.new(component) do
      define_singleton_method(:name) { component.name }
      define_singleton_method(:sidecar_files) do |extensions|
        extensions.map(&:to_s).include?("erb") ? [ template.to_s ] : super(extensions)
      end
      self.identifier = component.identifier
      self.virtual_path = component.virtual_path
```

In `app/helpers/pages_helper.rb` replace `document_title` (and its comment) with:

```ruby
  # The text of <title>. An explicit meta title is taken as written: it is
  # what an editor typed for search results, and no pattern is put around it.
  # Everything else is the THEME'S PATTERN (`layouts/public/_title`, theming
  # spec §2): the page's or the post's own title and the site's, where the
  # homepage has no title of its own to put beside the site's. The site
  # title is translated (translation helpers spec §5) and read in the
  # request's language with the usual fallback, like the page's own.
  def document_title(page, post: nil)
    meta_title = translated(page, :meta_title)
    return meta_title if post.nil? && meta_title.present?

    page_title = seo_title(page, post: post) unless post.nil? && page.root?
    themed_title(page_title: page_title, site_title: Locales.read(Current.site, :title))
  end

  # The theme's title pattern, as one line of text. The partial is a
  # template, so what it prints carries the line breaks and the indentation
  # it was written with: they are squeezed here, and a theme's author never
  # has to write the pattern on one line to get a clean <title>.
  #
  # `html_safe` is right here and nowhere near: the partial's output is
  # already escaped by ERB (a site title with an apostrophe arrives as
  # `&#39;`), `squish` only removes white space and hands back a plain
  # String, and escaping that again would print `&amp;#39;`.
  def themed_title(page_title:, site_title:)
    render("layouts/public/title", page_title: page_title, site_title: site_title).to_str.squish.html_safe
  end
```

- [ ] **Step 3: Implement `ThemeFolder`**

`lib/theme_folder.rb`:

```ruby
require "pathname"
require "digest"

# The site's theme folder, read once from `THEME_PATH` (theming spec §1).
# Everything that must agree about "which theme draws this site" (the view
# path, the component templates, the stylesheet's build, the asset path, the
# import map, the ETag, the boot line, System status) starts here instead of
# reading the variable itself.
#
# `config/application.rb` requires this file itself although `lib/` is
# autoloaded, as it does `site_address`: the boot's own initializer and
# `config/importmap.rb` read it before any application class is loaded. It
# uses nothing of Rails and nothing of Active Support.
#
# A blank value is "the default theme", never an error. A value that is
# there but names no directory, or a folder with something at its top that
# is not part of a theme, raises `Invalid` at once, so a typo stops the boot
# instead of quietly drawing the site with the default theme. Unlike
# `SiteAddress`, the message repeats the value: it is a path, and the path is
# what the person has to go and look at.
#
# TWO CHECKS, IN TWO PLACES. This file checks what plain Ruby can: the
# directory and its top-level entries. Whether every file under `views` and
# `components` is one the contract names, and whether an asset is named like
# one of the CMS's own, is `Theme::Check`'s, run by `Theme.load` when the
# application is prepared (`config/initializers/theme.rb`), because the
# contract is application code. Both stop the boot.
#
# THE TEST ENVIRONMENT IGNORES THE VARIABLE, so a developer's shell never
# changes a test run; a test hands a folder in (`ThemeFolder.new(path)`,
# `test/support/theme_test_helper.rb`).
#
# Nothing here is memoised but `current` itself: `files` and `fingerprint`
# read the folder each time they are asked, so a reload in development sees
# the folder as it is now. `Theme` keeps the fingerprint it was loaded with.
class ThemeFolder
  class Invalid < ArgumentError; end

  VARIABLE = "THEME_PATH".freeze

  # What a theme folder holds at its top, and nothing else. No `lib`, no
  # `config`, no `.rb` file anywhere: a theme holds no Ruby (decision 8).
  ENTRIES = %w[views components assets javascript].freeze

  DEFAULT_FINGERPRINT = "default".freeze

  attr_reader :path

  def self.current = @current ||= from_env(ENV)

  def self.reset!
    @current = nil
  end

  # `base` is what a relative value is relative to: the directory the
  # process was started in.
  def self.from_env(env, base: Dir.pwd)
    value = env[VARIABLE].to_s.strip
    return new(nil) if value.empty? || env["RAILS_ENV"] == "test"

    new(File.expand_path(value, base))
  end

  def self.announcement(folder)
    if folder.configured?
      "[ContentSpiel] Theme: #{folder.path} (#{folder.templates.size} templates, fingerprint #{folder.fingerprint[0, 8]})"
    else
      "[ContentSpiel] Theme: the default theme (#{VARIABLE} is not set)"
    end
  end

  def initialize(path)
    @path = path && Pathname.new(File.expand_path(path.to_s))
    check_shape! if @path
  end

  def configured? = !path.nil?

  def name = configured? ? path.basename.to_s : "default"

  # Every file of the theme, as a path relative to the folder, sorted. A dot
  # file or anything under a dot directory (`.DS_Store`, `.git/`, `.keep`)
  # and a README at the top are not the theme's: an operating system or an
  # editor puts the first there, and a person the second.
  def files
    return [] unless configured?

    Dir.glob("**/*", File::FNM_DOTMATCH, base: path.to_s).sort.select do |relative|
      !ignored?(relative) && File.file?(path.join(relative))
    end
  end

  # The templates a theme brings: for the boot line's count and for
  # `theme:check`, which compiles each.
  def templates = files.select { |file| file.end_with?(".erb") && file.start_with?("views/", "components/") }

  # SHA-256 over the relative path and the content of every file, in order.
  # Each path and each content is closed with a NUL, so bytes cannot move
  # from the end of one file into the name of the next and leave the digest
  # as it was. It is part of the public ETag (`PagesController`), so a
  # changed theme is never answered 304, and it is what the stylesheet's
  # build stamps its output with.
  def fingerprint
    return DEFAULT_FINGERPRINT unless configured?

    digest = Digest::SHA256.new
    files.each do |relative|
      digest << relative << "\0" << File.binread(path.join(relative)) << "\0"
    end
    digest.hexdigest
  end

  # The theme's one stylesheet, imported after the default theme's by the
  # build (`ThemeCss`), or nil: a theme of templates alone has none.
  def stylesheet = existing_file("assets/stylesheets/theme.css")

  # Where the theme's Stimulus controllers are, pinned under
  # `controllers/theme/` (`config/importmap.rb`), or nil.
  def controllers_path = existing_directory("javascript/controllers")

  # The folders that go on the asset load path: images and fonts, named in
  # the stylesheet and the templates by file name, and `javascript`, from
  # which a controller is served as `controllers/<name>_controller.js`.
  def asset_paths = %w[assets/images assets/fonts javascript].filter_map { |folder| existing_directory(folder) }

  private

  def existing_file(relative)
    return nil unless configured?

    file = path.join(relative)
    file.file? ? file : nil
  end

  def existing_directory(relative)
    return nil unless configured?

    directory = path.join(relative)
    directory.directory? ? directory : nil
  end

  def ignored?(relative)
    relative.split("/").any? { |segment| segment.start_with?(".") } || relative.match?(/\AREADME(\.[^\/]*)?\z/i)
  end

  def check_shape!
    raise Invalid, "#{VARIABLE} names no directory: #{path}" unless path.directory?

    Dir.children(path.to_s).sort.each do |entry|
      next if ignored?(entry)
      next if ENTRIES.include?(entry) && path.join(entry).directory?

      raise Invalid, "#{VARIABLE}: #{path.join(entry)} is not part of a theme. A theme folder holds the folders " \
                     "views, components, assets and javascript, and nothing else (dot files and a README are ignored)."
    end
  end
end
```

```ruby
class Theme
  # THE THEME CONTRACT (theming spec §7): the names a theme outside this
  # repository may rely on. Everything on these lists is stable: the CMS says
  # in its release notes when one changes. Everything that is not may change
  # freely, and a theme that uses it is on its own.
  #
  # One list, read by all of: the check when the application starts
  # (`Theme::Check`), `bin/rails theme:check`, `bin/rails theme:new`
  # (`Theme::Scaffold`), the tests (`test/values/theme/contract_test.rb`) and
  # the reference file (`docs/reference/theming.md`, which a test holds to
  # this file).
  #
  # ADDING A BLOCK TYPE (decision 18) is one entry here per thing it brings:
  # its component's line in COMPONENTS, which makes its template replaceable
  # and `theme:new` copy it, and its tokens' lines in THEMED_TOKENS or
  # FIXED_TOKENS. Nothing else in the mechanism names a block.
  #
  # The lists are data and name no class: a component is written as its path
  # (`blocks/image_component`), which is also where a theme puts its
  # template, so this value knows no component
  # (`test/lib/dependency_direction_test.rb`).
  module Contract
    # Tokens with a value for the light scheme and one for the dark
    # (`app/assets/tailwind/themes/default/tokens.css`, the first two
    # blocks), without the `--th-` prefix. A theme changes one by declaring
    # it again in its own stylesheet, under the same selectors.
    THEMED_TOKENS = %w[
      paper surface sunken ink dim meta line line-strong
      accent accent-hover accent-tint on-accent
      ok ok-ink ok-tint warn warn-ink warn-tint danger danger-ink danger-tint
      shadow-menu
      band-tinted band-strong on-band-strong on-band-strong-dim on-band-strong-accent
    ].freeze

    # Tokens with one value (the last block): type, tracking, spacing, shape.
    FIXED_TOKENS = %w[
      font mono
      t-display t-h1 t-h2 t-h3 t-body t-small t-label
      track-mono track-wide
      sp-1 sp-2 sp-3 sp-4 sp-5 sp-6 sp-7
      radius radius-pill ease
    ].freeze

    TOKENS = (THEMED_TOKENS + FIXED_TOKENS).map { |name| "--th-#{name}" }.freeze

    # The CMS's own under the same prefix, and not a theme's to rely on: the
    # preview bar's two colours and the image placeholder's two.
    OWN_TOKENS = /\A--th-(?:preview|ph)-/

    # The templates a theme may replace through its `views/` folder, by
    # their path under it, with what each is. The default is the file of the
    # same path under app/views.
    TEMPLATES = {
      "layouts/public/_frame.html.erb" => "everything inside <body> but the preview bar; `yield` is the page",
      "layouts/public/_title.html.erb" => "the pattern of the page title; locals `page_title` (nil on the homepage and a 404) and `site_title`",
      "layouts/public/_icons.html.erb" => "the favicon and the touch icon links",
      "layouts/public/_head.html.erb" => "the theme's own head tags, after the CMS's and before the stylesheet",
      "layouts/public/_header.html.erb" => "the site's header: its title, logo and menu",
      "layouts/public/_footer.html.erb" => "the site's footer: the copyright line, the social links, the light/dark switch",
      "layouts/public/_language_switcher.html.erb" => "the links to the shown page in the other languages",
      "layouts/public/_theme_toggle.html.erb" => "the light/dark switch; its script is the CMS's `theme` controller",
      "pages/show.html.erb" => "a page: its heading, hero and blocks, and the list of its subpages",
      "pages/not_found.html.erb" => "the page for an address that is nobody's"
    }.freeze

    # A theme's own partials, under any name: `views/theme/_anything.html.erb`,
    # rendered as `render "theme/anything"`.
    OWN_PARTIALS = "theme/".freeze

    # The components whose template a theme may replace through its
    # `components/` folder, by the component's path, with the methods its
    # template may call. A method not listed is the CMS's to change.
    COMPONENTS = {
      "blocks/rich_text_component" => %w[block page],
      "blocks/image_component" => %w[block page asset alt caption sizes],

    COMPONENT_HELPERS = %w[translated rich_text post_date resume_period post_url_path page_url_path render_block helpers].freeze

    # What a page or layout template may call. `public_urls.preview?` is the
```

`app/values/theme/check.rb`:

```ruby
class Theme
  # What is wrong with a theme folder, as sentences (theming spec §8). An
  # empty answer is a sound folder.
  #
  # STRICT ON PURPOSE (decision 14). A file under `views` or `components`
  # that the contract does not name is a problem, not something to ignore:
  # a misspelt `pages/shwo.html.erb` would otherwise silently never be used,
  # and a theme that holds `layouts/application.html.erb` would replace the
  # CMS's head (the view path finds whatever is there). So the list of what
  # a theme MAY hold is `Theme::Contract`, and everything else stops the boot.
  #
  # Two depths. The plain check is what `Theme.load` runs when the
  # application starts: it reads names only, so it costs a directory
  # listing. `deep: true` is `bin/rails theme:check`'s and a site's image
  # build's: it also compiles every template (a syntax error is found at the
  # build and not by a visitor) and reads each for the four names the public
  # ETag cannot see (spec §6).
  module Check
    # A public page is one cookie-less answer for every visitor, and its ETag
    # is made of the record, the content version, the settings, the revision
    # and the theme. A template that reads one of these draws a page that
    # differs by something none of them covers.
    FORBIDDEN = %w[params request cookies session].freeze

    # Where the CMS's own assets are, each a root of Propshaft's load path:
    # a file of the theme's that would be served under the same name as one
    # of these shadows it or is shadowed by it, by an order nobody chose.
    CMS_ASSET_ROOTS = %w[app/assets/images app/assets/fonts app/assets/builds app/javascript vendor/javascript].freeze

    # The theme's folders that go on the load path (`ThemeFolder#asset_paths`).
    THEME_ASSET_ROOTS = %w[assets/images assets/fonts javascript].freeze

    module_function

    def problems(folder, deep: false, root: Rails.root)
      return [] unless folder.configured?

      files = folder.files
      found = files.filter_map { |file| misplaced(file) }
      found += shadowing(files, Pathname(root))
      found += folder.templates.flat_map { |file| unsound(folder, file) } if deep
      found
    end

    def misplaced(file)
      area, rest = file.split("/", 2)
      allowed =
        case area
        when "views" then Contract::TEMPLATES.key?(rest) || (rest.start_with?(Contract::OWN_PARTIALS) && rest.end_with?(".html.erb"))
        when "components" then rest.end_with?(".html.erb") && Contract::COMPONENTS.key?(rest.delete_suffix(".html.erb"))
        when "assets" then rest == "stylesheets/theme.css" || rest.start_with?("images/", "fonts/")
        when "javascript" then rest.start_with?("controllers/") && rest.end_with?("_controller.js")
        end
      "#{file} is not part of the theme contract (#{MAY_HOLD.fetch(area)})" unless allowed
    end

    MAY_HOLD = {
      "views" => "views holds the templates Theme::Contract::TEMPLATES names and the theme's own partials under views/theme/",
      "components" => "components holds <component path>.html.erb for the components Theme::Contract::COMPONENTS names",
      "assets" => "assets holds stylesheets/theme.css, images/ and fonts/",
      "javascript" => "javascript holds controllers/**/*_controller.js"
    }.freeze

    # The name a file of the theme is served under: its path below the
    # folder that goes on the load path.
    def served_as(file)
      asset_root = THEME_ASSET_ROOTS.find { |candidate| file.start_with?("#{candidate}/") }
      asset_root && [ file.delete_prefix("#{asset_root}/"), file ]
    end

    def shadowing(files, root)
      served = files.filter_map { |file| served_as(file) }
      among_themselves = served.group_by(&:first).values.select { |group| group.size > 1 }.map do |group|
        "#{group.map(&:last).sort.join(" and ")} would be served under one name (#{group.first.first})"
      end
      against_the_cms = served.filter_map do |name, file|
        taken = CMS_ASSET_ROOTS.find { |cms_root| root.join(cms_root, name).file? }
        "#{file} is named like an asset of the CMS's own (#{taken}/#{name}): a theme adds assets, it does not replace one" if taken
      end
      among_themselves + against_the_cms
    end

    def unsound(folder, file)
      source = folder.path.join(file).read
      found = []
      begin
        RubyVM::InstructionSequence.compile(ActionView::Template::Handlers::ERB::Erubi.new(source).src, file)
      rescue SyntaxError => error
        found << "#{file} does not compile: #{error.message.lines.first.to_s.strip}"
      end
      code = source.scan(/<%(?!#)(.*?)%>/m).flatten.join("\n")
      FORBIDDEN.each do |name|
        next unless code.match?(/(?<![.\w@:])#{name}\b(?!\s*:(?!:))/)

        found << "#{file} reads #{name}: a public page is one answer for every visitor, and its ETag does not know what a template reads there"
      end
      found
    end
  end
end
```

```ruby
require "pathname"
require "fileutils"

# The public stylesheet's build (theming spec §4). ONE stylesheet, built from
# an entry file this module writes:
#
#   @import "<default theme>/theme.css";              tokens, base, prose, sections, the default templates' utilities
#   @import "<theme>/assets/stylesheets/theme.css";   the theme's own styles
#   @source "<theme>/views";                          so utilities in the theme's templates are built
#   @source "<theme>/components";
#
# Without a theme only the first line is there, which is the build the CMS
# always had. What follows from the order:
# - a theme changes a token by declaring it again, and copies nothing;
# - a template the theme does not replace is still styled, because the
#   default theme's styles are always in the build. That is what makes the
#   fallback real, and why the preview bar keeps its look under any theme;
# - a theme may write plain CSS or Tailwind utilities, through the same
#   executable.
# Both imports come before the `@source` lines: an `@import` after another
# rule is not an import.
#
# Paths are written relative to the entry file, so the entry reads the same
# on a laptop and in an image.
#
# WHEN: at image build, never at boot. `assets:precompile` runs
# `tailwindcss:build`, which runs `theme_css:build` (lib/tasks/theme_css.rake),
# with THEME_PATH set by the site's Dockerfile. The build stamps its output
# with the theme's fingerprint (`ThemeFolder::STAMP`), and production does
# not start when the stamp is another theme's (config/application.rb).
module ThemeCss
  DEFAULT = "app/assets/tailwind/themes/default/theme.css".freeze
  ENTRY = "tmp/theme/entry.css".freeze
  OUTPUT = "app/assets/builds/theme.css".freeze

  module_function

  def entry(folder, root:)
    from = Pathname(root).join(ENTRY).dirname
    relative = ->(path) { Pathname(path).relative_path_from(from).to_s }

    lines = [ %(@import "#{relative.(Pathname(root).join(DEFAULT))}";) ]
    if folder.configured?
      lines << %(@import "#{relative.(folder.stylesheet)}";) if folder.stylesheet
      %w[views components].each do |name|
        directory = folder.path.join(name)
        lines << %(@source "#{relative.(directory)}";) if directory.directory?
      end
    end
    lines.join("\n") + "\n"
  end

  def write_entry(folder, root:)
    path = Pathname(root).join(ENTRY)
    FileUtils.mkdir_p(path.dirname)
    path.write(entry(folder, root: root))
    path
  end

  def command(root:, executable:)
    [ executable, "-i", File.join(root.to_s, ENTRY), "-o", File.join(root.to_s, OUTPUT), "--minify" ]
  end

  def stamp!(folder, root:)
    path = Pathname(root).join(ThemeFolder::STAMP)
    FileUtils.mkdir_p(path.dirname)
    path.write("#{folder.fingerprint}\n")
  end
end
```

```ruby
module PublicSite
  # A branch of the page tree as a public template may draw it (theming spec
  # §7): a sidebar, a section's index, the crumbs above a page, previous and
  # next. It answers data and knows no helper, no view and no theme
  # (`ThemeHelper#page_tree` and its neighbours are the ones a template
  # calls).
  #
  # WHAT THE PUBLIC SEES, AND NOTHING ELSE. Which pages are in a branch and
  # in what order is the rows' to say (the tree is not in a copy): kept and
  # published pages only, the rule of every public listing, and a page with
  # no address in the language shown is left out with everything under it,
  # because there is nowhere to link it. But a TITLE is content, and content
  # of a published page comes from its copy (`Publishing.published_all`),
  # never from its rows: the spike this replaces read the rows, and a
  # sidebar would have shown a title nobody had published. In a preview the
  # rows are what is shown, as for every other reader
  # (`ThemeHelper#published_views`). `test/integration/public_canary_test.rb`
  # asks the site under a theme that draws all of this.
  #
  # THREE STATEMENTS whatever the branch's size: its pages, their stored
  # addresses (`PublicSite::Paths.current_paths`, one of the reads the entry
  # guard allows), their copies. The pages above a page are two more.
  # `test/queries/public_site/branch_test.rb` counts them at 4 pages and
  # at 30.
  class Branch
    # One page of a branch. `current` is the page being shown; `open` is a
    # page the shown one is somewhere below. `path` already carries the
    # language's prefix (and the preview's).
    Node = Data.define(:id, :title, :path, :children, :current, :open) do
      def current? = current

      def open? = open

      def leaf? = children.empty?

      # The branch flattened in reading order: a page, then its subpages,
      # each followed by its own.
      def reading_order = [ self ] + children.flat_map(&:reading_order)
    end

    def initialize(urls:, locale: I18n.locale)
      @urls = urls
      @locale = locale.to_s
    end

    # The branch under and including `top`, to any depth, or nil when `top`
    # itself is not shown (trashed, not published, no address in this
    # language). `current` is the page being shown, if it is in the branch.
    def under(top, current: nil)
      pages = top.self_and_descendants.kept.published.to_a # public: rows (which pages are in a branch, and their order, is the tree's; titles are read from the copies below)
      by_id = pages.index_by(&:id)
      return nil unless by_id.key?(top.id)

      build(by_id.fetch(top.id),
        by_parent: pages.group_by(&:parent_id),
        paths: Paths.current_paths("Page", by_id.keys),
        shown: as_shown(pages).index_by(&:id),
        current_id: current&.id,
        open_ids: ids_above(current, by_id))
    end

    # The pages above `page`, the homepage first, each as the public sees
    # it. Empty for the homepage.
    def above(page)
      as_shown(page.ancestors.kept.published.to_a.reverse) # public: rows (which pages are above is the tree's; as_shown hands back the copies)
    end

    private

    def as_shown(pages) = @urls.preview? ? pages : Publishing.published_all(pages)

    # The ids of the pages of the branch that `current` is below, walked in
    # memory: no statement.
    def ids_above(current, by_id)
      ids = []
      parent_id = current && by_id[current.id]&.parent_id
      while (page = by_id[parent_id])
        ids << page.id
        parent_id = page.parent_id
      end
      ids
    end

    def build(page, context)
      path = context[:paths].dig(page.id, @locale) or return nil

      children = context[:by_parent].fetch(page.id, []).sort_by { |child| [ child.position.to_i, child.id ] }
        .filter_map { |child| build(child, context) }
      Node.new(id: page.id, title: Locales.read(context[:shown].fetch(page.id), :title, locale: @locale),
        path: "#{@urls.prefix(@locale)}#{path}", children: children,
        current: page.id == context[:current_id], open: context[:open_ids].include?(page.id))
    end
  end
end
```

```ruby
  # and published, and every title comes from the page's copy
  # (`PublicSite::Branch`). Each is read once per render, however often a
  # template asks.

  # the homepage.

  # The branch under and including `top`, to any depth, as nested nodes:
  # `title`, `path`, `children`, `current?` (the shown page), `open?` (the
  # shown page is somewhere below), `leaf?`. nil when `top` is not shown.

    key = [ top.id, current&.id ]
    @page_trees.fetch(key) { @page_trees[key] = page_branch.under(top, current: current) }

  # followed by its own.

  # `skip` is a callable that says which pages the walk passes over (a theme
  # hands in "the pages that only group others", so next after the last page
  # of a group is the first page of the next); the shown page is never
  # skipped.

    walk = pages_in_reading_order(tree).reject { |node| !node.current? && skip&.call(node) }
    index = walk.index(&:current?) or return [ nil, nil ]

    [ (walk[index - 1] if index.positive?), walk[index + 1] ]
  end

  # The rendered blocks of a page with an id on each heading of `levels`,
  # and those headings as `id`, `text`, `level`: what a table of contents
  # and a link to a heading need.
  #
  # Made on the RENDERED page, from each heading's words, not stored in the
  # document (decision 17): an id must be unique on the whole page, and a
  # page's text is several blocks, each rendered and cached alone. So an id
  # follows its heading's words: REWORDING A HEADING CHANGES ITS ID, and a
  # link to it from elsewhere then opens the page at its top. A number is
  # added when two are alike, and a heading with no words a slug can be made
  # from (an empty one, one in a script `parameterize` empties) is "section".

  # article for a request that is not a 304, paid only by a template that
  # calls this.

        number = 1
        candidate = "#{base}-#{number += 1}" while taken.include?(candidate)
        taken << candidate
        node["id"] = candidate
      end
      Heading.new(id: id, text: node.text.squish, level: node.name.delete_prefix("h").to_i)
    end

  end
```

```ruby
class Theme
  # `bin/rails 'theme:new[PATH]'`: the default theme written into a folder of
  # a theme's shape (theming spec, decision 15).
  #
  # The default theme's templates stay where Rails and ViewComponent put
  # them (app/views, beside each component); this copy is how they are "the
  # example to copy". WHAT IS COPIED IS THE CONTRACT: every template of
  # `Contract::TEMPLATES` and every component template of
  # `Contract::COMPONENTS`, so a line added to either is copied from that
  # day on, and nothing the contract does not name can be. A site under the
  # written folder is drawn byte for byte as before
  # (`test/values/theme/scaffold_test.rb`); its author then deletes what
  # they do not want to own, because a file the folder does not hold comes
  # from the default theme and follows it through upgrades.
  module Scaffold
    class Refused < StandardError; end

    # The folders a theme may fill and that hold nothing yet. Each gets a
    # `.keep`, a dot file, which a theme folder does not count.
    EMPTY = %w[assets/images assets/fonts javascript/controllers views/theme].freeze

    module_function

    def write(to, root: Rails.root)
      target = Pathname(File.expand_path(to.to_s))
      if target.exist? && !(target.directory? && target.children.empty?)
        raise Refused, "#{target} exists and is not empty: theme:new writes into a new or an empty folder."
      end

      written = Contract::TEMPLATES.keys.map { |path| copy(Pathname(root).join("app/views", path), target, "views/#{path}") }
      written += Contract::COMPONENTS.keys.map { |path| copy(Pathname(root).join("app/components/#{path}.html.erb"), target, "components/#{path}.html.erb") }
      written << put(target, "assets/stylesheets/theme.css", stylesheet)
      EMPTY.each { |folder| put(target, "#{folder}/.keep", "") }
      written << put(target, "README.md", readme)
      written
    end

    def copy(source, target, relative) = put(target, relative, source.read)

    def put(target, relative, content)
      file = target.join(relative)
      file.dirname.mkpath
      file.write(content)
      relative
    end

    # A comment and nothing else, so the site looks as before; it names
    # every token, because the list is what a theme's author came for.
    def stylesheet
      tokens = Contract::TOKENS.each_slice(4).map { |names| "     #{names.join("  ")}" }.join("\n")
      <<~CSS
        /* This theme's one stylesheet. The build imports it AFTER the default
           theme's styles, so whatever is declared here wins and nothing has to
           be copied. Plain CSS, or Tailwind utilities in the templates: both
           are built by the same step (assets:precompile with THEME_PATH set).

           Change a token by declaring it again. A colour has a value for the
           light scheme and one for the dark:

             :root, [data-theme="light"] { --th-accent: ...; }
             [data-theme="dark"]         { --th-accent: ...; }

           The tokens of the contract:

        #{tokens}

           --th- is the CMS's prefix: a custom property of your own takes
           another. Images and fonts in assets/images and assets/fonts are
           named here by file name: url("mark.svg"). */
      CSS
    end

    def readme
      <<~TEXT
        # A ContentSpiel theme

        Written by `bin/rails 'theme:new[PATH]'`: a copy of the default theme.
        Set `THEME_PATH` to this folder and the site is drawn by it; it looks
        as before until a file here is changed.

        - `views/` holds the page templates and the frame; `views/theme/` is for
          partials of your own (`render "theme/name"`).
        - `components/` holds the templates of blocks and posts.
        - `assets/stylesheets/theme.css` is the one stylesheet; `assets/images`
          and `assets/fonts` are named in it by file name.
        - `javascript/controllers/` holds Stimulus controllers:
          `copy_controller.js` is `data-controller="theme--copy"`.

        Delete every file you do not want to own: what this folder does not
        hold comes from the default theme, and follows it through upgrades.
        A file that is not part of the contract stops the site from starting;
        `bin/rails theme:check` says which, and why. No Ruby here.
      TEXT
    end
  end
end
```

`lib/tasks/theme.rake`:

```ruby
# What a theme's author runs (theming spec, "What a person gets"). The work
# is Theme::Scaffold's and Theme::Check's; these say it to a person.
#
# The path is a rake argument, so the shell needs the quotes:
#   bin/rails 'theme:new[../my-site/theme]'
#   bin/rails 'theme:check[../my-site/theme]'    or, with THEME_PATH set:  bin/rails theme:check
namespace :theme do
  desc "Write a copy of the default theme into a new folder: bin/rails 'theme:new[PATH]'"
  task :new, [ :path ] => :environment do |_task, arguments|
    path = arguments[:path].to_s.strip
    abort "Say where: bin/rails 'theme:new[PATH]'" if path.empty?

    begin
      written = Theme::Scaffold.write(path)
    rescue Theme::Scaffold::Refused => error
      abort error.message
    end

    target = File.expand_path(path)
    puts "Wrote #{written.size} files to #{target}."
    puts "Start the site with THEME_PATH=#{target} and it is drawn by that folder. It looks as before until a file there changes."
  end

  # With THEME_PATH set to a folder that holds a file the contract does not
  # name, this task is never reached: the application does not start, with
  # the same sentences. Give the path as the argument (and leave THEME_PATH
  # unset) to check a folder the application could not start under.
  desc "Say what is wrong with a theme folder: THEME_PATH, or bin/rails 'theme:check[PATH]'"
  task :check, [ :path ] => :environment do |_task, arguments|
    path = arguments[:path].to_s.strip

    begin
      folder = path.empty? ? ThemeFolder.current : ThemeFolder.new(path)
    rescue ThemeFolder::Invalid => error
      abort error.message
    end
    abort "No theme folder to check: set THEME_PATH or run bin/rails 'theme:check[PATH]'." unless folder.configured?

    problems = Theme::Check.problems(folder, deep: true)
    if problems.empty?
      puts "#{folder.path}: #{folder.templates.size} templates, no problems."
    else
      problems.each { |problem| warn problem }
      abort "#{folder.path}: #{problems.size} #{problems.size == 1 ? "problem" : "problems"}."
    end
  end
end
```
