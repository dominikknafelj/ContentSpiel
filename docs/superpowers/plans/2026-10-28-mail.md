# Mail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A site sends mail over SMTP with settings from the setup wizard and Settings (the host's environment overriding field by field), knows whether mail works, shows the password reset and invites only when it does, and can invite people by mail.

**Architecture:** One value, `MailSettings` (`app/values/mail_settings.rb`), is the only reader of the seven `MAIL_*` variables and the mail columns of `site_settings`; it answers the effective settings, where each came from, a keyed fingerprint, the state and `ready?`. Every mail goes through `ApplicationMailer`, which takes its sender and SMTP options from `MailSettings`, and through one delivery job that retries a connection failure and records success or failure on `SiteSetting` with `update_columns`. An invited person is a `users` row with `invited_at` set; `User.can_sign_in` is the one scope every sign-in path and every count of people who can sign in reads.

**Tech Stack:** Rails 8.1, Action Mailer over `net-smtp` 0.5.1 (already in the lockfile through `mail`), Solid Queue, Active Record encryption, ViewComponent, Stimulus, Minitest with Cuprite.

**Spec:** `docs/superpowers/specs/2026-10-28-mail-design.md`. The screens and words are Claude Design's: `/Users/dknafelj/src/ContentSpiel/.superpowers/design-answers/2026-10-28-mail.md` (M1–M7). ## Global Constraints

- Variables, exactly: `MAIL_SMTP_SERVER`, `MAIL_SMTP_PORT`, `MAIL_SMTP_SECURITY`, `MAIL_SMTP_USERNAME`, `MAIL_SMTP_PASSWORD`, `MAIL_SENDER_NAME`, `MAIL_SENDER_ADDRESS`. A variable that is set but blank counts as not set.
- Columns on `site_settings`: `mail_server` (string), `mail_port` (integer), `mail_security` (string, `starttls` or `tls`), `mail_sender_name` (string), `mail_sender_address` (string), `mail_username` and `mail_password` (text, `encrypts`, as `ai_api_key`), `mail_login_saved_at`, `mail_verified_at`, `mail_last_sent_at`, `mail_failed_at` (datetime), `mail_verified_fingerprint` (string), `mail_failure` (jsonb: `{ "key", "line" }`).
- Security: `starttls` (REQUIRED, never "if offered", port 587 by default) or `tls` (port 465). `none` only from `MAIL_SMTP_SECURITY=none` and only without a login; the screens never offer it.
- States and words (spec "The states"), and `ready?` true for Working and Last send failed only.
- A delivery setting is server, port, security, username, password, sender address. The sender NAME is not one.
- Fingerprint: HMAC-SHA256 over the six delivery settings from whichever source, keyed by `Rails.application.key_generator.generate_key("content_spiel mail fingerprint", 32)`; never shown, logged or audited.
- Mail state columns are written with `update_columns` and `# version: none (mail's state is not content)`; never through a save of `SiteSetting`.
- Retries: a connection failure (refused, timeout, unknown host) is retried three times with backoff (`attempts: 4`), the failure recorded after the last; a refused login, a refused sender and anything else are recorded at once and not retried.
- Failure sentences and keys (spec "A failure's sentence"): `login`, `connect`, `security`, `sender`, `other`. The stored line has the effective username and password replaced by "…".
- Timeouts for an SMTP exchange: open 5 s, read 10 s (the test mail is sent in the request).
- Development and test: where no server is set the stand-in delivery is Rails' own (`:test` in test, `:file` into `tmp/mails` in development) and a send through it counts as a success. Ruling 1 below.
- Invite link valid 7 days; reset link stays 15 minutes; both tokens travel in the URL's fragment.
- Rate limits: reset request as today (10 per 3 min); invites 10 and test mails 5 per person per 3 minutes.
- Mail words: keys under `mail.` in `config/locales/mail.en.yml`, interpolations `%{site}`, `%{inviter}`, `%{minutes}`, `%{date}`. CS Studio words: keys per `docs/reference/i18n.md` (a component's in `config/locales/admin/<folder>.en.yml`); the exact words are the spec's and M1–M7's.
- No credential in a URL, a log line, an audit snapshot or a job's arguments. `mail_username` and `mail_password` join `Audit::Snapshot::NEVER_STORED`; the audit records "Mail login" as "set"/"not set".
- Every new service: `authorize!`, `record_event`, an entry in `EXPECTED_SERVICES` and a factory in `test/support/service_calls.rb`. Every new audit action: a sentence in `Audit::Sentence` and a place in `Editing::Signals::SILENT`.
- Tests: `PGGSSENCMODE=disable` before every test command; this worktree's test database is `content_spiel_test_mail_delivery` (`bin/rails db:test:prepare` once). Build CSS (`bin/rails tailwindcss:build`, `bin/rails theme_css:build`) before a system test, never while tests run. No network in tests: SMTP is the local stub of Task 2.

## Rulings made while planning

1. **The stand-in counts as a server in development and test.** The spec's "Not set up" needs a server, and its development section wants "Send test mail" to turn resets on without a provider. `MailSettings#complete?` asks for a server only where there is no stand-in (production). — Why: both sentences of the spec hold. — Cost if wrong: one condition.
2. **The invited row keeps `password_digest NOT NULL`** and holds the digest of a random 32-character password nobody is told; `invited_at` set means invited. `User.authenticate_by` is never reached for such a row: sign-in asks `User.can_sign_in`. — Why: no migration of a NOT NULL column and `has_secure_password`'s validations stay as they are. — Cost if wrong: a migration making the column nullable.
3. **The invite token is `generates_token_for(:invite, expires_in: 7.days) { invite_sent_at }`.** Accepting clears `invited_at` and keeps `invite_sent_at`, so a used link still finds its row and the page can say "already been used"; a resend moves `invite_sent_at` (the old link dies), a withdrawal deletes the row (not found: "expired"). — Why: the spec's four answers. — Cost if wrong: the used and expired answers merge.
4. **One reference file**, `docs/reference/mail.md`, with an index line in `CLAUDE.md`, not a section in `hosting.md`. — Why: mail is its own domain with its own rules. — Cost if wrong: a move of text.

## Review Focus

1. A host variable set to an empty string (a deploy file with `MAIL_SMTP_PASSWORD=`): expected to count as not set, so the screen's value applies and the field is editable. Test in Task 1.
2. A sender name with a line break or a quote typed into the form: expected to be refused with a sentence (a header-injection attempt or a broken From), never to reach a header. Test in Task 4.
3. A server that accepts the connection and never answers: expected "Could not reach …" within the timeouts, the request returning, not hanging the Settings page. Test in Task 2.
4. An invite to an existing user's address in another case or with spaces (`Ana@Example.com `): expected "Someone with this address already has an account." Test in Task 8.
5. A reset requested for an invited address: expected the same answer as for an unknown one, and no mail. Test in Task 7.
