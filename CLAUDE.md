# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

ContentSpiel is a Rails 8.1 CMS: a page-tree-driven public website plus CS Studio, its own admin. Content editors build pages out of ordered content blocks (rich text, images, post listings), organize them in a tree, and the same tree drives navigation, routing, and the sitemap. Rich text is Tiptap/ProseMirror JSON. Everything is translated via Mobility into the languages switched on in Settings (three by default, en/de/es, out of the 38 in `config/supported_locales.rb`).

## Setup & Commands

```sh
docker compose up -d          # Postgres 17, published on host port 5433 -- start this first
bin/setup --skip-server       # installs gems, prepares dev + test databases
bin/rails db:seed             # creates a development admin account (dev only, see db/seeds.rb)
bin/rails server               # or `bin/dev`, which runs server + `tailwindcss:watch` (see Procfile.dev)
```

- App: http://localhost:3000
- Sign in: http://localhost:3000/cs-studio/sign-in (`<ADMIN_PATH>/sign-in`)
- Admin (CS Studio, behind the same sign-in): http://localhost:3000/cs-studio (`ContentSpiel::ADMIN_PATH`, configurable via `ADMIN_PATH`)

**Tests:** `bin/rails test` (full suite, minitest). Single file: `bin/rails test test/models/page_test.rb`. Single test: `bin/rails test test/models/page_test.rb -n test_method_name` or `bin/rails test test/models/page_test.rb:42` (line number). System tests (Capybara on Cuprite, headless Chrome) are separate: `bin/rails test:system`; run `bin/rails tailwindcss:build` first, and on a laptop cap the workers (`PARALLEL_WORKERS=6 bin/rails test:system` — twelve flakes under load). On macOS prefix every test command with `PGGSSENCMODE=disable`: a parallel run can otherwise crash a forked worker in the pg gem and hang forever. `test/application_system_test_case.rb` prepends `StaleNodeAtOnce` to Cuprite's nodes so a poll whose element died in a Turbo visit fails at once instead of spending half a second per element — that is what made toasts that had come and gone look "missing". Two more rules for a system test: a link into the `#content` frame (a media tile, a trash tab, a list row) is promoted by Turbo to a page visit a few dozen milliseconds after the frame has rendered, and until that visit's `turbo:load` the screen is still arriving — a field typed into can be re-rendered, a Back can be cancelled by the late visit, a link clicked can lose to it — so a test that goes on to read or use the new screen follows the link through `click_frame_link` (`test/application_system_test_case.rb`: a link by its text, or a block for anything else, including a form whose answer redirects inside the frame), the one shared helper; `click_tile` in the media tests and `click_tab` in the trash tests are thin wrappers around it, and no test keeps its own copy of the wait. A `_top` form pressed in that window is held by the write queue and sent afterwards (the promotion hold, see `docs/reference/save-rule-and-write-queue.md`); `test/system/admin/promotion_hold_test.rb` presses without the wait on purpose and must keep doing so. And a test that resizes the window puts the size back in an `ensure`, because the browser is shared with the tests that follow. A test never waits for an element that only a `hover:` style reveals (the CI browser reports it can't hover): click it with `visible: :all`. A notes system test clears `localStorage["cs-notes-open"]` in its teardown (the drawer remembers "open" per browser), never follows a link inside `turbo-frame#notes` with `click_frame_link` (that frame is never promoted to a visit: click and assert), and, before it causes a signal, waits with `await_notes_live` until every cable subscription of the page has been answered; the suite's `test` cable adapter delivers to the browsers as it is, so no test switches adapters. A test that stubs `window.fetch` intercepts only its own request and hands every other to the real `fetch` it saved, because the editors' live parts (presence, notes, live editing) fetch too: a stub that takes everything answers or holds theirs; and a stub that counts or scripts "the writes" of an editor passes a request to `/cs-studio/editing/` through untouched and uncounted, because a claim and a release are writes in the queue. Two people are two Capybara sessions (`using_session`), and every presence system test is built that way (`test/system/admin/presence_test.rb`, `presence_lists_test.rb`): time is not moved with `backdate` (that moves `updated_at`, which `presence_marks` does not have). A test writes a mark's `seen_at` or `state_at` itself with `update_columns` to make a row stale or an away person older, and shortens a script's intervals (its refresh, its slow timer, its interval between readings) through the element's values; where it must show that nothing happens it holds a `sleep` with its `# sleep: <reason>`, which the sleeps guard permits. `await_notes_live` waits for presence's subscriptions as well as notes' (a part that is an element of the page says it on its own `data-live-part`, `app/javascript/live/state.js`). An open page or post editor catches up once when its live-editing subscription is confirmed, and `await_admin_controllers` waits for that too (`await_live_part`: the region `#editing` says `answered`), because a test that touched the page before it would see it reconciled under it. A test of the stale machinery itself (a 409, "Changed elsewhere") makes the colleague's save with `as_unheard(actor)`, which drops the signal: a save the editor heard of is drawn into it, and its next save is no longer stale. A reservation's clock is moved on its row (`update_all(changed_at: 3.minutes.ago)` for a lapsed hold, `requested_at: 6.seconds.ago` for a request that is due), the scripts' waits are shortened through the region's values, and the unit tests hand `now:` to the statements; the two-connection tests (`Editing::ReservationRaceTest`, `Editing::TakeOverRaceTest`) force an order with their `behind` helper, which waits until Postgres says the second statement is blocked behind the first (`docs/reference/live-editing.md`, "In tests"). **The system suite needs a quiet machine:** macOS background services (Software Update, Spotlight, photo analysis) at a load average of 80 to 110 made two whole runs worthless on 2026-10-10, with failures that were the machine's. Check `sysctl -n vm.loadavg` before a run (a load near the core count is not quiet), and a run that takes twice its usual time is not a result.

**System tests fail on any JavaScript error.** `JsErrorCollector` (`test/support/js_error_collector.rb`, prepended to `Ferrum::Page`) records `Runtime.exceptionThrown` and `console.error` (Stimulus reports a throwing action there, with an Error argument's first stack line appended to the message), and the teardown fails the test. A test that expects one wraps the step in `expect_js_error(pattern, times:)`; `JsErrorCollector::IGNORED` holds the matchers that are let through (one Turbo AbortError), each with its reason. A click is `press` (a native click, so a control a person couldn't press is not found); `press_by_script` is the exception and carries a one-line comment naming why. **No fixed sleeps:** `test/lib/system_test_sleeps_test.rb` fails on a `sleep` in a system test without `# sleep: <reason of at least ten characters>` on the same line; a test waits for a condition with `assert_eventually(wait:, message:)`, `await_js(condition, wait:)`, `click_frame_link`, `assert_writes_settled` (the write queue is empty; trivially true on a screen with no autosave form, so useless for a form that is paused or failed), `await_frames` (three animation frames and a task: enough to let an event's synchronous work finish before asserting that something did NOT happen, not enough to wait out a timer such as a debounce or a retry delay), `backdate(record, by:)` (puts `updated_at`, and a page's `settings_changed_at`, in the past without a callback, because the browser's clock does not follow `travel_to`) and, for an AI-provider test that needs a request kept in flight, `GatedProvider` (`test/support/gated_provider.rb`, a latch: `hold!`, `release`, `reset!`). `capture_sql` (`test/test_helper.rb`) returns the statements a block runs, for a test that says a write costs the same at any size.

A local run is quiet: what tests themselves print (the statements a migration test runs, the seed file's "Seeded dev accounts" lines) is swallowed, and shown only for a block that fails. `VERBOSE=1 bin/rails test` prints all of it, and CI always sets `VERBOSE` (`TestOutput` in `test/test_helper.rb`; a test that prints wraps the call in `TestOutput.quietly { ... }`).

Coverage is on request: `COVERAGE=1 bin/rails test` (SimpleCov, line and branch) writes `coverage/index.html`, which `bundle exec simplecov open` shows; the parallel workers' results are merged into the one report. It is off by default, since a run of one file would report a meaningless few percent. CI turns it on for the unit suite and keeps the report as the `coverage` artifact. There is no minimum yet, so a drop doesn't fail a run.

CI runs the browser suite as four jobs side by side (a runner has two cores): `bin/system-test-shard <index> <total>` deals the files so each job takes about the same time, by the seconds per file in `test/system_test_seconds.yml` (measured once on a runner; the table needs no upkeep: a file it does not list counts by its number of tests, and a stale number only makes the jobs a little uneven), `test/lib/system_test_shards_test.rb` keeps every file in exactly one shard, and the one check `system-test` speaks for the four. CI runs for a pull request only, and a new push to it ends the run before it: a merge to `main` is not tested again (the repository is private and a full run is about 48 billed Actions minutes), so `main` is run by hand when that is wanted (`gh workflow run CI --ref main`). A change that touches only `docs/` or a top-level `.md` file skips the browser suite; the unit suite always runs, because its guards read `CLAUDE.md` and `docs/reference`.

**Lint/scan** (all run in CI, see `.github/workflows/ci.yml`):

bin/rubocop            # style (rubocop-rails-omakase, config in .rubocop.yml)
bin/brakeman            # static security analysis
bin/bundler-audit       # known CVEs in gems

A new entry needs its `note` saying why the warning is false; `bin/brakeman` must exit 0 either way.

**DB:** `bin/rails db:prepare` / `db:migrate` / `db:test:prepare`. Schema lives in `db/schema.rb` (Postgres, jsonb-heavy) -- no `db/structure.sql`.

**Deploy:** Kamal (`.kamal/`), containerized via `Dockerfile`. Not typically invoked from Claude Code sessions.

### Rules a change can break silently

Each rule names the test that guards it where there is one; the reference file in the index explains the reasoning.

- Every public URL is a stored `public_paths` row derived by `PublicSite::Paths` from model callbacks: never write one by hand, never resolve a request by walking the tree, and keep `test/models/public_site/paths_test.rb` (parity with a full rebuild) green when a write path feeds a URL.
- Every content, settings, user, group and token write goes through an `ApplicationService` that calls `authorize!(` and `record_event(`, and a controller never writes a record itself (`test/services/service_contract_test.rb`, `test/services/service_behaviour_contract_test.rb`).
- Presence is one of the two writes that are not an `ApplicationService` (an edit reservation is the other, below): `Presence::Channel` writes and deletes its own `presence_marks` rows through `Presence::Mark` (one statement each, no callbacks), because a presence is not content, nobody asks for it by name and a row is ignored by every read after `Presence::STALE_AFTER`; it is never audited, never touches the record it is on (no `touch`, no `updated_at`) and never moves the content version, so a presence write says `# version: none (presence is not content)` on its line, and presence knows nothing of notes (`test/models/presence/mark_test.rb`: "presence writes nothing but its own row: not the record, not the content version, not the audit log"; `test/channels/presence/channel_test.rb`: "presence writes nothing of the record, of the content version or of the audit log"; `test/integration/admin/presence_test.rb`: "presence is read and never written: the record, the content version and the audit log do not move"; `test/lib/version_bump_test.rb`).
- A presence read ignores every row older than `Presence::STALE_AFTER` (150 seconds, not the 60 the spec said: a hidden tab's timers are throttled to about one a minute, and a hidden tab is an away person) whatever `Presence::Sweep` has or has not deleted, never includes the viewer, and counts a person once, however many tabs they have open: here if any tab is, and in the order of their earliest arrival (`test/queries/presence/roster_test.rb`: "a row just past STALE_AFTER is not seen and one just inside it is", "nobody else is nobody", "a person is one Person: here if any tab is here, since their earliest arrival among the tabs that are here", "here comes first, then the earliest arrival of any of the person's tabs, so a reload keeps their place"; `test/components/admin/presence_screen/people_component_test.rb`: "the viewer is never shown, one person in two tabs is one circle, and a stale row is nobody (17)").
- A subscription owns its presence row by a token: `Presence::Mark.leave` deletes only a row that still carries its subscription's token, so the late `unsubscribed` of a connection that died before a reconnect deletes nothing of the new one; a `beat` or a `report` that finds no row writes it again and signals, and a subscription that has left (`@left`, set before anything is deleted) writes nothing and tells nobody, since Action Cable can still work a command on the object while `unsubscribed` runs (`test/channels/presence/channel_test.rb`: "two connections of one tab: a late unsubscribe of the older leaves the newer subscription's row, and the newer one's deletes it", "a beat finds no row, puts it back with the subscription's token and the state it carries, and tells the others", "a beat and a report that come after the leave write no row and tell nobody"; `test/models/presence/mark_test.rb`: "leave deletes the row of that token only: a late leave of an older subscription deletes nothing").
- The presence signal of a list names no record: `{ kind: "presence" }` on `presence:list`, whose stream any signed-in user may open, since a signal that said "post 812" would tell someone with no grant on posts that it exists and that somebody is working on it; a list re-reads all its markers on any signal, at most once every five seconds, through the read scope (`test/channels/presence/channel_test.rb`: "a signal on the list names no record, whatever the kind"; `test/channels/presence/list_channel_test.rb`; `test/system/admin/presence_lists_test.rb`: "any number of signals within the interval cause one fetch, and one more after it").
- A record is found for a presence subscription or a presence request only through `RecordKinds.find` or a kind's `readable` (`Admin::RecordOfKind` for a request, `kind.readable_ids` narrowing the asked ids of a list, `Presence::Roster` told nothing about rights and trusting its caller to have narrowed), and a record outside the scope, a trashed one, an unknown kind and a bad id are one answer (`test/channels/presence/channel_test.rb`: "a record out of scope, a trashed one, an unknown kind, a bad id and a tab of the wrong shape are rejected and write nothing"; `test/integration/admin/presence_test.rb`: "a record outside the viewer's scope, a missing one and an unknown kind are a 404", "here answers only the readable ids, and says nothing of the others"; `test/models/record_kinds_test.rb`: "find answers exactly the records readable holds, whoever asks, trashed ones included"; `test/integration/trash_visibility_test.rb`: "a trashed page, post and image have no presence anywhere: not their people, not their count, not a subscription"). A kind is `scoped` (per-record rights: not found outside them) or not (the library: a 403 without `media.upload`, which says nothing of any one image).
- A channel's hooks (`subscribed`, `arrived`, `stream_name_for`) and its `unsubscribed` are private, and a `Live::RecordChannel` descendant offers a client only the actions it means to (`Presence::Channel`: `report` and `beat`; the notes channels, `Presence::ListChannel` and `Editing::Channel`: none), because Action Cable lets a client call any public method a channel class defines itself, and a public `arrived` in presence writes a row. The stream hook is `stream_name_for`, never Rails' own `stream_for`, which a subclass that forgot it would silently get (`test/channels/live/record_channel_test.rb`: "no channel under app/channels that descends from Live::RecordChannel offers an action it does not mean to", "the test subclasses make the guard able to fail: a public hook would be an action", "a subclass that forgot stream_name_for fails loudly, not with Rails' stream_for"; `test/channels/presence/channel_test.rb`: "only report and beat are actions"; `test/channels/notes/person_channel_test.rb`: "the channel offers a client no action: subscribed is private"; `test/channels/editing/channel_test.rb`: "the channel offers a client no action").
- A slot-hosting component does not name the features in its slots: the editors' header, the media panel, the page tree's rows, the posts table and (for a block's markers, `editor.block.markers`) the block card and a section's tile draw `Admin::Ui::SlotComponent` at a name from `Admin::Slots::NAMES`, a feature registers in `config/initializers/admin_slots.rb` (the one file that names them all, inside `to_prepare` after `reset!`), a list slot's loader runs once for all the rows of the list and a row only reads its entry, `Admin::Slots.load` hands the host's context (`holds:` on a block) to a loader that declares a keyword of that name or `**` and to no other, and every slot component accepts `**` for the context of the host it does not use (`test/lib/notes_boundary_test.rb`: "the editors' header and the media panel do not name notes: they draw their slots", "every place that still names notes directly is a named exception with its trigger, and still names them", "the block card and the tile draw no marker themselves: they draw the slot" (both still name notes for the "Add note" item of their menus, a named exception); `test/components/admin/slots_test.rb`: "load calls each loader once with every record and the viewer, and skips entries without one", "load hands the host's context to a loader that names it or takes any, and to no other", "the real registry holds notes' components, and presence's people in the header at its size and in the panel at its"; the 3-against-30 statement tests in `test/components/admin/pages_screen/tree_component_test.rb` and `test/components/admin/posts_screen/table_component_test.rb`; `test/components/admin/presence_screen/people_component_test.rb`: "it takes what the hosts hand every slot component and ignores it, and an actor that is no user is shown nothing"). A place that is not a slot yet stays a direct call and is a named exception in the boundary test with the trigger that would make it one.
- A person's name reaches a marker, a tooltip or a circle that a script writes as text, never as HTML, and the short name is `PersonName.of` for notes and presence alike, never `User#display_name` (`test/components/admin/presence_screen/row_marker_component_test.rb`: "a name is text, whatever was typed as one"; `test/integration/admin/presence_test.rb`: "a name with markup in it is answered as the text it is"; `test/system/admin/presence_lists_test.rb`: "hovering a marker shows its words in the shared tooltip, in the tree and in the posts list, whole and on top, and a name is text"; `test/values/person_name_test.rb`).
- The presence group and the lists are filled by a plain `fetch`, never a Turbo request, because the write queue holds Turbo's requests while a save is out and who else has the page open is nobody's business in an editor; the record's script (`admin--presence--record`; the list's script owns no row and does not) ends its subscription on `pagehide` (`suspend`) and takes it up on `pageshow` (`resume`), because a page kept for the Back button holds its socket open and the person would stay on the record (`test/system/admin/presence_lists_test.rb`: "a list's readings are plain requests: no Turbo fetch, visit, frame load or stream"; `test/system/admin/presence_test.rb`: "a page that is hidden away by the browser leaves at once, and is back when it is shown again"; `test/system/admin/live_connection_test.rb`: "suspend ends the subscription on the server in the same task and keeps the listener, and resume takes it up again").
- An editing signal is sent only by `Editing::Signals`, through `Live::Signals`, and carries a kind (`content` or `holder`), a block's id or none, a reason and, when the request named its tab, the `origin`, never text. Its source is the audit log's after-commit notification, so no content service names the feature: every action in `Audit::Sentence::ACTIONS` is in `Editing::Signals::MAP` or in `SILENT` with its reason, and a new action must be placed in one of them. `origin` is `Current.editing_tab`, which `Admin::BaseController` reads from `X-Notes-Tab` for every CS Studio request, never `Current.notes_tab` (a content request that set that one would make the tab that deleted a block skip the refresh of its own notes drawer), and `heard` never raises: it runs in the request that made the write (`test/models/editing/signals_test.rb`: "every action the app records is mapped or silent, with a reason, and none is both", "a block's save signals its page: content, saved, the block's id and nothing else", "the tab that made the change is named, and a junk id is left out", "nothing is sent for a write that is rolled back, and a signal that fails does not fail the write"; `test/models/notes/signals_test.rb`: "nothing in the app broadcasts but Live::Signals, and only a ...::Signals module calls it").
- Every write an editor sends carries the tab's id in `X-Notes-Tab`: Turbo's requests get it from the one listener in `app/javascript/editing/requests.js`, and the three hand-built writes (the autosave, the block reorder, the page tree's move) add `[TAB_HEADER]: TAB` themselves. A write without it claims nothing, and its own tab fetches what it has just drawn (`test/lib/editing_tab_header_test.rb`: "each hand-built write of an editor sends the tab header", "Turbo's own requests get the header from one listener").
- A form that holds unsaved changes is never replaced, removed or moved by a live refresh, and neither is anything else of its unit; everything else is replaced by what was fetched. `app/javascript/editing/merge.js` is the one place that says so, and it decides by ids, `data-editing-subject`, `data-editing-version` and the caller's `unsaved(form)`, never by comparing HTML (a fetched form carries a fresh CSRF token, a mounted editor has added elements). A kept unit is the same element afterwards, so the list is reconciled around it, which needs an id on every ancestor of a unit up to the block list; a block is one subject with one form on screen, so a kept unit whose block the answer has elsewhere stays and nothing of that block is drawn in its new place; and every version is written through `Editing.version` (`test/system/admin/editing_merge_test.rb`: "a card that holds unsaved text is the same element with its text after a list merge, and a clean one is replaced", "one kept card while the others are reordered around it is never taken out of the document", "a kept card whose block was moved into a section stays where it is, is not gone, and the block has one form", "a catch-up of a page with a section leaves no id on the page twice, whatever it kept", "a catch-up leaves a card of the same version as it is, with its menu open, and replaces one that changed").

None asks for a lock, but Postgres locks the row a statement touches until the end of the transaction it is in, so every one is called in autocommit, outside a service's transaction: `Admin::EditingClaims` claims before the service runs. - A save is a claim, in this order: the three autosave actions claim for the request's tab, refuse a tab that does not hold the subject (a 409, nothing written, nothing audited), then run the stale check, then the service; a claim that very request took is given back when the save is refused as stale, denied or raises, and kept on a 422. A request with no tab id (a script, the MCP server) neither claims nor is refused, and someone who may not save the record (`Editing::Rights`, the services' own rule in `AccessControl::OwnerRule`: `edit`, and `publish` once the record has a `published_at`) claims nothing. It is a draft in the tab's `sessionStorage` under `cs-note-draft:<user id>:<form key>`, and it does not outlive the person: every such key is removed when they sign out, and a page loaded for someone else removes what is not theirs (`test/system/admin/note_composer_test.rb`: "signing out removes every note draft from the tab, and the next person finds none", "a page loaded for another person removes the drafts that are not theirs and keeps their own").
- A route name a notes query hands up (`Dashboard::NotesForYou`, `Dashboard::OpenThreads`) is resolved only by `Admin::NotePathsHelper#note_route_path`, against `NOTE_ROUTES`; a name that is not on the list raises and calls nothing (`test/helpers/admin/note_paths_helper_test.rb`, which also fails on any other `public_send` of a route in the notes components and controllers).
- A person is named in a note through `Notes.name_of` (`Admin::NotesScreen::PersonNameComponent`): the name, or the part of the email address before the at sign; never `User#display_name`, which the rest of CS Studio uses and which answers the whole address (`test/integration/admin/note_names_test.rb`).
- `notes=open` and `thread=<id>` in an editor's address follow the drawer through `admin--notes--drawer#syncAddress`: replaced, never pushed, by Turbo's own history with the restoration identifier it has, and only while the address is that editor's (`test/system/admin/notes_drawer_test.rb`: "the address follows the drawer…", "Back after opening and closing the drawer leaves the page", "a remembered drawer puts notes=open into the address of the editor it opened on, not of the page before it").

### Pitfalls

Each of these ends a description in `docs/reference/` and is repeated here because the mistake it names is easy to make.

- **Public URLs** (`docs/reference/page-tree-and-routing.md`; the comments in `page.rb`, `public_site/paths.rb` and `tree_ranking.rb` hold the two-pages-one-URL and nil-position footguns):
  Read the extensive comments in `page.rb`, `public_site/paths.rb` and `tree_ranking.rb` before changing any of this -- the two-pages-one-URL and nil-position footguns they guard against are non-obvious and previously shipped as bugs (see commit `da80c58`).
- **Public routing** (same file; `config/routes.rb` carries the history of the 500-vs-404 regression):
  Read the routes.rb comments before touching `format: false` or the locale constraint; there's a documented history of a 500-vs-404 regression here.
- **The write queue** (`docs/reference/save-rule-and-write-queue.md`; every write of an autosave screen is serialised on this assumption):
  The queue assumes Turbo's morphing page refresh stays off.
  Notes, presence and an open editor (`docs/reference/live-editing.md`: plain GETs merged by `editing/merge.js`) are refreshed part by part for the same reason (`docs/reference/notes.md`, "Live delivery"): no `turbo_refreshes_with`, no `broadcast_refresh`, no `<meta name="turbo-refresh-method">`. All three are refused by `test/lib/notes_guards_test.rb` ("nothing in the app turns on Turbo's page refresh or morphing, or broadcasts one"), and any broadcast but `Live::Signals`' by `test/models/notes/signals_test.rb`.
- **Import-map pins** (`docs/reference/rich-text.md`; the option to re-add after re-pinning is `preload: "admin"`, which keeps the editor off public pages):
  Re-pinning Tiptap (`bin/importmap pin @tiptap/core @tiptap/starter-kit @tiptap/extension-link ...`) writes the new pins without that option — re-add `preload: "admin"` afterwards (`test/integration/public_javascript_test.rb` catches a miss).
- **AI requests** (`docs/reference/translations.md`; the three that must agree are the provider's 25 s timeout, `AI::Translate::MAX_FIELDS` / `MAX_CHARACTERS`, and `proxy.response_timeout: 75` in `config/deploy.yml`):
  Keep the timeout, the cap and the proxy setting in step when changing any of them.
- **Active Record encryption keys** (same file; an env var that is set wins over the credentials for that key alone, so the keys must not be split between the two):
  Setting only some of the env vars therefore mixes two key sets, so keep all three in the same place.
  Once keys are set, keep them: losing them makes the stored AI key unreadable, and the fix is to remove it and enter it again.

### i18n / Mobility

Translated attributes (`Page#title/slug/subtitle/meta_title/meta_description`, `Post#title/slug/excerpt`, `ContentBlock#caption`) are plain jsonb columns via the Mobility `:jsonb` backend (`config/initializers/mobility.rb`); rich text (`Post#body`, `ContentBlock#body` — pages have none) is the same jsonb backend, one Tiptap/ProseMirror JSON document per locale, via `HasRichTextBody` (see `docs/reference/rich-text.md`), not ActionText. Available/default locales are set once in `config/application.rb` (`config.i18n.available_locales`), not in the Mobility initializer, because Mobility needs it at load time to define per-locale accessors. Falls back to `:en` everywhere. Because translated columns are jsonb, `where(slug: ...)` on them is a bug (comparing jsonb to a string) — use Mobility's `.i18n` scope, as the slug-uniqueness validations on `Page`/`Post` do.

## Key Conventions

- **No RSpec** — Minitest + fixtures (`test/fixtures/`), not factories.
- **No Devise / no ActiveAdmin** — auth and admin (CS Studio) are both hand-rolled as described above; don't reach for those gems' idioms.
- **No npm/webpack** — JS is import-maps only (`importmap-rails`); CSS is Tailwind via `tailwindcss-rails` (`bin/rails tailwindcss:watch` in dev).
- **Long, load-bearing code comments are the norm in this codebase**, especially in `page.rb`, `content_block.rb`, `post.rb`, and `routes.rb` — they document non-obvious invariants and past incidents (e.g. the Accept-header 500, the two-pages-one-URL collision). Read them before changing the code they annotate, and match that density when adding similarly non-obvious logic; don't strip them out during cleanup.
- **New admin strings are keys, not literals.** A string a person reads in CS Studio lives in `config/locales/admin/` and is read with `t(".key")` (a component: `admin.components.<scope>.key`, via `Admin::AdminComponent`, in the one file per component folder, `config/locales/admin/<folder>.en.yml`, `notes.en.yml` being the one exception, which stays whole because it holds notes' own keys and the strings notes puts on other screens' components, both guarded by `test/lib/source_layout_test.rb`; a script: `messages(element).t(key)` from the server's `data-messages`). The shared components and the admin layout are converted and `test/lib/admin_i18n_test.rb` keeps them free of English (its `CONVERTED` list grows with each screen). The scheme, the plural/interpolation/date rules and what is out of scope: `docs/reference/i18n.md`.
- **Never define `Admin::Media` or `Admin::Trash`** — either module would shadow the top-level `Media`/`Trash` namespaces (models and services) for every bare `Media::`/`Trash::` reference lexically inside `module Admin`, a `NameError` that has already shipped once mid-task. That's why the media library's admin components are `Admin::MediaLibrary::` and the Trash screen's are `Admin::TrashScreen::`. The same goes for **`Admin::Translations`, `Admin::AI` and `Admin::Ai`**, which would shadow `Translations::`/`AI::`: the translation screens' components live under `Admin::TranslationScreen::`. The same goes for **`Admin::Audit`** (it would shadow `Audit::Event`/`Sentence`/`Filter`): the audit log's components live under `Admin::AuditScreen::`. And for **`Admin::Dashboard`** (it would shadow the `Dashboard::` queries): the dashboard's components live under `Admin::DashboardScreen::`. And for **`Admin::Notes`** (it would shadow `Notes::`): the notes components live under `Admin::NotesScreen::`, and the controllers are `Admin::NotesController`, `Admin::NoteThreadsController` and so on, classes and not a namespace. A screen's components go in a namespace named after the *screen*, never after a domain module: besides those, `Admin::EditorScreen::`, `Admin::PostsScreen::`, `Admin::SettingsScreen::`, `Admin::TokensScreen::`, `Admin::GroupsScreen::`, `Admin::UsersScreen::`, `Admin::PagesScreen::` (the page tree), `Admin::MindGraphScreen::` and `Admin::Shell::`, and `Admin::Ui::` for the shared building blocks that belong to no one screen (the dialog, the toast, the fields' wrappers, the save bar) (`Settings::`, `Groups::`, `Users::` and `ApiTokens::` are service namespaces a bare `Admin::Settings` and so on would shadow the same way). The same goes for **`Admin::Presence`** (it would shadow `Presence::`), **`Admin::Live`** (`Live::Signals`, `Live::RecordChannel`), **`Admin::RecordKinds`** and **`Admin::PersonName`**: presence's components live under `Admin::PresenceScreen::`, its controller is `Admin::PresenceController`, a class and not a namespace; and for **`Admin::Editing`** (it would shadow `Editing::`): live editing's components are the editors' own (`Admin::EditorScreen::HoldStripComponent`, `LiveRegionComponent`, `HolderAvatarComponent`, `UpdatedMarkComponent`), its controller is `Admin::EditingController` and its concern `Admin::EditingClaims`, and inside `module Admin` they write `::Editing::`; and the slot registry, which holds component classes and is no domain, is `Admin::Slots` (`app/components/admin/slots.rb`, a loose file named in `test/lib/source_layout_test.rb` beside the base class). One test guards every one of them, `test/lib/admin_namespace_shadow_test.rb`. Its names are derived, not listed: whatever sits at the top of `app/models`, `app/services`, `app/queries`, `app/values` and `app/constraints` — a directory is a namespace, a file a class or module (so `Admin::Page` is refused too) — each both as Zeitwerk inflects it and as a plain camelize would (hence `Ai`), so a new domain is guarded the day its directory appears. It fails when `Admin` defines one of those names and when a bare reference from inside `Admin` doesn't reach the top-level constant; its allow-list (`ALLOWED`) is empty, and an entry needs its reason written beside it. The Tags screen has no components of its own.
- **Where a component goes.** A component is in `app/components/admin/ui/` when more than one screen uses it (or the layout does, or a registry such as `columns/` or `fields/`), otherwise in the folder of the screen that owns it, and its class name follows the folder (`Admin::Ui::DialogComponent`, `Admin::PagesScreen::TreeComponent`). One thing is tested: nothing is loose in `app/components/admin/` but `admin_component.rb` (`test/lib/source_layout_test.rb`). The class name following the folder is Zeitwerk's doing, and a file in the wrong place fails `bin/rails zeitwerk:check`. Which folder a component belongs in is a convention with no test: it is a judgement made at review, so look at who renders it when you add a second user to a one-screen component.
- **Where a script goes.** A topic has one name and up to two folders with it: its Stimulus controllers in `app/javascript/controllers/admin/<topic>/` and its plain modules in `app/javascript/<topic>/`. A controller's identifier follows its path (`admin--notes--live`). A behaviour of a shared control is in `ui`, what only the layout uses in `shell`, and autosave, the save bar and the write queue are one topic, `saving`. `i18n`, `search` and `live` are the three module folders with no topic of that name: `i18n` and `search` are helpers every screen shares, `live` is the cable connection the notes, presence and editing topics share (`live/connection`: the socket, its pooled subscriptions, the tab's id). Nothing is loose in `controllers/admin/`, and a module folder with no topic of its name is refused (`test/lib/source_layout_test.rb`).
- **Where a class goes.** `app/models` holds the Active Record models, each domain's namespace and its entry file (`audit.rb` beside `audit/`), `Current` and the registries; a plain value object goes in `app/values` (`Pagination`, `Theme`), a route constraint in `app/constraints` (`LocaleRouteConstraint`, `Setup::RedirectConstraint`), a read that spans models in `app/queries`, a write in `app/services`. Both guards below look at all five directories.
- **Queries are Active Record, then Arel, then SQL, and a fragment has a name on the model.** What Active Record's own syntax says exactly is said that way (a hash condition, `where(published_at: ..now)`, `where.not`, `.or`, `merge`, `group(:column)`, `where(id: relation.select(:id))`). What it can't say is Arel nodes, never a string — a strict or column-to-column comparison (`arel_table[:published_at].gt(now)`), a function, a jsonb operator, LIKE, a row comparison, `EXISTS`, `COUNT(*) FILTER`, a join with its own `ON`, an ordering by an expression — built through `SqlNodes` (`app/values/sql_nodes.rb`), with Ruby values handed to the nodes, never interpolated. A SQL string stays only where Arel has no node (`upsert`'s `ON CONFLICT`, `LOCK TABLE`, the recursive heredoc in `PublicSite::Paths`) and carries `# sql: <reason>` on its line or the line above, as does a statement sent to the connection (`test/lib/sql_strings_test.rb`). Either way it is a named scope on the model or a method of the query object or index that owns it, with a line saying what it answers, and a controller or component calls it by name: `Tag.named` / `name_containing` / `by_name`, `TitleSearch` (`title_matching(text, locale:)`, `title_matching_any_locale(text)` on `Page` and `Post`), `Publishable.scheduled`, `Page.trash_roots` / `trash_branch_members`, `User.name_or_email_containing`, `Audit::Event.older_in_log_than` / `newer_in_log_than` / `newest_per_subject`, `Translations::StateIndex.work_list`. A search scope escapes its own text (`SqlNodes.like_pattern`), so a caller hands over what was typed and never escapes it again.
- **Dependency order.** Models, queries (`app/queries`) and services know nothing of components, helpers or controllers — with one exception by design: a type definition registers its components (`app/models/content_types/*.rb` and `block_types/*.rb` name the components that render the type: `t.component`, `t.list_component`, `t.detail_component`), because that registration is the plugin seam. Components may know models and queries; controllers orchestrate services and never write a record themselves. A model or query that needs *wording* returns data and a component renders it: `Audit::Sentence` is the actor as facts, the sentence as parts and the subject as a route *name* with its arguments, and `Admin::AuditScreen::SentenceComponent` turns that into a name, markup and a URL; `Dashboard::Activity` returns rows holding such a sentence and builds no component. Route resolution happens in components and controllers, from a fixed set of route names the lower layer may hand up (`Audit::Sentence::Route`), with the request's own URL options. The reason is the direction of change: a screen is rebuilt far more often than a rule, and a model that renders, or a query that picks a component, has to be rewritten with every screen that shows it — and can't be used from MCP, a job or the console, where there is no view. Among the domains the same direction holds: `RichText` and `ContentModel` at the bottom, then `AccessControl` and `Audit`, the content models, the derived indexes (`PublicSite`, `Translations`, `Media`), services, and controllers and components on top; a lower layer never references a higher one. `test/lib/dependency_direction_test.rb` keeps it so: under `app/models`, `app/queries`, `app/services`, `app/values` and `app/constraints` (comments stripped) it fails on a `…Component` constant, `ApplicationController`, `ActionController`, `url_helpers` and `Rails.application.routes`, with an `ALLOWED` list that names each exception and its reason (the type definitions' component registration; `RichText::HtmlRenderer` and `BuiltIns` building HTML with Action View's tag helpers; `Media::Asset`'s Active Storage URLs) and fails on an entry that matches nothing. What a lower layer needs from a higher one comes in as data or a callable: rich-text components are drawn by `RichText.component_renderer`, assigned in `config/initializers/rich_text.rb`; a `Jump::Search` row carries `[route name, args, params]`, which `Admin::JumpHelper` resolves against a fixed list; `PostGraph::Global` and `PostGraph::Local` take `url_for:` with no default, and `PostGraph::Search` answers ids the controller turns into URLs; and the starter content is written by `StarterContents::EnsureHome` and `StarterContents::Add`, since `StarterContent` (a model) holds only the sample data and `added?`.
- **A change that alters what a person sees or does, in CS Studio or on the public site, names the guide pages it affects in its pull request under "Documentation", or says "none".** The guide lives in its own repository (`contentspiel-docs`, today still named `contentspiel-site`) and is updated there before the change is released; no guide text is kept in this repository.
- **Design docs**: `docs/superpowers/specs/` and `docs/superpowers/plans/` hold the original design specs and implementation plans this app was built from — useful background when a change touches the page tree or content blocks.
