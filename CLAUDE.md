# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

ContentSpiel is a Rails 8.1 CMS: a page-tree-driven public website plus CS Studio, its own admin. Content editors build pages out of ordered content blocks (rich text, images, post listings), organize them in a tree, and the same tree drives navigation, routing, and the sitemap. Rich text is Tiptap/ProseMirror JSON. Everything is translated into three locales (en/de/es) via Mobility.

## Setup & Commands

```sh
docker compose up -d          # Postgres 17, published on host port 5433 -- start this first
bin/setup --skip-server       # installs gems, prepares dev + test databases
bin/rails db:seed             # creates a development admin account (dev only, see db/seeds.rb)
bin/rails server               # or `bin/dev`, which runs server + `tailwindcss:watch` (see Procfile.dev)
```

- App: http://localhost:3000
- Sign in: http://localhost:3000/cs-studio/sign-in (`<ADMIN_PATH>/sign-in`)
- Admin (CS Studio, behind the same sign-in): http://localhost:3000/cs-studio (`ContentSpiel::ADMIN_PATH`, configurable via `ADMIN_PATH`)

**Tests:** `bin/rails test` (full suite, minitest). Single file: `bin/rails test test/models/page_test.rb`. Single test: `bin/rails test test/models/page_test.rb -n test_method_name` or `bin/rails test test/models/page_test.rb:42` (line number). System tests (Capybara on Cuprite, headless Chrome) are separate: `bin/rails test:system`; run `bin/rails tailwindcss:build` first, and on a laptop cap the workers (`PARALLEL_WORKERS=6 bin/rails test:system` — twelve flakes under load). On macOS prefix every test command with `PGGSSENCMODE=disable`: a parallel run can otherwise crash a forked worker in the pg gem and hang forever. `test/application_system_test_case.rb` prepends `StaleNodeAtOnce` to Cuprite's nodes so a poll whose element died in a Turbo visit fails at once instead of spending half a second per element — that is what made toasts that had come and gone look "missing". Two more rules for a system test: a link into the `#content` frame (a media tile, a trash tab, a list row) is promoted by Turbo to a page visit a few dozen milliseconds after the frame has rendered, and until that visit's `turbo:load` the screen is still arriving — a field typed into can be re-rendered, a Back can be cancelled by the late visit, a link clicked can lose to it — so a test that goes on to read or use the new screen follows the link through `click_frame_link` (`test/application_system_test_case.rb`: a link by its text, or a block for anything else, including a form whose answer redirects inside the frame), the one shared helper; `click_tile` in the media tests and `click_tab` in the trash tests are thin wrappers around it, and no test keeps its own copy of the wait. A `_top` form pressed in that window is held by the write queue and sent afterwards (the promotion hold, see `docs/reference/save-rule-and-write-queue.md`); `test/system/admin/promotion_hold_test.rb` presses without the wait on purpose and must keep doing so. And a test that resizes the window puts the size back in an `ensure`, because the browser is shared with the tests that follow. A test never waits for an element that only a `hover:` style reveals (the CI browser reports it can't hover): click it with `visible: :all`. A notes system test clears `localStorage["cs-notes-open"]` in its teardown (the drawer remembers "open" per browser), never follows a link inside `turbo-frame#notes` with `click_frame_link` (that frame is never promoted to a visit: click and assert), and, before it causes a signal, waits with `await_notes_live` until every cable subscription of the page has been answered; the suite's `test` cable adapter delivers to the browsers as it is, so no test switches adapters. Two people are two Capybara sessions (`using_session`).

**System tests fail on any JavaScript error.** `JsErrorCollector` (`test/support/js_error_collector.rb`, prepended to `Ferrum::Page`) records `Runtime.exceptionThrown` and `console.error` (Stimulus reports a throwing action there, with an Error argument's first stack line appended to the message), and the teardown fails the test. A test that expects one wraps the step in `expect_js_error(pattern, times:)`; `JsErrorCollector::IGNORED` holds the matchers that are let through (one Turbo AbortError), each with its reason. A click is `press` (a native click, so a control a person couldn't press is not found); `press_by_script` is the exception and carries a one-line comment naming why. **No fixed sleeps:** `test/lib/system_test_sleeps_test.rb` fails on a `sleep` in a system test without `# sleep: <reason of at least ten characters>` on the same line; a test waits for a condition with `assert_eventually(wait:, message:)`, `await_js(condition, wait:)`, `click_frame_link`, `assert_writes_settled` (the write queue is empty; trivially true on a screen with no autosave form, so useless for a form that is paused or failed), `await_frames` (three animation frames and a task: enough to let an event's synchronous work finish before asserting that something did NOT happen, not enough to wait out a timer such as a debounce or a retry delay), `backdate(record, by:)` (puts `updated_at` in the past without a callback, because the browser's clock does not follow `travel_to`) and, for an AI-provider test that needs a request kept in flight, `GatedProvider` (`test/support/gated_provider.rb`, a latch: `hold!`, `release`, `reset!`). `capture_sql` (`test/test_helper.rb`) returns the statements a block runs, for a test that says a write costs the same at any size.

A local run is quiet: what tests themselves print (the statements a migration test runs, the seed file's "Seeded dev accounts" lines) is swallowed, and shown only for a block that fails. `VERBOSE=1 bin/rails test` prints all of it, and CI always sets `VERBOSE` (`TestOutput` in `test/test_helper.rb`; a test that prints wraps the call in `TestOutput.quietly { ... }`).

Coverage is on request: `COVERAGE=1 bin/rails test` (SimpleCov, line and branch) writes `coverage/index.html`, which `bundle exec simplecov open` shows; the parallel workers' results are merged into the one report. It is off by default, since a run of one file would report a meaningless few percent. CI turns it on for the unit suite and keeps the report as the `coverage` artifact. There is no minimum yet, so a drop doesn't fail a run.

CI runs the browser suite as four jobs side by side (a runner has two cores): `bin/system-test-shard <index> <total>` deals the files so each job takes about the same time, by the seconds per file in `test/system_test_seconds.yml` (a file not listed there counts by its number of tests, so a new file needs no entry; measure again with `bin/rails test -v` when the jobs drift apart), `test/lib/system_test_shards_test.rb` keeps every file in exactly one shard, and the one check `system-test` speaks for the four. A change that touches only `docs/` or a top-level `.md` file skips the browser suite; the unit suite always runs, because its guards read `CLAUDE.md` and `docs/reference`.

**Lint/scan** (all run in CI, see `.github/workflows/ci.yml`):

bin/rubocop            # style (rubocop-rails-omakase, config in .rubocop.yml)
bin/brakeman            # static security analysis
bin/bundler-audit       # known CVEs in gems

A new entry needs its `note` saying why the warning is false; `bin/brakeman` must exit 0 either way.

**DB:** `bin/rails db:prepare` / `db:migrate` / `db:test:prepare`. Schema lives in `db/schema.rb` (Postgres, jsonb-heavy) -- no `db/structure.sql`.

**Deploy:** Kamal (`.kamal/`), containerized via `Dockerfile`. Not typically invoked from Claude Code sessions.

### Rules a change can break silently

Each rule names the test that guards it where there is one; the reference file in the index explains the reasoning.

- Every public URL is a stored `public_paths` row derived by `PublicSite::Paths` from model callbacks: never write one by hand, never resolve a request by walking the tree, and keep `test/models/public_site/paths_test.rb` (parity with a full rebuild) green when a write path feeds a URL.
- Every content, settings, user, group and token write goes through an `ApplicationService` that calls `authorize!(` and `record_event(`, and a controller never writes a record itself (`test/services/service_contract_test.rb`, `test/services/service_behaviour_contract_test.rb`).
- A record outside the viewer's scope is not found, not forbidden: look it up through `AccessControl.scope` and answer 404, and use `AccessControl.holds?` for navigation only, never to gate a write.
- A permission or content type removed from its registry is dormant, not gone: a grant naming it matches nothing but is carried through every save until someone presses Remove, and a group is judged on its grants as stored (`LiveGrants#as_stored`).
- The owner flag changes only through `PATCH users/:id/owner`; the ordinary user form does not permit `owner`.
- `Audit.record` is the one write path of the append-only audit log, and no secret reaches a snapshot, a log line or a page: a password digest, a token's `lookup_digest`, an API key (`Audit::Snapshot::NEVER_STORED`, `filter_parameters`).
- A token or API key is never rendered, logged or audited after it is created.
- `Settings::Save` and `Locales::Enable`/`Disable`/`MakeDefault`/`Configure` lock the settings row first (`site.lock!`) and decide from the locked row.
- Trashed pages, posts and images are hidden explicitly at each narrowing point, never by a `default_scope`; a new list, search, picker or public query over them belongs in `test/integration/trash_visibility_test.rb`.
- `public_paths`, `media_usages` and `translation_states` are derived rows, refreshed inside the transaction of the write that changes them and never written by hand; a write path that changes what they are computed from belongs in `test/services/translation_state_parity_test.rb` or `test/models/public_site/paths_test.rb`.
- The public content version moves only through `PublicSite.bump_version!`; a write that goes around the callbacks (`update_all`, `update_columns`, `touch_all`, `insert_all`, `delete_all`) bumps it or says `# version: none (reason)` on the line (`test/lib/version_bump_test.rb`).
- No inline event handlers in a view, a component, a helper or a script's markup: wire behaviour through `data-action` (`test/lib/inline_handlers_test.rb`).
- CS Studio sources use tokens, not colour literals: no hex or `rgb()`/`hsl()` value, no `dark:` variant other than `dark:scheme-dark`, no `danger` in a translation chip or language tab, and no `mx-auto` in the shell except the 403 and 404 messages (`test/lib/admin_design_rules_test.rb`).
- A Stimulus identifier follows its controller's path (`admin--notes--live` is `controllers/admin/notes/live_controller.js`), so moving or renaming a controller file renames the identifier everywhere it is written: `data-controller`, `data-action`, targets, values and params in both spellings (`data-admin--x-target` and `admin__x_value:`), event names (`admin--notes--live:delivery`) and the selectors in `app/assets/tailwind` and in tests. A name left behind does not raise, the control is just dead. `test/lib/source_layout_test.rb` holds that every identifier written in `app`, `test`, `config`, `CLAUDE.md` and `docs/reference` has a controller file ("every admin identifier written in the app has a controller file"), that every `data-controller` value in a component, view or helper names one exactly ("every data-controller value that names an admin controller names a controller file exactly"), that no one-level identifier of the old form is left ("no identifier of the old one-level form is left") and that nothing is loose in `controllers/admin/` ("nothing is loose in app/javascript/controllers/admin"). What none of them catches is a test that asserts a controller's *absence* by a fragment of its name (`[data-controller*='notes-live']` has no `admin--` token to check): after the rename it goes on passing while it checks nothing. That case has no guard; when a controller file is renamed, search the tests for the old name's fragments by hand.
- Every autosave, block reorder, block form and tree move of a CS Studio screen is sent through `app/javascript/saving/queue.js`, never from a hand-built request beside it, and an autosave carries the record's `base_updated_at` so a stale one is refused with a 409 and nothing is written.
- Content screens autosave; configuration screens (Settings, Groups, Users, Your account) save explicitly through `Admin::Ui::SaveBarComponent`.
- Choosing a library image for a hero or an image block goes through `Media::Choosing`, and the database's own foreign key is what keeps an image in use from being deleted.
- Editing an already-published record needs `publish`, not just `edit`, because autosave writes the live record; a save that changes only the publish state needs only `publish` (`Posts::Save` / `Pages::Save#publish_only?`).
- `Pages::Save` and `Posts::Save` take only the keys in their `ATTRIBUTES` lists; moving and trashing belong to `Pages::Move` and `Trash::Move`.
- A new `ApplicationService` needs its entry in `EXPECTED_SERVICES` and a factory in `test/support/service_calls.rb` (`test/services/service_behaviour_contract_test.rb`).
- A password changes only through `Users::UpdatePassword` or `Users::Save`, never `update!` on the model: they end the user's sessions and audit the change.
- Rich text is written through `#assign_body`, never the raw Mobility accessor.
- The foreign keys to library images stay NO ACTION, never `on_delete: :restrict`: Postgres 18 reports SQLSTATE 23001, which Rails doesn't map to `ActiveRecord::InvalidForeignKey`, so every rescue would miss it (`MediaForeignKeysNoAction`).
- The Mind graph's page is a frame with no graph data in it, and `d3-force` and `mind_graph/` stay `preload: false`: only that screen loads them, d3-force from inside its layout worker by asset URL (a re-pin writes the line without the option; `test/integration/public_javascript_test.rb`). Whatever its script writes into the page is taken back in the controller's `reset()`, because Turbo's snapshot keeps it — pinned nodes included: a pin lives in the page that made it and is stored nowhere. In its box the document's order is search, graph, list (the Tab order) while a grid puts the search and the list in one column on the right, so moving a part in the markup moves it for the keyboard.
- `turbo-rails` is pinned in the `Gemfile`; an upgrade means re-reading `app/javascript/saving/` and the header of `app/javascript/controllers/admin/saving/save_bar_controller.js` against the new Turbo source.
- A block in a section still belongs to the page: `owner` is the page, `section_id` and `section_column` only place it, and `page.content_blocks` is every block of the page; display order comes from `BlockOutline` (one per render on the public page, `ThemeHelper#block_outline`), never from `position` alone, which is counted per container (`test/models/block_outline_test.rb`).
- Every write to a page's blocks takes the page's row lock first, then block rows: `ContentBlocks::Save`, `Destroy`, `Reorder` and `Duplicate` call `ContentBlocks::Structure#lock_owner` as the first statement of their transaction, so does `Translations::Confirm` when the record is a block, `Tags::Merge#repoint_blocks` and `Trash::Purge#purge_branch` lock their pages in id order before any block, and `RichText::ActionTextImport` locks a block's page before it writes the body. A section's fold, lift and renumbering write other blocks' rows under that lock, and a delete or a duplicate writes the page's `translation_states` rows before those, so a block-first writer on the same page deadlocks against them. The rows a block's write shares with the rest of its page are the `pages` row, the other blocks AND the page's derived rows (`Translations::StateIndex.refresh` upserts the owner's `translation_states` for any block): a new writer of a `content_blocks` row that writes any of those in the same transaction takes the page first (the `capture_sql` tests in `test/services/content_blocks/`, `test/services/translations/confirm_test.rb`, `test/services/tags/merge_test.rb`, `test/services/trash/purge_test.rb`, `test/tasks/rich_text_migration_test.rb`; statement order only, no two-connection test).
- A block changes container in three places and no other: `ContentBlocks::Reorder` (with `moved_from`), which is the only one a person asks for by name and in the editor is sent only by `admin--editor--blocks#move` inside `app/javascript/saving/queue.js`; `ContentBlocks::Destroy#lift` (a column to the top level, "Remove section, keep blocks"); and `ContentBlocks::Save#fold_removed_columns` (a column to the last column left, when a section's layout is narrowed). `ContentBlocks::Save` reads `section_id` and `section_column` from its caller for a new block only.
- Code asks `capability?(:container)` (`ContentBlock#container?`) and the definition's `columns` (`#column_count`), never `block_type == "section"`.
- The foreign key on `content_blocks.section_id` stays NO ACTION; a section is emptied or lifted by `ContentBlocks::Destroy`, and `Page` destroys the blocks in its sections first (`test/models/content_block_test.rb`: "the database keeps section and column together and refuses to delete a section that holds a block" for the key refusing a bare destroy, "destroying a page destroys the blocks in its sections first" for the page's order; no test tells NO ACTION from RESTRICT for this key, which is the half the media keys' rule above explains).
- Every block's form in a section is rendered with the page and only shown or hidden by `admin--editor--section`: an open form is never fetched and never removed, because the write queue's guarantees are about forms that are in the document. A section's redraw (`section_structure_streams`) never replaces a panel (`test/system/admin/sections_test.rb`: "choosing a narrower layout folds the second lane into the first without losing the open form", "after a fold the open form still saves, its tile says it is open, and the menu shows the new layout", "an add into a column folded away elsewhere is refused with a message, and the lanes are redrawn as they are"), and a refused block move redraws the list only when no autosave form holds unsaved text (same file: "a refused move does not redraw the list while another block's form holds text that was refused", "a refused move does not redraw the list over text typed while its request was out, and that text is then saved", and "a drop into a column another tab has folded away is refused and the list is redrawn" for the settled screen). The one action that does replace the forms of blocks that stay, "Remove section, keep blocks", goes through `admin--saving--queue-hold` and does not run while a form ended unclean ("Remove section, keep blocks does not run while a form holds text that was refused, and says so", "Remove section, keep blocks waits for an edit typed while the block's save was on the wire").
- An audit event's old-to-new values are `field_changes`, never `changes` (`ActiveRecord::Dirty` owns that name), and the log is append-only in Postgres too: the trigger `db/triggers/audit_events_append_only.sql` is reapplied after every schema load.
- A note never writes the record it is on: no `touch`, no `updated_at`, no `PublicSite.bump_version!`, no `X-Page-Base-Updated-At`; a note's form is an ordinary Turbo form in `turbo-frame#notes`, never an `admin--saving--autosave` form and never inside one, so an autosave base is never moved by a note (`test/services/notes/start_test.rb`: "a note writes nothing of the record it is on"; `test/system/admin/notes_flow_test.rb`: "a note sent while an autosave is on the wire goes after it, once, and moves no base").
- A note's text, its quote and its files' names never reach the audit log or a log line: a note event's subject is the content record, `snapshot: nil`, metadata ids only; `body` and `quote` are filtered from the request log for the notes controllers only (a bare `:body` filter would drop a post's body from its audit snapshot), a quote travels in a URL as `note_quote`, and `Admin::NoteFilesController` never hands `send_data` a `filename:`, which Rails logs (`test/services/notes/start_test.rb`: "the audit event is on the content record and holds no text"; `test/integration/admin/note_writes_test.rb`: "a posted note's text, quote and picked names are filtered from the request's logged parameters", "the notes filter leaves a post's and a block's body where it was…"; `test/integration/admin/note_files_test.rb`: "no notes request logs a file's name…").
- A thread is never found by its id alone, nor a message or a file: the container first, through the read scope (`Admin::NoteContainer`), then the thread among that container's; outside the scope is the 404, an image without `media.upload` the 403, and only a thread's own absence is forgiven, as the list with "This note is gone…" (`test/integration/admin/notes_test.rb`: "outside the read scope every part is not found, never forbidden"; `test/integration/admin/note_counts_test.rb`: "only the thread's absence is forgiven…").
- A note's file is read only through `Admin::NoteFilesController`, by its attachment's id among that message's files; no `rails_blob_path`, `url_for(blob)`, signed id or variant of one is ever rendered, and note files stay on the `notes` storage service, which Active Storage's public blob, representation and disk routes refuse (`test/integration/admin/note_files_test.rb`: "no rendered view of the notes holds an Active Storage URL…", "a file is found only as an attachment of that message of that thread of this record, by someone who may read it", "Active Storage's public routes refuse a note's blob, by signed id and by a disk key, and still serve a library image").
- A note's file is typed by its bytes and refused when its name's ending is not one of that type's (`Notes::Files::EXTENSIONS`): what is downloaded opens by its name (`test/models/notes/files_test.rb`: "a file is refused by what it is, whatever it is called and whatever the browser said", "a file whose name does not end as its type's names do is refused: scripts as text, a macro file, a picture named as text").
- Whoever deletes a page, post, image or block for good calls `Notes::Remove` in its transaction: `Trash::Purge` BEFORE it destroys a page's branch (the right is asked again, and a branch scope reads closure rows the destroy deletes) and AFTER it destroys a post or an image, with no row lock of its own (one ahead of the destroy reverses `Posts::Save`'s order and can deadlock); `ContentBlocks::Destroy` after the block, under the page's lock (`test/services/trash/purge_test.rb`: "the notes are removed before the first page of the branch is deleted", "a post and an image are deleted before their notes are touched, and the purge locks neither row itself"; `test/services/content_blocks/destroy_test.rb`: "a block's notes are removed after the block is deleted, under the page's lock" for the order, "deleting a section with its blocks deletes the notes of each" for the removal).
- The content side never references `Notes::`: those two call sites, naming `Notes::Remove` and nothing else, are the only ones (`test/lib/notes_boundary_test.rb`).
- Every notes service that acts on a record takes the container's row lock first (`Notes::Authorization#lock_container`, read through `kept`; `with_locked_thread`), the same first lock a page's block writes take, and answers "This note is gone…" for a trashed or purged record, writing and signalling nothing; a new notes write does the same, or says `# lock: none (reason)` in its class body as `Notes::Remove` does, whose callers hold the row (`test/lib/notes_guards_test.rb`: "every notes service takes the container's lock, or says in its class body why it takes none"; `test/services/notes/thread_state_test.rb`: "each of them locks the page's row before it reads or writes a notes row"; `start_test.rb`, `delete_message_test.rb`, `react_test.rb`, `mark_read_test.rb`, `stale_thread_test.rb`; statement order only).
- A pushed signal carries a kind, ids, a reason and an optional `origin` (the opaque id of the tab whose write caused it, from `X-Notes-Tab`, echoed only in the shape `Notes::Signals::TAB` allows), never text, a title or a name; it is sent only by `Notes::Signals`, after the outermost commit; and every part it refreshes is fetched through the read scope, which `Notes::RecordChannel` also asks at subscribe time, judging the user as they are now (`test/models/notes/signals_test.rb`, which fails for a notes service without a case and for any other broadcast in `app/`; `test/channels/notes/record_channel_test.rb`).
- A new list or count of notes narrows through `Notes.readable_threads`, or counts over ids the read scope already narrowed (`Notes::Counts` hides nothing itself), and belongs in `test/integration/trash_visibility_test.rb`.
- Nothing replaces a note's composer or an open edit form: a live refresh and the answer to one of the tab's own buttons are merged around them (`admin--notes--live`), a thread in a hidden document is not fetched (its GET would read the note for the person), and every link into the notes frame carries `data-turbo-prefetch="false"`, because opening a thread marks it read and a prefetched link must never be taken for the frame's own navigation (the editors and the Media screen switch prefetch off for the whole page; on a record's notes page, `/notes/<type>/<id>`, the attribute on the link is all there is). A composer that is moved keeps the saved text as its baseline (the field's `defaultValue`), its field is read-only while its note is on the way, and a reply to a thread that went comes back in the list's new-note field (`test/lib/notes_guards_test.rb`: "every link into the notes frame switches prefetch off"; `test/system/admin/notes_live_test.rb`: "a message being edited, and one being asked about, stay as they are while the thread around them is refreshed", "a thread open in a hidden document is not fetched…", "an older live answer is not drawn over this tab's own newer one"; `test/system/admin/note_thread_answers_test.rb`: "a link prefetched while Pin's answer is on its way does not cost the open edit its text", "no link in the thread view is prefetched", "while a reply is on its way its field is read-only, so nothing typed after Send can be lost", "a reply sent to a thread deleted a moment before is kept…"; `test/system/admin/note_edit_drafts_test.rb`: "an edit whose thread was refreshed by someone's reply is still an unsaved edit…").
- Unsent note text is not unsaved content: it never raises the unload guard or the leave dialog (`test/system/admin/notes_flow_test.rb`: "leaving an editor with a half-typed note asks nothing, and an unsaved edit of the page still asks"). It is a draft in the tab's `sessionStorage` under `cs-note-draft:<user id>:<form key>`, and it does not outlive the person: every such key is removed when they sign out, and a page loaded for someone else removes what is not theirs (`test/system/admin/note_composer_test.rb`: "signing out removes every note draft from the tab, and the next person finds none", "a page loaded for another person removes the drafts that are not theirs and keeps their own").
- A route name a notes query hands up (`Dashboard::NotesForYou`, `Dashboard::OpenThreads`) is resolved only by `Admin::NotePathsHelper#note_route_path`, against `NOTE_ROUTES`; a name that is not on the list raises and calls nothing (`test/helpers/admin/note_paths_helper_test.rb`, which also fails on any other `public_send` of a route in the notes components and controllers).
- A person is named in a note through `Notes.name_of` (`Admin::NotesScreen::PersonNameComponent`): the name, or the part of the email address before the at sign; never `User#display_name`, which the rest of CS Studio uses and which answers the whole address (`test/integration/admin/note_names_test.rb`).
- `notes=open` and `thread=<id>` in an editor's address follow the drawer through `admin--notes--drawer#syncAddress`: replaced, never pushed, by Turbo's own history with the restoration identifier it has, and only while the address is that editor's (`test/system/admin/notes_drawer_test.rb`: "the address follows the drawer…", "Back after opening and closing the drawer leaves the page", "a remembered drawer puts notes=open into the address of the editor it opened on, not of the page before it").

### Pitfalls

Each of these ends a description in `docs/reference/` and is repeated here because the mistake it names is easy to make.

- **Public URLs** (`docs/reference/page-tree-and-routing.md`; the comments in `page.rb`, `public_site/paths.rb` and `tree_ranking.rb` hold the two-pages-one-URL and nil-position footguns):
  Read the extensive comments in `page.rb`, `public_site/paths.rb` and `tree_ranking.rb` before changing any of this -- the two-pages-one-URL and nil-position footguns they guard against are non-obvious and previously shipped as bugs (see commit `da80c58`).
- **Public routing** (same file; `config/routes.rb` carries the history of the 500-vs-404 regression):
  Read the routes.rb comments before touching `format: false` or the locale constraint; there's a documented history of a 500-vs-404 regression here.
- **The write queue** (`docs/reference/save-rule-and-write-queue.md`; every write of an autosave screen is serialised on this assumption):
  The queue assumes Turbo's morphing page refresh stays off.
  Notes are refreshed part by part for the same reason (`docs/reference/notes.md`, "Live delivery"): no `turbo_refreshes_with`, no `broadcast_refresh`, no `<meta name="turbo-refresh-method">`. All three are refused by `test/lib/notes_guards_test.rb` ("nothing in the app turns on Turbo's page refresh or morphing, or broadcasts one"), and any broadcast but `Notes::Signals`' by `test/models/notes/signals_test.rb`.
- **Import-map pins** (`docs/reference/rich-text.md`; the option to re-add after re-pinning is `preload: "admin"`, which keeps the editor off public pages):
  Re-pinning Tiptap (`bin/importmap pin @tiptap/core @tiptap/starter-kit @tiptap/extension-link ...`) writes the new pins without that option — re-add `preload: "admin"` afterwards (`test/integration/public_javascript_test.rb` catches a miss).
- **AI requests** (`docs/reference/translations.md`; the three that must agree are the provider's 25 s timeout, `AI::Translate::MAX_FIELDS` / `MAX_CHARACTERS`, and `proxy.response_timeout: 75` in `config/deploy.yml`):
  Keep the timeout, the cap and the proxy setting in step when changing any of them.
- **Active Record encryption keys** (same file; an env var that is set wins over the credentials for that key alone, so the keys must not be split between the two):
  Setting only some of the env vars therefore mixes two key sets, so keep all three in the same place.
  Once keys are set, keep them: losing them makes the stored AI key unreadable, and the fix is to remove it and enter it again.

### i18n / Mobility

Translated attributes (`Page#title/slug/subtitle/meta_title/meta_description`, `Post#title/slug/excerpt`, `ContentBlock#caption`) are plain jsonb columns via the Mobility `:jsonb` backend (`config/initializers/mobility.rb`); rich text (`Post#body`, `ContentBlock#body` — pages have none) is the same jsonb backend, one Tiptap/ProseMirror JSON document per locale, via `HasRichTextBody` (see `docs/reference/rich-text.md`), not ActionText. Available/default locales are set once in `config/application.rb` (`config.i18n.available_locales`), not in the Mobility initializer, because Mobility needs it at load time to define per-locale accessors. Falls back to `:en` everywhere. Because translated columns are jsonb, `where(slug: ...)` on them is a bug (comparing jsonb to a string) — use Mobility's `.i18n` scope, as the slug-uniqueness validations on `Page`/`Post` do.

## Key Conventions

- **No RSpec** — Minitest + fixtures (`test/fixtures/`), not factories.
- **No Devise / no ActiveAdmin** — auth and admin (CS Studio) are both hand-rolled as described above; don't reach for those gems' idioms.
- **No npm/webpack** — JS is import-maps only (`importmap-rails`); CSS is Tailwind via `tailwindcss-rails` (`bin/rails tailwindcss:watch` in dev).
- **Long, load-bearing code comments are the norm in this codebase**, especially in `page.rb`, `content_block.rb`, `post.rb`, and `routes.rb` — they document non-obvious invariants and past incidents (e.g. the Accept-header 500, the two-pages-one-URL collision). Read them before changing the code they annotate, and match that density when adding similarly non-obvious logic; don't strip them out during cleanup.
- **New admin strings are keys, not literals.** A string a person reads in CS Studio lives in `config/locales/admin/` and is read with `t(".key")` (a component: `admin.components.<scope>.key`, via `Admin::AdminComponent`, in the one file per component folder, `config/locales/admin/<folder>.en.yml`, `notes.en.yml` being the one exception, which stays whole because it holds notes' own keys and the strings notes puts on other screens' components, both guarded by `test/lib/source_layout_test.rb`; a script: `messages(element).t(key)` from the server's `data-messages`). The shared components and the admin layout are converted and `test/lib/admin_i18n_test.rb` keeps them free of English (its `CONVERTED` list grows with each screen). The scheme, the plural/interpolation/date rules and what is out of scope: `docs/reference/i18n.md`.
- **Never define `Admin::Media` or `Admin::Trash`** — either module would shadow the top-level `Media`/`Trash` namespaces (models and services) for every bare `Media::`/`Trash::` reference lexically inside `module Admin`, a `NameError` that has already shipped once mid-task. That's why the media library's admin components are `Admin::MediaLibrary::` and the Trash screen's are `Admin::TrashScreen::`. The same goes for **`Admin::Translations`, `Admin::AI` and `Admin::Ai`**, which would shadow `Translations::`/`AI::`: the translation screens' components live under `Admin::TranslationScreen::`. The same goes for **`Admin::Audit`** (it would shadow `Audit::Event`/`Sentence`/`Filter`): the audit log's components live under `Admin::AuditScreen::`. And for **`Admin::Dashboard`** (it would shadow the `Dashboard::` queries): the dashboard's components live under `Admin::DashboardScreen::`. And for **`Admin::Notes`** (it would shadow `Notes::`): the notes components live under `Admin::NotesScreen::`, and the controllers are `Admin::NotesController`, `Admin::NoteThreadsController` and so on, classes and not a namespace. A screen's components go in a namespace named after the *screen*, never after a domain module: besides those, `Admin::EditorScreen::`, `Admin::PostsScreen::`, `Admin::SettingsScreen::`, `Admin::TokensScreen::`, `Admin::GroupsScreen::`, `Admin::UsersScreen::`, `Admin::PagesScreen::` (the page tree), `Admin::MindGraphScreen::` and `Admin::Shell::`, and `Admin::Ui::` for the shared building blocks that belong to no one screen (the dialog, the toast, the fields' wrappers, the save bar) (`Settings::`, `Groups::`, `Users::` and `ApiTokens::` are service namespaces a bare `Admin::Settings` and so on would shadow the same way). One test guards every one of them, `test/lib/admin_namespace_shadow_test.rb`. Its names are derived, not listed: whatever sits at the top of `app/models`, `app/services`, `app/queries`, `app/values` and `app/constraints` — a directory is a namespace, a file a class or module (so `Admin::Page` is refused too) — each both as Zeitwerk inflects it and as a plain camelize would (hence `Ai`), so a new domain is guarded the day its directory appears. It fails when `Admin` defines one of those names and when a bare reference from inside `Admin` doesn't reach the top-level constant; its allow-list (`ALLOWED`) is empty, and an entry needs its reason written beside it. The Tags screen has no components of its own.
- **Where a component goes.** A component is in `app/components/admin/ui/` when more than one screen uses it (or the layout does, or a registry such as `columns/` or `fields/`), otherwise in the folder of the screen that owns it, and its class name follows the folder (`Admin::Ui::DialogComponent`, `Admin::PagesScreen::TreeComponent`). One thing is tested: nothing is loose in `app/components/admin/` but `admin_component.rb` (`test/lib/source_layout_test.rb`). The class name following the folder is Zeitwerk's doing, and a file in the wrong place fails `bin/rails zeitwerk:check`. Which folder a component belongs in is a convention with no test: it is a judgement made at review, so look at who renders it when you add a second user to a one-screen component.
- **Where a script goes.** A topic has one name and up to two folders with it: its Stimulus controllers in `app/javascript/controllers/admin/<topic>/` and its plain modules in `app/javascript/<topic>/`. A controller's identifier follows its path (`admin--notes--live`). A behaviour of a shared control is in `ui`, what only the layout uses in `shell`, and autosave, the save bar and the write queue are one topic, `saving`. `i18n` and `search` are the two module folders with no topic of that name: helpers every screen shares. Nothing is loose in `controllers/admin/`, and a module folder with no topic of its name is refused (`test/lib/source_layout_test.rb`).
- **Where a class goes.** `app/models` holds the Active Record models, each domain's namespace and its entry file (`audit.rb` beside `audit/`), `Current` and the registries; a plain value object goes in `app/values` (`Pagination`, `Theme`), a route constraint in `app/constraints` (`LocaleRouteConstraint`, `Setup::RedirectConstraint`), a read that spans models in `app/queries`, a write in `app/services`. Both guards below look at all five directories.
- **Queries are Active Record, then Arel, then SQL, and a fragment has a name on the model.** What Active Record's own syntax says exactly is said that way (a hash condition, `where(published_at: ..now)`, `where.not`, `.or`, `merge`, `group(:column)`, `where(id: relation.select(:id))`). What it can't say is Arel nodes, never a string — a strict or column-to-column comparison (`arel_table[:published_at].gt(now)`), a function, a jsonb operator, LIKE, a row comparison, `EXISTS`, `COUNT(*) FILTER`, a join with its own `ON`, an ordering by an expression — built through `SqlNodes` (`app/values/sql_nodes.rb`), with Ruby values handed to the nodes, never interpolated. A SQL string stays only where Arel has no node (`upsert`'s `ON CONFLICT`, `LOCK TABLE`, the recursive heredoc in `PublicSite::Paths`) and carries `# sql: <reason>` on its line or the line above, as does a statement sent to the connection (`test/lib/sql_strings_test.rb`). Either way it is a named scope on the model or a method of the query object or index that owns it, with a line saying what it answers, and a controller or component calls it by name: `Tag.named` / `name_containing` / `by_name`, `TitleSearch` (`title_matching(text, locale:)`, `title_matching_any_locale(text)` on `Page` and `Post`), `Publishable.scheduled`, `Page.trash_roots` / `trash_branch_members`, `User.name_or_email_containing`, `Audit::Event.older_in_log_than` / `newer_in_log_than` / `newest_per_subject`, `Translations::StateIndex.work_list`. A search scope escapes its own text (`SqlNodes.like_pattern`), so a caller hands over what was typed and never escapes it again.
- **Dependency order.** Models, queries (`app/queries`) and services know nothing of components, helpers or controllers — with one exception by design: a type definition registers its components (`app/models/content_types/*.rb` and `block_types/*.rb` name the components that render the type: `t.component`, `t.list_component`, `t.detail_component`), because that registration is the plugin seam. Components may know models and queries; controllers orchestrate services and never write a record themselves. A model or query that needs *wording* returns data and a component renders it: `Audit::Sentence` is the actor as facts, the sentence as parts and the subject as a route *name* with its arguments, and `Admin::AuditScreen::SentenceComponent` turns that into a name, markup and a URL; `Dashboard::Activity` returns rows holding such a sentence and builds no component. Route resolution happens in components and controllers, from a fixed set of route names the lower layer may hand up (`Audit::Sentence::Route`), with the request's own URL options. The reason is the direction of change: a screen is rebuilt far more often than a rule, and a model that renders, or a query that picks a component, has to be rewritten with every screen that shows it — and can't be used from MCP, a job or the console, where there is no view. Among the domains the same direction holds: `RichText` and `ContentModel` at the bottom, then `AccessControl` and `Audit`, the content models, the derived indexes (`PublicSite`, `Translations`, `Media`), services, and controllers and components on top; a lower layer never references a higher one. `test/lib/dependency_direction_test.rb` keeps it so: under `app/models`, `app/queries`, `app/services`, `app/values` and `app/constraints` (comments stripped) it fails on a `…Component` constant, `ApplicationController`, `ActionController`, `url_helpers` and `Rails.application.routes`, with an `ALLOWED` list that names each exception and its reason (the type definitions' component registration; `RichText::HtmlRenderer` and `BuiltIns` building HTML with Action View's tag helpers; `Media::Asset`'s Active Storage URLs) and fails on an entry that matches nothing. What a lower layer needs from a higher one comes in as data or a callable: rich-text components are drawn by `RichText.component_renderer`, assigned in `config/initializers/rich_text.rb`; a `Jump::Search` row carries `[route name, args, params]`, which `Admin::JumpHelper` resolves against a fixed list; `PostGraph::Global` and `PostGraph::Local` take `url_for:` with no default, and `PostGraph::Search` answers ids the controller turns into URLs; and the starter content is written by `StarterContents::EnsureHome` and `StarterContents::Add`, since `StarterContent` (a model) holds only the sample data and `added?`.
- **Design docs**: `docs/superpowers/specs/` and `docs/superpowers/plans/` hold the original design specs and implementation plans this app was built from — useful background when a change touches the page tree or content blocks.
